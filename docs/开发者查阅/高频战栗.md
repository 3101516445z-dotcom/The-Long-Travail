# 高频战栗实现与复用

## 调用关系

`HighFrequencyTremorItem` 继承 `PickaxeItem`；`HighFrequencyTremorActions` 提供潜行主手条件与 BreakSpeed 倍率。右键入口沿用 `GoldenAgeInteractionMixin` 的 Forge 事件派发后处理位置，先检查最终取消状态与 useBlock/useItem DENY，再分派 FTB 或单块能力。

`PlayerBlockBreaker` 保留 Forge BreakEvent、玩家限制、方块移除回调、采收判定、playerDestroy、经验和 BoundlessAcquisition 通知。见证可在方块自身拒绝移除后回退至替换为原流体状态，但不绕过 Forge 事件取消。实际状态未改变不记为成功。移除前在破坏事件和采收资格回调之后核对玩家世界、主手物品实例、幽谷状态及目标方块实体身份；见证强制移除前再次核对，避免误删同状态替换容器。方块已成功移除后使用捕获的原工具和原世界继续结算；玩家跨维度时不再向新维度发送小王子获取通知。ThreadLocal 作用域在 finally 中清理，嵌套特殊破坏不再次执行。

`TremorBlockDropsMixin` 保留当前方块战利品调用链，仅在恶意采收作用域内将 LootParams 幸运值设为玩家幸运值的 2 倍。工具本身及工具副本的附魔均不改写。

`TremorFortuneMixin` 在 `ApplyBonusCount.run` 调用 `Formula.calculateNewCount` 前将时运参数乘以 2；此处已经包含 Curios 对苦旅冥府见证等饰品的加成。因此时运 III + 冥府见证 6 按 18 计算。只作用于时运公式；时运和幸运共用 matchesBoostedHarvest 检查当前世界、方块位置、原状态、玩家与采收作用域。检查在各自计算时重新执行，不缓存匹配结果。不会再经过物品附魔 NBT 的 255 读取上限，恶意计算使用 long 中间值，并将结果固定限制在 0～1024，不开放配置，以约束原版时运公式的输入和循环次数；普通挖掘及见证不乘倍。此为通用战利品公式入口，不新增对其他模组内部类的专门联动。

容器沿用自身正常移除与掉落回调，不复制掉落、库存或外部存储。自行实现且不经过 `ApplyBonusCount` 的第三方时运算法不保证获得倍率；已在公式调用前合并的加成包含在倍率内。幸运仅影响使用幸运参数的战利品表。

## 可复用组件

- `NbtInheritingShapedRecipe` 使用原版有序配方序列化器，并通过 `nbt_source` Ingredient 指定标签来源。结果使用 `getTag().copy()`，默认保持原版 smithing_transform 语义；可选 `repair` 默认为 false，高频战栗配方设为 true，在复制后将结果 Damage 清零，其他 NBT 不变。此选项同时经网络序列化同步；不迁移完整 ItemStack 序列化中的 ForgeCaps。配方应保证只有一个来源材料。
- `ItemDurabilityProtection` 统一永生芽标记和高频战栗固有保护；沿用 ItemStack.hurt 与 Item.setDamage 两处入口。只阻止损伤增加，不改既有损伤或降低损伤的写入。
- `PlayerBlockBreaker` 是内部入口，需要传入已确定的恶意/见证模式，当前限于高频战栗。不要将其当作绕过授权的公共 API。

## FTB Ultimine 2001.1.8

可选 Mixin 与反射门面避免无 FTB 时链接外部类。原始 `FTBUltimine.blockRightClick` 对本能力先返回 pass，等待整个 Forge 交互事件派发完成；门面再调用原方法，让 FTB 计算选区。`PlatformMethodsImpl.blockRightClick` 在原版作物收获等分支前将选区交给统一破坏入口，返回实际成功数量。FTB 原方法继续处理其右键冷却记录和经验费用。

`blockBroken` 在特殊破坏作用域内返回 pass，避免每个方块再次启动普通连锁。选择集合直接构建包含不可变坐标的 LinkedHashSet，一次完成快照、保序与去重；完整验证选区后才执行破坏；每块开始前核对起始玩家世界、主手物品实例与幽谷状态，改变时结束剩余选区。版本升级须复核方法签名、选区规则和取消语义。

真实客户端的按键、预览、潜行切换形状行为需另行验收；隔离服务端不能代替整包客户端验证。

## 异常与配置边界

单次交互在 `HighFrequencyTremorActions.use` 捕获 RuntimeException；FTB 在逐块循环中捕获并停止，返回此前已确认成功的数量。日志保留原目标方块 ID、维度、位置和堆栈；不重试、不补发、不回滚。内部 `breakBlock` 仍向调用方传播异常并在 finally 清理作用域。反射边界重新抛出被包装的 Error，不将其当作普通失败吞掉。若异常发生在方块移除之后，该方块可能已消失且结算不完整，不能据此推断世界已恢复。

黑名单的条目校验要求完整规范 ID；整项非法通过既有 ConfigValidation / ManagedConfig / ConfigRecovery 实现重载保留旧值、启动备份恢复默认。合法未知 ID 不删除，服务端启动和重载后通过 ConfigProblems 去重提示；空列表与重复项保持合法。语法无法解析时沿用整文件恢复规则。

`TremorFeedback` 使用服务端玩家的 tickCount，按玩家与提示类型分别进行40刻限频，通过 displayClientMessage(..., true) 显示快捷栏提示；WeakHashMap 不强引用离线玩家。直接交互只对起始目标检查并提示黑名单，不改变原有FTB选区处理；内部破坏与连锁黑名单跳过仍静默。单块异常、FTB逐块异常和反射失败共用异常提示，Error仍传播。五种语言共用两条语义键。

## 文本与配置同步

HighFrequencyTremorItem.appendDetails 提供独立详情与分段；ThemeTooltips 提供悬浮简述，风味句复用 flavor.high_frequency_tremor。五种语言在 src/main/lang 维护。CatalogTextStyle 为本物品保留语义色，条件行加粗；CatalogEntries 复用未佩戴苦旅提醒。

TooltipConfigSync 的 deepValley.tremorBlacklist 同步服务器有效名单。展示使用方块名称，未注册项显示原 ID，空列表显示“无”。默认仅禁止 minecraft:barrier，不覆盖已有配置。
