# 伤害结算与追加效果

## 伤害入口与事件阶段

服务端通过 `target.hurt(source, amount)` 发起伤害。`LivingEntity.hurt` 和 `Player.hurt` 由 [DamageScope](../../src/main/java/com/thelongtravail/combat/DamageScope.java) 建立独立的 [CombatContext](../../src/main/java/com/thelongtravail/combat/CombatContext.java)。

通常按以下次序结算：输入与免疫检查、来源转换、Attack/Hurt 事件、内部倍率与必杀、原版护甲和魔法防御、输出增幅、百分比减伤、见切、霸主、吸收生命、最终 Damage 事件和普通生命扣除。取消或免疫会结束对应分支。

事件监听器按所需阶段修改伤害。直接调用 `setHealth` 不进入上述事件和吸收结算。

## 来源与命中确认

| 字段 | 含义 |
| --- | --- |
| `DamageIdentity.original` | 原始来源实例，用于识别追加、反伤和重放。 |
| 有效来源 | 当前参与防御与标签判断的来源，可能经过类型转换。 |
| `damageRecord.total` | 实际生命与吸收下降量之和，支持专用确认值。 |
| `damageRecord.healthLoss` | 普通生命的非负下降量。 |
| `damageRecord.committed` | 普通生命下降是否已提交。 |

每个上下文只做一次首次有效损失确认；吸收生命下降也可确认命中。`hurt` 的返回值与实际损失记录应分别处理。替换来源实例可能改变内部身份识别，来源转换时保留直接实体与责任实体。

仅统计伤害、不扣除原版生命的实体，可在损失确认位置调用 `CombatContext.recordDummyDamage`；调用须与当前上下文的目标和来源匹配。

## 追加、反伤与重放

来源私有标记控制 TLT 内部的增伤和追加分派。使用相同的 `DamageType` 不会取得相同的私有身份；外部监听器仍按正常事件流程执行。

第三方反伤类型加入 `the_long_travail:retaliation` 标签，使本模组识别反伤链。跨游戏刻的反伤同样需要保留该标签。

已结算金额的重放与新发起伤害分别处理，避免重复应用防御和增伤。`CombatContext.close()` 恢复父上下文后执行正常收尾；异常退出只清理作用域。延迟伤害保留目标身份，并在执行前复核存活、维度与状态。

## 诊断入口

JVM 参数 `-Dthelongtravail.damageTrace=true` 启用 `TLT_DAMAGE` 日志，记录根调用、父子关系、目标、来源、金额、策略、首次确认及退出状态。

- `-Dthelongtravail.damageTrace.limit=256`：记录条数，范围 1–10000。
- `-Dthelongtravail.damageTrace.target=<实体UUID>`：筛选根目标并保留其嵌套链。

`confirmed` 是首次有效损失快照，后续写入可能继续增加总量。
