# 伤害结算与追加效果

## 伤害入口与事件阶段

服务端通过 `target.hurt(source, amount)` 发起伤害。苦旅在该调用的 Forge 伤害事件与原版结算阶段处理属性、防御及追加效果。

通常按以下次序结算：输入与免疫检查、来源转换、Attack/Hurt 事件、内部倍率与必杀、原版护甲和魔法防御、输出增幅、百分比减伤、见切、霸主、吸收生命、最终 Damage 事件和普通生命扣除。取消或免疫会结束对应分支。

事件监听器按所需阶段修改伤害。直接调用 `setHealth` 不进入上述事件和吸收结算。

## 来源与命中确认

同一笔伤害的原始来源与参与防御判断的有效来源可能不同；事件监听器应使用所在阶段提供的来源。`hurt` 的返回值与实际生命损失分别处理，吸收生命下降也可确认命中。替换来源时保留直接实体与责任实体。

仅统计伤害、不扣除原版生命的实体，可在实际受击路径中调用：

```java
CombatContext.recordDummyDamage(target, source, amount);
```

此方法位于 `com.thelongtravail.combat.CombatContext`，完整签名为 `recordDummyDamage(LivingEntity, DamageSource, float)`。在服务端游戏线程、当前目标的伤害调用尚未结束时上报已接受的金额；目标及来源须与该次伤害匹配。客户端、非正数、非有限值或没有匹配上下文时不记录。该入口触发相应的命中确认，不扣除生命或发起新的 `hurt` 调用。

## 追加、反伤与重放

TLT 内部的增伤、追加与重放分派同时使用伤害类型和来源私有标记。外部监听器按 Forge 事件流程执行。

第三方反伤类型加入 `the_long_travail:retaliation` 标签，使本模组识别反伤链。跨游戏刻的反伤同样需要保留该标签。

外部追加伤害通过新的 `hurt` 调用独立结算。延迟伤害应在执行前复核目标身份、存活和所在维度。

## 诊断入口

JVM 参数 `-Dthelongtravail.damageTrace=true` 启用 `TLT_DAMAGE` 日志，记录根调用、父子关系、目标、来源、金额、策略、首次确认及退出状态。

- `-Dthelongtravail.damageTrace.limit=256`：记录条数，范围 1–10000。
- `-Dthelongtravail.damageTrace.target=<实体UUID>`：筛选根目标并保留其嵌套链。

`confirmed` 是首次有效损失快照，后续写入可能继续增加总量。

## 订阅实际扣血

在 Forge 事件总线上订阅 `DamageHealthLossEvent`。服务端伤害结算实际扣除普通生命值时，`getEntity()` 返回受伤实体，`source()` 返回伤害来源，`amount()` 返回本次扣除的普通生命值。仅消耗伤害吸收时不会触发。
