# 伤害结算与追加效果

## 接入位置

伤害通过 `LivingEntity.hurt` 或 `Player.hurt` 进入 [DamageScope](../../src/main/java/com/thelongtravail/combat/DamageScope.java)，每次调用建立独立的 [CombatContext](../../src/main/java/com/thelongtravail/combat/CombatContext.java)。

通常依次执行输入与免疫检查、来源转换、攻击及 Hurt 事件、内部倍率与必杀、原版护甲和魔法防御、输出增幅、百分比减伤、见切、霸主、吸收生命、最终 Damage 事件及普通生命扣除。取消和免疫会提前结束对应分支。详见[战斗属性](combat-attributes.md)。

新增攻击使用服务端 `target.hurt(source, amount)`；事件监听器按所需阶段修改伤害。直接 `setHealth` 不进入伤害事件、吸收和攻击后收益。独立生命损失见[三个战斗效果](三个战斗效果.md)。

## 来源与金额

| 字段或概念 | 用途 |
| --- | --- |
| 输入金额 | 传给 hurt 的值，继续参与后续防御和事件结算。 |
| 原来源 | DamageIdentity.original 保留的来源实例，用于追加、反伤、重放和处决身份认领。 |
| 有效来源 | 籠釣瓶或波旬转换后的类型，用于当前防御与标签判定；直接实体和责任实体保留。 |
| damageRecord.total | 实际生命与吸收下降量之和；假人可提供专用确认值。 |
| damageRecord.healthLoss | 普通生命的非负下降量，用于第六天魔王吸血。 |
| damageRecord.committed | 生命下降是否已提交的布尔标志，用于 HEALTH_LOSS 受击惩罚。 |

每个上下文只做一次首次有效损失确认；吸收生命下降也可确认命中。`hurt` 返回值不能替代损失记录。只记录统计而不减原版生命的实体可按[假人适配](optional-compat.md#试验假人)提供确认。

主体归属按具体机制解析：普通伤害读取 DamageSource，女仆由安全门面解析，幡收魂另行回溯弹射物 owner。女仆阶段读取在线主人，伤害和属性仍属于女仆。多部件目标以主体保存状态和冷却，实际伤害继续调用命中部件，保留部位修正。

## 增伤、减伤与标签

普通输出按 `1 + outgoingBonus()` 相加，必杀另乘 2。百分比减伤在 `DamageReduction` 中将各适用剩余倍率相乘，再扣见切、判断霸主；单项遵守各自上限，不另设总减伤上限。

肃正读取有效来源的[物理和魔法标签](伤害分类与肃正.md)，两类同时命中时选择魔法。来源转换后按新类型分类，不从原类型追溯。

第三方反伤类型加入 `the_long_travail:retaliation`，使见切和蔷薇识别反伤链。同步嵌套伤害还受当前作用域限制；跨刻反伤应保留该标签。

## 追加与重放

| 来源 | 金额与 TLT 内部处理 |
| --- | --- |
| 逐日追加 | 伤害开始时的目标最大生命乘配置比例；排除本模组输出增幅与必杀，仍经过适用防御和外部事件。 |
| 堂吉诃德追加 | 原攻击前的目标当前生命乘比例；使用专用来源身份，不重复普通增伤、必杀和见切，仍检查霸主。 |
| 洛伦兹幻想追加 | 命中前目标当前生命乘比例；保留射手，排除普通输出增幅与必杀，继续适用见切和霸主。 |
| 无穷花重放 | 保存已结算金额，跳过已结算防御及必杀、见切，仍检查当前霸主。 |
| 见切反击 | falling_anvil 类型，责任实体为受击者；可必杀，普通输出加成为零，防御侧正常处理。 |
| 玫瑰丛反击 | 直击类型及独立反击身份，使用自身金额与分支资格。 |

来源私有标记控制 TLT 自身分派；外部伤害监听器仍在正常 hurt 链执行。使用相同 DamageType 不会自动取得这些私有来源身份。

`CombatContext.close()` 恢复父上下文后再执行 finish，仍处于 `DamageScope` 的同步范围。异常退出清理作用域但不执行正常 finish。逐日以效果主体 UUID 在同步派生链中认领一次；跨刻重放建立新范围。逐日与籠釣瓶的细则见[专项接入](sun-chaser-kagotsurube.md)。

## 死亡与延迟处理

死亡监听器取消事件或恢复实体时，猪笼草回血、幡收魂与死者之书会在各自后续节点复查结果。幡还要求原装备实例仍佩戴，处决收魂与普通死亡记录共享去重。

延迟任务分别校验存活、维度、状态代次或装备实例，接入方应保留对应身份，不将旧任务交给重生或替换后的新实体。卸装、退出与换维度清理本来源状态。

阿兹拉尔终结可进入原版死亡和底层存储清理，专用目标与来源实例匹配时跳过普通战斗属性。其强制路径可能绕开第三方可取消死亡及自定义 die；依赖这些回调的 Boss 奖励和任务需独立协作。受限掉落补偿见[战利品接入](loot-integration.md#强制终结补偿的联动边界)。

## 伤害链诊断

JVM 参数 `-Dthelongtravail.damageTrace=true` 启用 `TLT_DAMAGE` 日志，记录根调用、父子关系、目标、来源、金额、策略、首次确认及退出状态。

- `-Dthelongtravail.damageTrace.limit=256`：记录条数，范围 1–10000。
- `-Dthelongtravail.damageTrace.target=<实体UUID>`：筛选根目标并保留其嵌套链。

confirmed 是首次有效损失快照，后续写入可能继续增加总量。诊断关闭时不创建诊断作用域。

## 磷叶石治疗触发

磷叶石的触发配置位于 `aspects/deep_valley.toml` 的 `[items.phosphophyllite]`：`healTrigger`、`healCooldownTicks`、`healExcludedDamageTypes`。分别控制触发阶段、治疗尝试间隔和排除的伤害类型；默认受击触发、0 刻、空列表。概率未命中也计入尝试间隔。

`CombatContext` 分别读取苦旅与磷叶石的触发模式。磷叶石自行校验见证条件并持有独立的 `ReceivedHitGate`；苦旅恶意的冷却、排除项及跳过惩罚不控制磷叶石。二者只复用判定工具，治疗仍在本次伤害流程收尾时执行。磷叶石的触发模式独立同步到客户端，供简述和拾遗详情使用。
