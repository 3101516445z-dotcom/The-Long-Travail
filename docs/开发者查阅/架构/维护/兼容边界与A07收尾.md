## 女仆适配的实际范围

本轮直接核对 [MaidAccessories](../../../../src/main/java/com/thelongtravail/compat/maid/MaidAccessories.java)、[MaidAccessoryRuntime](../../../../src/main/java/com/thelongtravail/compat/maid/MaidAccessoryRuntime.java) 的装备、主人、阶段、身份、装备变更、tick/停服入口，以及 [MaidAccessoryLedger](../../../../src/main/java/com/thelongtravail/compat/maid/MaidAccessoryLedger.java)、[TravailMaidPlugin](../../../../src/main/java/com/thelongtravail/compat/maid/TravailMaidPlugin.java)、[MaidBaubleSync](../../../../src/main/java/com/thelongtravail/compat/maid/MaidBaubleSync.java)。Runtime 内各战斗算法仍按对应玩法专项的已读范围认定，不宣称本轮重新逐方法审计。

MaidAccessories.items 当前明确登记 15 项：spring_corner、everlasting_flower、eki、tokaido、midnight_lafite、icarus、don_quixote、azrael、sword_and_lantern、phosphophyllite、a_thousand_years_later、demon_king_of_the_sixth_heaven、myriad_souls_banner、star_voice、lorentz_fantasy。

其余 9 项 affection、mistletoe、perfect_fluid、golden_age、tower_of_babel、underground_velvet、book_of_the_dead、free_and_easy_wandering、little_prince 未在该饰品绑定列表中。这里仅说明登记范围，不等于这些物品对女仆绝无被动影响、所有权交互或外部容器作用。

- 外层通过 ModList 的 touhou_little_maid 是否安装决定是否调用 Runtime；不是所有兼容都经过 Mixin Gate。
- Runtime.equipped 读取女仆实际饰品槽，拒绝死亡/已移除实例。phase 找在线且未断开的主人，再读主人日记见证；主人缺席或无日记返回 INACTIVE。不能把主人的槽位物品直接当作女仆装备。
- identity 将独立 UUID 写入女仆 persistentData；MaidAccessoryLedger 在主世界 SavedData 的 travail_maid_accessories 中保存按身份组织的状态。星之声等冷却不使用主人的玩家键，账本 complete 仅对已有条目合并最大冷却。
- 饰品穿脱触发 equipmentChanged：堂吉诃德忘记状态、死告天使取消 armed 并增加 generation、剑与灯清战斗状态；无穷花脱下额外调用 cancel 终止旧追加链。不能把任何换装都描述为清空全部持久冷却。
- tick 在冻结判断之前仍有属性对账和剑与灯效果清理，冻结判断之后才处理相应治疗计时和账本冷却；不能概括为“冻结时整个 Runtime 什么都不做”。serverTick 遍历受监视实体，清死亡/移除状态，再处理进入本轮时已有的 PENDING 数量；停服清运行容器，不等于删除 SavedData。
- MaidBaubleSync 对受监视女仆保存快照、发送 changes，StartTracking 发初始变化并 watch，停服清快照。同步消息最终应用仍依赖第三方网络实现，本轮未逐行核对第三方接收端。

必须另行运行：主人上线/离线、日记阶段切换、女仆穿脱/卸载重载、实体身份复制、星之声组冷却、死告天使排队后换装、无穷花脱下与剑与灯追踪同步。未运行前不将 15 项登记写成“15 项兼容测试通过”。

## 可选加载与注入边界

本轮核对 [OptionalCompatPlugin](../../../../src/main/java/com/thelongtravail/compat/OptionalCompatPlugin.java)、[OptionalCompatState](../../../../src/main/java/com/thelongtravail/compat/OptionalCompatState.java) 和 [兼容 Mixin 清单](../../../../src/main/resources/mixins.the_long_travail.compat.json)；检查器内部契约和目标方法行为继续沿用 [输入请求与可选加载](../链路/输入请求与可选加载.md) 及对应专项。

| 分支 | 已读加载条件 | 未由条件证明的内容 |
|---|---|---|
| 神化名称、Quark 日记符文 | 按对应模组 ID 存在判断 | 目标版本方法语义及注入成功 |
| 假人伤害 | 目标方法签名及 totalDamageTakenInCombat 的指定写入次数为 1 | 第三方全部伤害路径、显示/实际统计一致 |
| 女仆性格存储 | stamp/buildRequest/resolveRelease/superviseHealthFix 四个静态方法契约 | 动态生命恢复与其他插件写入竞争 |
| MaidSwim/MaidRelicSlot | 检查目标类可读；缺类不加载，IOException 抛 IllegalStateException | 完整 API 版本匹配；异常不是统一静默降级 |
| Gravestone、Caelus | 共享 Gate 检测并缓存状态，检查器见 OptionalCompatChecks | 墓碑插件的私有存储和实际飞行/复活行为 |
| Embeddium 灯光 | calculate 的特定描述符存在 | 渲染正确、光照无残留、性能收益 |
| JEI 覆盖层 | 指定绘制方法名称和 void 返回特征 | 所有参数/内部绘制布局兼容，或配方数据正确 |
| Sounds | 字段、方法及指定指令布局联合检查并缓存 | 所有声音路径在不同插件组合中的行为 |

Gate 由 UNCHECKED 转为 ABSENT/ENABLED/DISABLED，之后复用结果；不因一般配置热重载重新探测。Gate 捕获缺类、IO 和 LinkageError 后禁用，与其他独立分支的异常策略不同。清单 required=true、defaultRequire=1，不能据“可选”二字认为被放行的所有注入失配都会安全跳过。未单独匹配的分支也不能假定已经过强契约检查。

Curios 是必需依赖；编译期与运行期分别查看 [mods.toml](../../../../src/main/resources/META-INF/mods.toml)、[optional-compat.gradle](../../../../gradle/optional-compat.gradle)。移动兼容类必须同时检查 package、Mixin 注册、构建和入口文档。

## 后续结构调整：女仆基础访问

第四轮将原 Runtime 的 equipped、owner、identity 方法体提取至 [MaidAccess](../../../../src/main/java/com/thelongtravail/compat/maid/MaidAccess.java)。装备仍返回原槽位中的首个匹配 ItemStack；死亡/移除返回空，主人只接受在线且未断开的 ServerPlayer，身份仍使用 TravailMaidIdentity 键且仅缺失时创建。MaidLanternCombat 直接使用基础访问；MaidAccessories.casterId 仍经可选模组检查后进入。原 Runtime 公开方法保留转发，阶段判断、饰品规则、缓存、队列和事件次序保持原位。具体实施及验收记录见 [结构优化实施记录](结构优化实施记录.md)。

## 后续结构调整：女仆规则查询

第五轮新增 [MaidAccessoryRules](../../../../src/main/java/com/thelongtravail/compat/maid/MaidAccessoryRules.java)，承接主题阶段、饰品选取、生效资格及春日一隅/天气相关只读查询。MaidAccess 提供原生访问，MaidAccessoryRules 组合查询规则，MaidAccessoryRuntime 保留事件、效果执行、冷却与缓存生命周期；MaidAccessories 负责可选模组门禁。原 Runtime 的公开方法继续转发。

阶段查询不统一增加装备或存活条件：多数阶段函数只依赖主人的日记；phosphophyllitePhase 仍额外要求有效装备，装备查找本身拒绝死亡/移除的女仆。基础条件和阶段条件必须按具体规则组合。Phase 仍使用原 MaidAccessoryRuntime.Phase 枚举类型以保留现有签名，规则类不调用 Runtime 的执行方法；仍保留类型层面的依赖。

## 第十三轮依赖收尾

当前 END tick 调度归 [MaidRuntimeMaintenance](../../../../src/main/java/com/thelongtravail/compat/maid/MaidRuntimeMaintenance.java)。它从 MaidRuntimeState 获取实体快照，按原顺序执行刷新及 MaidPeriodicEffects，再调用状态组件排空本次队列。MaidRuntimeState 不再依赖 MaidPeriodicEffects；前文第九轮记录中的双向依赖已解除。Phase 的原公开类型仍保留，未扩大迁移范围。
