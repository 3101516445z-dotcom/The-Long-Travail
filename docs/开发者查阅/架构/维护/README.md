## 生成和检查

在仓库根目录使用现有 Node.js 18+：

```text
node docs/开发者查阅/架构/维护/generate.mjs
node docs/开发者查阅/架构/维护/generate.mjs --check
node docs/开发者查阅/架构/维护/test-checks.mjs
```

生成器读取 Java 主源码及下述资源/构建范围，写入索引中的四份固定文件：源码归属.md、引用候选.md/json、资源与构建指纹.json。--check 不写文件，比较预期索引并检查本地 Markdown 内联链接及 Markdown 标题锚点。不加载游戏，不修改 Java、配置或 JAR；未接入 Gradle 正式构建。

分类规则集中在 generate.mjs 的 groups 与 overrides；前者提供目录初分，后者记录重点例外。规则修改后重新生成。人工章节单独维护，不由工具覆盖。

## 当前实现边界

生成器使用无额外依赖的词法扫描建立类型引用候选。显式导入、同包和通配导入只帮助筛选候选；局部同名变量可能误报，嵌套类型与动态接入可能漏报。tokenLine 记录候选标识在源码中的位置。

引用候选用于导航；确认调用关系时需沿源码及实际编译类路径核对。

Java 指纹维持原格式，独立覆盖 src/main/java。新增 [资源与构建指纹](../索引/资源与构建指纹.json) 对 src/main/resources、src/main/lang、gradle 全目录，以及 build.gradle、settings.gradle、gradle.properties、gradlew/gradlew.bat 和四份具名 tools 语言脚本计算路径与字节 SHA-256；增加、删除、修改均会使 --check 失败。明确列表见 JSON 的 scope，缺失的固定文件不入 files，新增后可检测；扫描范围以该列表为准。

指纹不依赖 Git 是否跟踪文件，不含用户配置、build 生成物、外部依赖 JAR、src/test 或所有本机脚本。资源二进制也按字节记录，但不会解析纹理含义或检查资源引用闭包。

[checks.mjs](checks.mjs) 检查项目书所有 Markdown 内联链接的本地文件/目录，支持角括号路径和百分号编码；带 fragment 的 Markdown 目标（含项目书之外的文件）检查 ATX/Setext 标题及重复标题 -N 后缀，忽略 fenced code 中的示例链接。标题使用本仓库约定的 Unicode 小写/去标点/空白转连字符规则；不是完整 GitHub/CommonMark 渲染器。引用式链接、HTML 链接/自定义锚点、复杂内联嵌套与 HTML 实体未实现，非 Markdown fragment 不校验，外部 URL 不联网检查。受审计目录中的符号链接拒绝递归，以免把范围扩展到目录外。

[test-checks.mjs](test-checks.mjs) 在独立临时仓库运行 14 个正反例：中文/重复/Setext 标题、fenced 示例、编码和空格路径、断链/缺锚点、资源/语言/构建/工具变化检测、原 Java 检查保留，以及不同 cwd 运行。临时目录创建后仅删除本次夹具。此检查器不新增 npm 依赖。

## 更新触发

新增/删除/修改 Java 或列入 scope 的资源/构建输入后生成索引；改变职责、公共入口、数据存储或生命周期时更新相应章节。修改网络或 Mixin 时重新核对注册、方向、方法目标和接收线程。人工章节按对应实现同步维护。

生成器与检查器随架构文档提供，可在仓库根目录独立运行。
