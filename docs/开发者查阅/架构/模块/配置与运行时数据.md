# 配置与运行时数据

## 配置定义与文件装配

`config` 根包保留配置定义、公开句柄与重载协调；`config/storage` 管理文件注册、读写、恢复、监听和发布，`config/defaults` 管理联动默认池及初始化标记。定义辅助类、文件管理内部类和默认条目辅助类分别保留同包封装。

[TravailConfig](../../../../src/main/java/com/thelongtravail/config/TravailConfig.java) 按顺序创建各文件的 Builder，装配主题和物品定义，最后生成 SPECS。公开配置句柄由此集中提供；各定义组返回持有本组句柄的 record。

| 定义组（位于 config） | 配置文件与职责 |
|---|---|
| GeneralConfigDefinition | general.toml 的通用规则、探索数量及自动效果预算 |
| RewardDeliveryDefinition | general.toml 的奖励投递预算与溢出策略 |
| UtilityItemsDefinition | utility_items.toml 的路引搜索与引导参数 |
| FlourishingDefinition、AbyssDefinition、FarReachDefinition | 繁茂、归墟、穷遐文件的要求池、恶意与见证规则 |
| DeepValleyDefinition、UnderworldDefinition、BoundlessDefinition | 幽谷、冥府、无垠文件的要求池、恶意与见证规则 |
| VisualDeprivationDefinition | aspects/deep_valley.toml 的视觉剥夺画面参数 |

[TravailDefinitionSupport](../../../../src/main/java/com/thelongtravail/config/TravailDefinitionSupport.java) 提供数值范围、列表条目格式检查和要求池定义；Builder 与要求池映射由装配方传入。[TravailPoolDefaults](../../../../src/main/java/com/thelongtravail/config/TravailPoolDefaults.java) 提供各主题内置效果、垂钓和幻影奖励条目。联动默认值仍由对应 CompatDefaults 定义和初始化。

各组只参与定义期装配。文件恢复由 ConfigRecovery 管理，字段转换由 ConfigValidation 管理，热重载后的机制刷新与客户端同步由 ConfigReloadCoordinator 调度。新增主题规则在相应 Definition 中定义，需要公共访问的句柄在 TravailConfig 暴露；独立物品参数进入现有主题 ItemsConfig。

## 效果和移动接入

`mixin/effects` 集中效果持续时间、隐藏效果链和移除回调访问，以及共用溢出治疗结算。`mixin/movement` 集中高度系数缓存、普通速度、飞行速度、鞘翅位移与撞墙系数，以及僵硬效果的速度处理。具体状态和规则分别位于 `runtime/attributes`、`runtime/effects` 与 `common/OverflowHealing`。

## 运行机制归属

| 路径 | 职责 |
|---|---|
| diagnostics/HotPathMetrics | JVM 开关控制的热点计数与观察 |
| common/weighted | 权重条目解析、累计权重表与抽样 |
| runtime/pools | 效果、奖励条目与 RuntimePools 不可变快照发布 |
| runtime/effects | 自动效果预算、动作窗口、清理轮换、效果修改、等级与持续状态 |
| runtime/attributes | 高度惩罚、飞行速度调整与繁茂属性支持 |
| runtime/rewards | 奖励持久队列、预算与投递 |
| runtime/scheduling | 日记周期任务的分相调度 |

RuntimePools.reload 依次诊断效果预算、刷新高度惩罚状态、失效旅程候选池、构建并发布快照，随后清理探索查询与路引任务。效果状态、属性修饰和奖励队列分别由对应组件管理；配置重载仍使用集中协调入口。

本章说明 TLT 的配置注册、文件恢复、候选发布和公共配置重载后的运行时刷新入口。完整过程见 [配置加载与重载](../链路/配置加载与重载.md)，接口和测试约定见 [公共运行模块](../../runtime-integration.md)。

## 基础能力与协调层

| 职责 | 源码入口 | 边界 |
|---|---|---|
| 注册与装配 | [ConfigFiles](../../../../src/main/java/com/thelongtravail/config/storage/ConfigFiles.java) | 将 TravailConfig.SPECS 注册为 COMMON，将客户端定义注册为 CLIENT；装配默认池补充和监听生命周期 |
| 单文件状态管理 | [ManagedConfig](../../../../src/main/java/com/thelongtravail/config/storage/ManagedConfig.java) | 维护磁盘基线、当前有效配置、是否可写和是否监听；连接 Forge 配置事件 |
| 解析与文件写入 | [ConfigFileIO](../../../../src/main/java/com/thelongtravail/config/storage/ConfigFileIO.java) | UTF-8/TOML 解析、委托排版、临时文件替换；不负责玩法缓存 |
| 定义校验 | [ConfigValidation](../../../../src/main/java/com/thelongtravail/config/storage/ConfigValidation.java) | 按 ForgeConfigSpec 转换、补齐和回退字段；包含动态战利品概率处理 |
| 启动恢复 | [ConfigRecovery](../../../../src/main/java/com/thelongtravail/config/storage/ConfigRecovery.java) | 原始字节备份、默认值恢复、迁移及写前比较 |
| 文件事件 | [ConfigWatcher](../../../../src/main/java/com/thelongtravail/config/storage/ConfigWatcher.java) | 后台监听、事件合并、调用单文件重载；不在此直接刷新游戏世界 |
| 派生数据 | [RuntimePools](../../../../src/main/java/com/thelongtravail/runtime/pools/RuntimePools.java) | 解析注册表相关池，发布快照并清理探索缓存；同时协调高度惩罚等具体机制 |
| 服务端刷新与展示同步 | [ConfigReloadCoordinator.onConfigReloading](../../../../src/main/java/com/thelongtravail/config/ConfigReloadCoordinator.java) | 转入服务端执行队列，刷新机制、菜单及客户端提示快照 |

ConfigFileIO 是文件基础设施；ManagedConfig 是带 Forge 生命周期的管理层；RuntimePools 与 TravailNetwork 已直接依赖具体玩法，属于协调层。新增玩法可以复用前者，但不能把后两者描述为完全独立的通用库。

## 三份状态不能混用

| 状态 | 所有者 | 用途 |
|---|---|---|
| 磁盘原始字节与最近基线 `disk` | 文件系统、ManagedConfig | 检测重复通知和写入期间的外部修改；不是玩家存档 |
| 已发布配置 `active` 与 ForgeConfigSpec | ManagedConfig | 供配置读取；非法字段回退后可以与磁盘内容不同 |
| 运行时快照和缓存 | RuntimePools、各机制、客户端同步层 | 从有效配置和注册表派生；需要刷新、失效或网络同步 |

`RuntimePools.snapshot` 是 volatile 引用，重建完成后一次替换。池条目经过格式及注册表可用性检查；相同目标保留首条，后续重复项记录警告。等级映射和黑名单使用只读副本。配置文件发布、机制缓存刷新和客户端同步分别执行。

## 生命周期与失败边界

- 启动时由 `ConfigRecovery.prepare` 恢复并写入规范化配置；存在问题的原始文件先归档到配置目录的 `invalid` 子目录，并保存说明及核对备份字节。I/O 失败可以阻断加载，不能一概认为总能自动恢复。
- Loading 事件后启动监听；卸载时移除对应文件回调，无剩余文件的目录监听被取消。
- 热重载的字段非法与整份 TOML 无法解析走不同分支，详见链路章。`rejected` 表示禁止本次写回，不表示整份候选不发布。
- `save()` 只在已加载且可写时执行，并比较磁盘基线。`update(edit)` 是内部预设编辑路径：写入后更新配置，但没有显式分发 Reloading 事件，也未复用完整 validate 流程。不能把它当作自动刷新全部运行时机制的通用入口。
- `spec.correct` 可能移除未定义键。

## 新增配置时查什么

先在对应 Spec 定义键、默认值和合法范围，再核对排版与双语说明。随后区分读取方式：直接 `.get()`、预计算池、缓存、客户端提示分别需要对应的更新路径。依赖注册表的值在注册表就绪后解析。

修改公共配置刷新逻辑时，沿 `ConfigReloadCoordinator.onConfigReloading` 检查 RuntimePools、GoldenAgeActions、Affection、菜单、RainEvents 和 TooltipConfigPacket；新增缓存必须明确由谁失效。客户端配置不进入这个 COMMON 过滤后的广播流程。

配置规则、预设格式和已有测试入口以 [运行时约定](../../runtime-integration.md) 为准。

## 配置保存与默认项合并

ManagedConfig 保留锁、校验、入口差异和异常策略；ConfigFileIO.writeChecked 负责有版本检查的写盘，publish 负责运行时发布。[ConfigDefaultEdits](../../../../src/main/java/com/thelongtravail/config/defaults/ConfigDefaultEdits.java) 提供列表默认值编辑能力，applyLive 明确完美流体现有的先改活动配置策略，不能用它替代普通 update 的候选隔离路径。详见 [默认池链路](../链路/默认池初始化与更新链路.md)。

## 环境峰值迁移与固定能力

ConfigValidation 在字段校验前迁移伊卡洛斯 sunnyPeak 和午夜拉菲 shelteredNonClearPeak：仅当当前定义包含新键、新键缺失且旧键存在时，将旧总峰值减去 malicePeak，写入 sunnyExtraPeak 或 shelteredNonClearExtraPeak，并限制在0.01至1000之间。普通峰值缺失时按默认0.5换算；无效旧值交给后续校验和归档。显式提供的新键优先，重复读取不会再次换算。

迁移记录进入现有 issues，原配置的归档仍由 ConfigRecovery 负责；spec.correct 清除已无定义的旧键。旧配置中的零值不再用于关闭环境或见证加成。

RainConfig 不再定义东海道 skill.enabled；RainEvents 与 RainWeather 固定按启用机制执行。FlourishingItemsConfig 不再定义 repairOnApply，ImmortalBud 赋予标记时直接修复耐久。逍遥游没有技能启用配置。路引 searchRadius 的范围为16至30000000，WayguideSearch 不再额外截断到5000。
