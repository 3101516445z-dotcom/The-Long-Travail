# 装备与携带

本章介绍 TLT 的装备规则、恢复桥接、依赖清退、槽位维护和携带查询源码。女仆原生饰品系统另属兼容模块。

## 三种问题，三个入口

| 问题 | 入口 | 不能据此推断 |
|---|---|---|
| 当前用于状态查询的是哪本苦旅？ | TravailCurios.find/stack | 背包或末影箱中的苦旅不因此激活；find 本身委托 Curios.findFirstCurio，没有自行校验 travel_diary 名称 |
| 这个饰品可否放进这个位置？ | 物品 canEquip → AccessoryEquipRules / DiaryEquipmentRules | 查到物品不等于当前满足全部玩法触发条件 |
| 玩家是否携带某件物品？ | CarryingApi.query | 携带不等于佩戴；不自动赋予效果或装备资格 |

## 基础与扩展关系

| 代码 | 架构职责 | 主要使用者 |
|---|---|---|
| [DiaryEquipmentRules](../../../../src/main/java/com/thelongtravail/helper/DiaryEquipmentRules.java) | 日记特有佩戴/卸下规则，依赖有效见证读取 | LongTravailItem |
| [AccessoryEquipRules](../../../../src/main/java/com/thelongtravail/helper/AccessoryEquipRules.java) | 指定功能槽前置查询、单件限制；恢复时委托作用域 | 各类饰品 canEquip |
| [AccessoryRestore](../../../../src/main/java/com/thelongtravail/helper/AccessoryRestore.java) | 待恢复数据快照、首次接受位置、嵌套作用域 | AccessoryEquipRules、CuriosRestoreMixin |
| [TravailCurios](../../../../src/main/java/com/thelongtravail/helper/TravailCurios.java) | 首件日记定位、额外 curio 槽修饰、缩槽疏散及返还入口 | 日记、归乡、玩家维护、旅程变更 |
| [DependentAccessories](../../../../src/main/java/com/thelongtravail/helper/DependentAccessories.java) | 注册玩法前置、失效清理和清退协调 | 有日记前置的饰品 |
| [ItemDelivery](../../../../src/main/java/com/thelongtravail/common/ItemDelivery.java) | 拆分合法堆叠、主背包插入、剩余掉落 | TravailCurios 及其他投递逻辑 |
| [CarryingApi](../../../../src/main/java/com/thelongtravail/api/CarryingApi.java) | 服务端三态查询、来源缓存、外部接入 | 小王子、駅、巴别塔 |

ItemDelivery 属于较通用的基础能力；DependentAccessories 虽提供统一注册方法，内部仍直接列出物品及主题 cleanup；CarryingApi.allowed 也含駅与巴别塔旧配置规则。不能把这些协调器统称为无玩法依赖的底层库。

## 日记和额外槽位

DiaryEquipmentRules.canEquip 只接受 travel_diary 标识；canUnequip 要求玩家且为创造模式或六主题全部有效见证。全部见证依据 LongTravailData.hasWitness，因此包含调试覆盖的影响。LongTravailItem 禁止右键直接装备，Curios 掉落规则为 ALWAYS_KEEP；这些是日记专属规则，不应扩大为所有饰品规则。

LongTravailItem.onEquip 初始化日记并根据无垠见证维护额外 curio 槽。onUnequip 只有 newStack 不是该物品时才清槽，因为 NBT 变化也可能触发装备回调。TravailPlayerMaintenance 在正常运行和旅程变化中继续校正槽位。

TravailCurios 用固定 EXTRA_CURIO_SLOTS UUID 管理本来源修饰：相同数量及 ADDITION 操作时保持幂等；减少时先疏散末尾槽位中的功能物品，再移除旧修饰、添加新修饰。该疏散函数操作 getStacks，没有遍历外观槽；不应描述为已经处理所有第三方槽位排列或外观库存情况。

相关资源为 [日记槽定义](../../../../src/main/resources/data/the_long_travail/curios/slots/travel_diary.json)、[玩家槽分配](../../../../src/main/resources/data/the_long_travail/curios/entities/player.json)及[日记物品标签](../../../../src/main/resources/data/curios/tags/items/travel_diary.json)。配置和数据包可能改变实际槽位环境，Java 规则不是全部输入。

## 恢复期和运行期

正常 canEquip 通过 AccessoryEquipRules.hasEquipped 检查指定非外观槽；unique 允许同槽位索引替换，排除其他功能位置中的同种物品。includeCosmetics=true 只改变正常查询时的重复项范围，不表示允许装备到外观槽。

CuriosRestoreMixin 包装 readTag，在恢复执行期间建立 AccessoryRestore。hasDiary 此时检查输入快照中的 travel_diary，而非尚未完成恢复的当前库存。快照来自 StacksHandler.Stacks.Items，不包含 CosmeticStacks；它只报告输入中存在的前置，不递归判断该前置最终能否通过恢复校验。

unique 在恢复期记录第一个通过校验的位置，位置包含槽名、索引、cosmetic；同位置重复校验仍允许。它必须在物品其他校验之后调用，避免无效位置提前占用资格。ThreadLocal 保存前一作用域，close 恢复它，current 还检查实体对象身份，支持嵌套并隔离穿戴者。

详细时序见 [恢复与依赖返还](../链路/装备恢复与依赖返还.md)，接入契约见 [饰品佩戴与恢复校验](../../accessory-equipment.md)。

## 携带查询的运行顺序

1. 校验服务端游戏线程；死亡/旁观返回 ABSENT；同玩家递归查询抛异常。
2. 检查已确认位置缓存；每次重新校验来源开关、索引和物品，失效则删除。
3. 顺序扫描 inventory、offhand、armor、enderChest，然后查询 Curios 功能槽，排除外观槽。
4. 外部来源开关关闭则返回 ABSENT；开启时检查短期信号，再按注册快照查询 Provider。
5. 任一来源确认即返回 PRESENT。没有确认且某 Provider 抛 RuntimeException 则 UNKNOWN；否则 ABSENT。finally 释放递归标记。

查询不递归打开背包/潜影盒，不扫描普通方块容器；外部库存需要专用 Provider 或命名上报。仅缓存确认位置，不缓存否定结果。isCarrying 把 UNKNOWN 映射为 false，因此需要保守撤权的调用者必须使用 query。

| 调用者 | UNKNOWN 的当前处理 |
|---|---|
| LittlePrinceFlight | 仅延续已有内存 active，不首次授予飞行 |
| BabelCarrying | query != ABSENT，将 UNKNOWN 视为携带，保守保留保护资格 |
| RainState（駅） | 使用 isCarrying，不凭 UNKNOWN 确认携带收益 |

来源规则由全局 CarryingConfig 与特定物品旧开关共同限制。外部 Provider 与短期信号共用 externalInventoryTick 开关。Provider 使用唯一 ResourceLocation 注册，初始化单线程调用；重复 ID 抛错，回调中新注册项在下次查询参与。故障按来源每分钟限频记录，后续查询仍会尝试，不能误写为永久禁用。

信号按玩家/物品/来源记录游戏时刻，上报当刻及后两刻有效，时间倒退或超过窗口时清理。forget 清位置和信号；clear 还清递归和告警记录，但保留 Provider 注册表。小王子生命周期监听、巴别塔等调用方负责相关清理，不依赖 WeakHashMap 自动及时释放。

## 扩展和验证边界

新增饰品应明确槽位、外观、绑定、消耗状态和前置，再最后调用 unique；需要持续前置的物品另登记 DependentAccessories，并提供可重复执行、只撤销自身状态的 cleanup。不能只在 canEquip 检查而省略运行中失效路径。

新增携带来源优先复用 Provider/reportCarried；不把外部物品复制到玩家背包，也不通过携带 API 激活日记状态。女仆沿用原生饰品栏及在线主人查询，不自动纳入玩家携带接口。详见 [携带 API](../../carrying-api.md)和[小王子飞行](../链路/小王子飞行.md)。

本地 `gradlew.bat -I tools/accessory-restore.init.gradle runServer` 使用 build/accessory-restore-server、已有 run/eula.txt 和端口 25594，检查 accessory-restore-result.txt 为 PASS。tools 可能不随仓库提供。需覆盖恢复顺序、同位置复验、嵌套/异常、重复物品、前置失效、满背包/创造返还、缩槽与外部修饰、Provider 故障及恢复、信号过期。
