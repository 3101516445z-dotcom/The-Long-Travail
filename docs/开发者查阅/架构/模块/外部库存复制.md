# 外部库存复制

本章介绍配方、复制图、领取协调及五类存储适配。兼容格式细节继续维护在 [可选兼容](../../optional-compat.md#外部库存复制)，执行顺序见 [复制预览与领取](../链路/复制预览与领取.md)。

## 从玩法入口到存储适配

原版合成菜单接入位于 mixin/crafting：FluidCraftingGridAccessor 读取网格，FluidCraftingClickMixin 与 FluidCraftingQuickMoveMixin 将普通点击和快速移动接入 FluidCrafting。复制事务位于 abyss/copy，各外部存储适配位于 compat/fluid。

| 层次 | 源码入口 | 职责 |
|---|---|---|
| 配方 | [PerfectFluidRecipe](../../../../src/main/java/com/thelongtravail/abyss/copy/PerfectFluidRecipe.java) | 两个非空槽位、完美流体与目标识别、黑名单、预览及原件返还 |
| 物品规则 | [PerfectFluidCopies](../../../../src/main/java/com/thelongtravail/abyss/copy/PerfectFluidCopies.java) | 保护物品判断、单件复制、原件返还判断与内嵌内容净化 |
| 领取协调 | [FluidCrafting](../../../../src/main/java/com/thelongtravail/abyss/copy/FluidCrafting.java) | 服务端重新识别、菜单快照、准备、提交、领取及异常恢复 |
| 复制图 | [FluidCopyGraph](../../../../src/main/java/com/thelongtravail/abyss/copy/FluidCopyGraph.java) | 身份映射、内嵌遍历、外部库存队列、预算、写入和逆序回滚 |
| UUID 存储适配 | [FluidBackpackStore](../../../../src/main/java/com/thelongtravail/compat/fluid/FluidBackpackStore.java)、[FluidRsStore](../../../../src/main/java/com/thelongtravail/compat/fluid/FluidRsStore.java)、[FluidUnifiedStore](../../../../src/main/java/com/thelongtravail/compat/fluid/FluidUnifiedStore.java) | 为各系统复制真实内容并注册新身份 |
| 统一盘失败清理 | [UnifiedCopyCleanup](../../../../src/main/java/com/thelongtravail/compat/fluid/UnifiedCopyCleanup.java) | 分别尝试清理本次新建的 RS 代理、管理器条目和磁盘目录，汇总错误；源盘保持原状 |
| 内嵌资源格式适配 | [FluidAeStore](../../../../src/main/java/com/thelongtravail/compat/fluid/FluidAeStore.java)、[FluidBeyondStore](../../../../src/main/java/com/thelongtravail/compat/fluid/FluidBeyondStore.java) | 按资源键及真实数量转换，保留格式契约并校验回读 |
| 原版菜单桥接 | [FluidCraftingClickMixin](../../../../src/main/java/com/thelongtravail/mixin/crafting/FluidCraftingClickMixin.java)、[FluidCraftingQuickMoveMixin](../../../../src/main/java/com/thelongtravail/mixin/crafting/FluidCraftingQuickMoveMixin.java) | 普通结果槽点击及快速移动进入领取协调 |

`abyss/copy` 管理复制图、预算、事务和领取流程。`CopyStorage` 定义识别登记、转换上下文与提交/回滚契约；`compat/fluid/FluidStorageAdapters` 登记具体格式，存储实现通过上下文递归转换内容。复制内核沿用完美流体保护规则。[PerfectFluidBackpacks](../../../../src/main/java/com/thelongtravail/compat/fluid/PerfectFluidBackpacks.java) 仅将旧入口委托给复制图，并不是另一套背包复制实现。

## 适配器登记与移除

`CompatBootstrap` 调用 `FluidStorageAdapters.initialize` 安装登记表。转换顺序为物质球、AE2、背包、RS；引用识别顺序为背包、RS、AE2、物质球。每张复制图持有登记快照，按原顺序准备外部库存并提交写入。

移除存储实现时，在装配表中将对应 `Entry` 的 implementation 设为 null，并保留识别器。该格式仍被识别为外部存储，预览与领取会拒绝处理，材料保持原状；普通物品复制继续工作。RS 标准盘与统一盘共用一项登记，细分移除时需保留对被移除类型的拒绝分支。登记在初始化阶段完成。

## 身份、数量与原件

每次 prepare 新建一张 `(库存系统, 原 UUID) → 新 UUID` 映射。同一原库存被多处引用，只产生一个新库存；先记录映射再排队处理内容，因此 A 引用 B、B 引用 A 时副本仍互相引用，不回指原库存。不同次合成使用不同映射。这里的“独立”指副本与原件独立，不是强制拆散副本内部原有的共享关系。

普通 ItemStack/NBT 数据在副本上转换；外部库存必须由适配器读取真实存储。适配器负责复制受支持格式的存储内容；未知自定义存储引用没有自动复制流程。

最外层只复制一件目标。RS 标准盘的 Quantity、RSI 1.5.3 统一盘以及 AE2、物质球的 long 数量分别处理，不能通过原版字节 Count 搬运大数量。转换库存物品时以数量 1 序列化身份，再恢复数量或单独保存资源数量。

净化发生在复制品：各层苦旅、完美流体和当前黑名单物品被清除。普通内嵌槽位保留 Slot 和列表位置，改成 air/Count=0；资源表则按各自格式移除条目。不可堆叠、识别到特殊存储或内含需要净化内容的目标，输出一件副本并通过 remaining items 返还一件原件；其他目标输出两件。

## 适配矩阵

| 存储 | 实际内容与提交 | 拒绝条件举例 |
|---|---|---|
| 精妙背包 | BackpackStorage 内容复制，递归转换；提交注册新 contentsUuid | 原库存缺失、UUID 碰撞、capturedMobs 非空或类型异常 |
| RS 标准/共振盘 | writeToNbt、物品数量专用反序列化、原工厂重建；提交到磁盘管理器 | 未列出的实现、工厂缺失、重建类型改变、缺失库存 |
| RS Integration 1.5.3 统一盘 | long 物品/流体数量及 Mana、Source、Soul；独立磁盘文件、管理器 Entry 和 RS 代理 | 世界/格式错误、备份进行中、隔离条目、容量截断、身份冲突 |
| AE2 | 内嵌 AEKey 与 long 数量转换，相同输出键合并；AE2 读取接口回读验证 | 未知元件/资源通道、数量溢出或总数不符、绑定空间元件、危险创造资源 |
| Beyond Dimensions 物质球 | stack_list 逐条转换，保留顺序及各条 long 数量，不合并重复条目 | 未支持的资源实现/旧格式、字段异常、非整数数量、无法无损回读 |

AE2 分区过滤 list 不是实际库存，不能当库存复制或净化。物质球适配只识别该物品实际库存，不解释整个模组的网络绑定。所有直接 API、Mixin 成员布局与实现名称都需要在上游升级时重新核对。

## 支持范围与维护影响

`FluidCrafting.supported` 精确接受 InventoryMenu 和 CraftingMenu，子类不自动放行。识别到特殊引用或 AE2/物质球格式的目标，要求进入这个领取流程；自动合成和其他菜单没有因支持 ItemStack 而自动兼容。普通目标仍走普通配方领取。

复制仍为同步操作。深度 128、遍历计数 4,000,000、独立 UUID 存储 4096 是拒绝边界，不是时间或内存预算，也不是所有资源条目总数。外部库存链通过队列展开，NBT 深度在各库存内部重新起算；部分深拷贝发生在计数检查之前。

新增适配必须同时设计识别、预览、准备、真实数量处理、嵌套净化、提交及回滚。只增加一个 UUID 替换分支会使副本指向不存在或共享的存储。验证至少包含共享引用、循环引用、大数量、嵌套保护项、未知实现、提交中途异常、领取无空间及快速移动；上述场景需按当前版本验证。
