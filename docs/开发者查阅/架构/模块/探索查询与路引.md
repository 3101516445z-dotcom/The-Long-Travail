# 探索查询与路引

旅程数据模型见 [旅程与主题状态](旅程与主题状态.md)，物品完整流程见 [路引搜索与返还](../链路/路引搜索与返还.md)。

## 基础能力与扩展

| 层次 | 源码入口 | 职责与边界 |
|---|---|---|
| 空间匹配基础 | [JourneySpatial](../../../../src/main/java/com/thelongtravail/data/JourneySpatial.java) | 结构包围盒、群系邻点和空间缓存；不保存日记进度 |
| 探索协调 | [JourneyQueries](../../../../src/main/java/com/thelongtravail/data/JourneyQueries.java) | 玩家查询缓存、剩余条件、自然到访写入；未佩戴日记也可累计玩家群系发现 |
| 延迟确认 | [JourneyVisits](../../../../src/main/java/com/thelongtravail/data/JourneyVisits.java) | 固定观察位置、区块请求与过期检查；确认后写入日记 |
| 玩法扩展 | [WayguideSearch](../../../../src/main/java/com/thelongtravail/data/WayguideSearch.java) | 消费剩余条件寻找指引目标，不因找到远处目标完成该目标的到访 |
| 几何辅助 | [WayguideGeometry](../../../../src/main/java/com/thelongtravail/data/WayguideGeometry.java) | 螺旋扫描与短距离指向位置，不负责世界加载或进度 |
| 实体和补偿 | [WayguideEntity](../../../../src/main/java/com/thelongtravail/entity/WayguideEntity.java)、[WayguideReturns](../../../../src/main/java/com/thelongtravail/data/WayguideReturns.java) | 搜索展示、指引、物品托管与失败返还；见专项链路 |

这不是严格的独立分层框架：查询和搜索都直接读取 Minecraft 世界、配置和日记。复用空间匹配应从 JourneySpatial 入手；新增指引玩法需要另处理任务、实体、物品所有权和清理，不能只复制扫描函数。

## 自然到访的判定

[TravailEvents](../../../../src/main/java/com/thelongtravail/event/TravailEvents.java) 每 20 个玩家 tick 调用 JourneyQueries.update。查询还比较维度、方块位置、读取期限、时钟回退和日记条件身份。自然写入沿 LongTravailData.visitBiome / visitStructure，并 rebase 同玩家旧身份的待确认观察；不是每次都走外部 JourneyService 写入流程。

结构的 loadedAt 只通过 getChunkNow 读取已加载区块。水平容差为零时只看所在区块，否则看相邻一圈引用；再解析结构起点。普通结构使用整体包围盒，PIECE_ONLY 列表使用各 piece 包围盒；contains 应用水平/垂直配置容差，并用 long 做边界加减。不能把邻圈读取描述成任意半径穷举。

每个世界的结构缓存按玩家所在区块索引，最多 256 项；记录目标集合、候选盒和依赖区块。空候选有效期 20 tick，非空 100 tick，命中后仍用当前位置匹配盒子。区块加载/卸载按依赖失效，异步收到的事件通过服务器线程执行清理。

群系中心通过 level.getBiome 读取，不应把整个群系路径说成“只访问 getChunkNow”。中心命中剩余条件时直接返回；否则按配置半径检查同高度四个轴向邻点，仅在邻点所需周边区块已加载时采样。它不是圆形区域遍历。群系缓存每世界最多 2048 项、100 tick，半径变化、时间回退、中心变化或相关区块事件均参与失效。

## 延迟结构确认与身份

observe 先收集已加载匹配，再为未解决目标保存 Observation：玩家、世界、当时位置、目标和旅程 UUID/revision。缺少当前位置引用时请求 STRUCTURE_REFERENCES，缺少起点时请求 STRUCTURE_STARTS。

有效性要求玩家在线、存活、未移除、仍在同一世界、日记身份相同且未超过 30 秒。**不要求玩家仍站在原地**；确认的是观察时的位置。自然到访引起的 revision 变化由 rebase 衔接，外部修改及生命周期清理可以作废旧观察。

队列最多 256 条、每玩家 16 条，超量移除较旧观察；相同玩家/世界/位置/身份去重。tick 最多检查 256 条，使用 1 ms 软预算，一次至多新发起一个请求，全局只有一个在途请求。完成结果只在 future.isDone 后用 getNow 取出，写入前再核对观察仍在队列且有效。

取消、过期或 invalidate 会移除观察并释放自己的票据，但不取消共享 future；未完成请求继续占用在途名额。后续完成不再写入失效观察。clear 用于停止路径时进一步清空在途引用。这种保留名额的做法限制重复请求积累，也意味着长期未完成请求会阻塞后续确认；30 秒观察超时不等于强制终止底层生成。

## 搜索与确认的差异

| 问题 | 自然探索 | 路引搜索 |
|---|---|---|
| 坐标含义 | 玩家观察位置是否位于匹配范围 | 剩余目标的候选位置 |
| 群系证据 | 世界中心及已加载邻点 | 生成器 BiomeSource 噪声采样 |
| 结构证据 | 引用、有效起点及包围盒包含 | placement 候选处存在目标有效起点 |
| 身份变化 | 自然写入可 rebase 待确认观察 | 搜索任务要求最初身份仍相同 |
| 在途名额 | JourneyVisits 自己的一个名额 | WayguideSearch 自己的一个名额，两者不共用 |
| 输出 | 日记到访进度 | 实体方向提示与目标缓存 |

路引优先筛选当前生成器可能出现的剩余群系；有群系候选就采用 BiomeScanner，即使扫描失败也不会自动接着搜索结构。仅没有这类群系候选时才准备结构扫描。群系螺旋网格和高度层、结构 placement 轮转都受预算限制，不保证全局最近目标。结构 rings future 未完成时等待，不同步 join。

## 结构候选枚举

[WayguidePlacementCursor](../../../../src/main/java/com/thelongtravail/data/WayguidePlacementCursor.java) 负责随机分布与同心环结构的候选区块顺序，消费调用方提供的预算，不申请区块票据。WayguideSearch 保留任务队列、超时、在途请求及取消清理；StructureScanner 仍负责候选校验与请求衔接。

## 维护和验证

修改到访容差要同时检查缓存依赖、邻区块读取范围、piece 列表和延迟确认；修改旅程身份要检查 rebase 与外部失效；修改搜索策略要检查目标缓存、半径、超时和返还。

源码已核对上述入口及事件调用。运行待验收：边界/piece 到访、站位移动后的延迟确认、换日记/跨维度失效、慢区块请求释放票据后仍占位、多人队列公平性、实际群系与生成器采样差异。文档与索引检查不能证明服务器耗时上限或整合包兼容性。
