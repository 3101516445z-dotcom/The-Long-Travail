# 战斗结算

覆盖 TLT 伤害桥接、上下文、属性结算、见切反击与重放协调；第三方伤害实现需独立核验。各物品伤害公式、终结生命周期和多部件命中完整流程见玩法章节。

## 基础、协调与玩法扩展

| 代码 | 职责与依赖 |
|---|---|
| [ModAttributes](../../../../src/main/java/com/thelongtravail/registry/ModAttributes.java) | 注册三项实体属性、挂载属性供应器；可选百分比显示由 PercentAttributes 接入 |
| [CombatAttributes](../../../../src/main/java/com/thelongtravail/combat/CombatAttributes.java) | 读取修饰后的属性值，缺失/非有限返回零，并按范围钳制 |
| [AttributeDamage](../../../../src/main/java/com/thelongtravail/combat/AttributeDamage.java) | 单次伤害的必杀、见切、霸主、取消和反击安排；begin 也刷新部分玩法属性，不是纯数学工具 |
| [CombatContext](../../../../src/main/java/com/thelongtravail/helper/CombatContext.java) | 每次 hurt 的核心协调器；汇集玩法快照、免疫、输出、确认及后续效果 |
| [CombatConsequences](../../../../src/main/java/com/thelongtravail/helper/CombatConsequences.java) | received/confirmed 阶段向星之声、剑与灯、亚兹拉尔等分发，包内协作类 |
| [InsightRetaliation](../../../../src/main/java/com/thelongtravail/combat/InsightRetaliation.java) | 见切反击来源与同步反伤链保护 |
| [DamageReplay](../../../../src/main/java/com/thelongtravail/combat/DamageReplay.java) | 延迟已结算伤害队列、身份复核、续链策略与冷却现场恢复；当前源码中 EverlastingFlower 使用 enqueue |
| LivingCombatMixin / PlayerCombatMixin | 建立伤害作用域，记录生命及吸收变化；非玩家和玩家入口分工 |
| FluidErosionUnavoidableMixin / DamageReplayMixin | Forge Attack/Hurt/Damage 桥接及护甲后、吸收前节点；类名不代表只服务流体或重放 |

CombatContext 位于 helper，但直接依赖繁茂、归墟、穷遐、幽谷、冥府、无垠及女仆逻辑，是核心协调中心。不要仅按包名把它视为独立基础库。

## 运行阶段

普通链路为：输入校验 → Attack资格和受击尝试 → Hurt阶段内部受伤倍率及必杀 → 原版护甲/魔法防御 → 本模组输出与减伤 → 见切 → 霸主 → 吸收生命 → 最终伤害事件 → 普通生命 → 上下文收尾及后续效果。

这是一条阶段地图，不表示所有来源经过相同分支。`beforeAbsorption` 内各物品减伤与输出先后以源码为准，不能把它简化为可交换的统一乘数。具体属性语义仍以[战斗属性契约](../../combat-attributes.md)为维护源；时序和桥接见[伤害确认与重放](../链路/伤害确认与重放.md)。

## 三类触发不可混用

| 阶段/标记 | 来源 | 可以说明什么 |
|---|---|---|
| prepareAttack / accessoryAttack | 通过来源、数值、存活等入口筛选的攻击尝试 | 触发部分 received 逻辑，不证明最终造成伤害 |
| committed | 记录普通生命下降 | HEALTH_LOSS 受击惩罚的依据；不是吸收损失标记 |
| damageConfirmed | 有限普通生命或吸收损失；假人专用有效统计适配 | 在来源排除规则下确认实际伤害，同次调用避免重复确认 |
| recordedDamage / relicHealthLoss | 生命及吸收累计 / 独立普通生命损失累计 | 两者用于不同玩法，不可互换 |

hurt 返回 true、事件未取消和进入 Attack 阶段都不足以替代实际损伤确认。伤害归属取 DamageSource.getEntity，玩家专用分支要求 ServerPlayer，不自动把宠物攻击记给主人。

confirmDamage 在实际损失记录时即可分发部分效果，不是全部等到 hurt 返回；finish 再分发堂吉诃德后续、受击反馈、成功攻击、无穷花追加、治疗及属性反击。新增效果应先选择正确阶段并复用既有来源排除。

## 状态与生命周期

CombatContext.CURRENT 为 ThreadLocal 链，每次 hurt 有独立实例；current 同时匹配目标和 DamageSource 对象身份。嵌套伤害不会因为来源相同就共享实例，子调用确认损伤时会标记相同目标的父上下文，避免父调用错误恢复受伤冷却。

AttributeDamage 保存每笔伤害的 started/defended/cancelled、阈值和反击量；防御只结算一次。完全归零且本次及嵌套均未确认伤害时，finish 恢复旧 invulnerableTime/lastHurt；这不回滚耐久、击退或已经发生的回调。

DamageReplay 队列按服务器保存于内存，任务持有攻击者/目标/直接实体弱引用和来源类型、位置、数值、世界及策略。停服移除该服务器队列，不写入存档。InsightRetaliation 的 CHAIN 只覆盖同步调用范围，不识别未标记的第三方延迟反伤。

## 特殊来源边界

| 来源 | 当前核心处理 |
|---|---|
| 处决 | 实例匹配可放行专用非法数值；处决类型/实例按各入口排除属性；非匹配嵌套攻击不能自动继承全部豁免 |
| 流体侵蚀 | AttributeDamage 明确排除三属性，另受保护策略控制；不依赖数据包标签单一判断 |
| 伤害重放、堂吉诃德追加 | settled，不再抽必杀/扣见切，仍检查当前霸主；二者不能据此推断其他防御步骤完全相同 |
| 见切反击 | 特殊 DamageSource 实例，普通铁砧类型；不触发本模组普通输出加成和成功攻击追加链，防御仍处理 |
| 洛伦兹追加 | 不再必杀，不进入普通成功追加链；保留相应防御属性与 finish 中属性收尾 |
| 蔷薇/荆棘及 retaliation 标签 | 影响反击链识别；不等于禁用全部防御和其他反馈 |

InsightRetaliation.hit 还检查双方存活、世界、移除状态及玩家伤害权限。见切把伤害抵到零仍可安排反击；外部取消及最终归零的取消语义由 attributeDamage.cancelled/finishDamage 共同控制。

## 扩展与验证

新增成功伤害效果从 confirmed/finish 的既有分工接入，核对生命与吸收、反伤、重放、处决、嵌套及异常；新增乘区检查 Hurt 与 beforeAbsorption，不能另开 hurt 冒充必杀；新增重放策略明确 valid 与 continueChain，不能通过循环同步 hurt 绕过调度。

本地入口 `gradlew.bat -I tools/combat-attributes.init.gradle runServer` 使用 build/combat-attributes-server、run/eula.txt、端口25591，结果文件 combat-attributes-result.txt 须以 PASS 开头。女仆分支追加 -PcombatAttributesMaid；测试工具和第三方 JAR 不保证随仓库提供。

应验证阈值相等/相邻float、仅损失吸收、取消与归零、双方反击、图腾、玩家/非玩家、嵌套异常、重放失效/容量/续链、相同UUID新实例和第三方伤害覆盖。静态桥接存在不证明所有模组实体都沿用该链路。

## 数值记录与事件确认分离

[CombatDamageRecord](../../../../src/main/java/com/thelongtravail/helper/CombatDamageRecord.java) 只累计一次 hurt 上下文的实际生命损失、吸收损失及假人伤害。它不触发事件、不查询装备，也不决定命中反馈。CombatContext 继续管理嵌套作用域、取消、确认与 finish 次序，通过记录对象读取 committed、total、healthLoss。每个上下文独占记录对象；不把吸收损失当作 HEALTH_LOSS 惩罚条件。

改动前后各通过 4,410 项隔离服务端检查，覆盖数值边界、嵌套/异常恢复和既有伤害、吸收、取消及真实女仆场景；未宣称整包 TPS 改善。实施与证据见 [结构优化实施记录](../维护/结构优化实施记录.md)。

## 攻击快照拆分决策

当前 CombatContext 构造不只是读取数值，还会 claim 回放与药效标记，并在末尾安装当前上下文。因此保留该执行顺序，先通过嵌套/异常/取消回归约束行为。伤害数值记录继续由 CombatDamageRecord 承担。
