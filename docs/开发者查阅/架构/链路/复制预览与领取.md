# 复制预览与领取

源码分工与路径见 [外部库存复制](../模块/外部库存复制.md)。事务回滚覆盖TLT控制的提交步骤；第三方回调的外部副作用与断电后的跨文件恢复需由对应存储实现处理。

## 预览与真实准备分开

PerfectFluidRecipe.matches 检查两个非空槽位、目标保护规则、菜单支持及黑名单；异常记录后不匹配。assemble 通过 PerfectFluidCopies.copy 序列化目标，再调用 reserveIds，在副本上分配身份和净化，异常则给空预览。

assemble 在一次调用内复用输入 NBT 快照及引用识别结果，用于菜单资格和原件返还判断；输出转换仍在独立副本上进行，不跨调用缓存输入、输出 UUID 或外部库存资格。matches、remaining items 和实际领取仍重新核对。会改写已识别 UUID，但不排队读取它们指向的外部库存，也不提交存储写入。因此嵌套背包中的 capturedMobs 等限制可能直到领取时才被发现。内嵌 AE2/物质球数据仍经过专用转换。预览 UUID 不是最终领取 UUID；真实准备建立另一张图。

```mermaid
flowchart TD
    A[结果槽点击或快速移动] --> B[FluidCrafting.take 服务端重新识别]
    B --> C{需要专用复制?}
    C -->|否| D[普通 action]
    C -->|是| E[快照菜单、背包和鼠标物品]
    E --> F[prepare 转换根物品并遍历外部库存队列]
    F --> G[commit 按准备顺序写入新库存]
    G --> H[替换结果槽并调用原领取 action]
    H --> I{流体数量减少?}
    I -->|是| J[返回领取结果]
    I -->|否| K[回滚新增库存并恢复旧结果槽]
    F -->|异常| L[拒绝并报告阶段]
    G -->|异常| M[逆序回滚已尝试写入]
    H -->|异常| M
    M --> N[如已进入领取阶段 尝试恢复菜单及背包]
    N --> L
```

## 领取入口与重入

普通点击桥接只包装结果槽，并排除 QUICK_MOVE、CLONE、QUICK_CRAFT、PICKUP_ALL；QUICK_MOVE 由 quickMoveStack 单独包装。take 再检查服务端玩家、精确菜单类型及 ACTIVE 标记。ThreadLocal 防止同线程嵌套包装重复准备；finally 移除标记，它不是跨线程事务锁。

服务端重新从配方管理器识别当前配方。若旧结果仍在但配方已失配，网格里又存在完美流体，则拒绝，避免领取过期预览。只有本配方且 hasReferences 为真才走完整准备流程；AE2 和物质球也被此识别纳入，即使其内容不需要外部 UUID 写入。

## 准备与提交顺序

1. 保存全部菜单槽、玩家背包和鼠标携带物品；记录流体槽领取前数量。
2. `FluidCopyGraph.prepare` 以单件源物品建立根副本。transform 先处理保护项，再分流物质球、AE2 和 UUID 引用。
3. UUID 首次出现时先分配映射，再加入 pending；按队列顺序准备背包、统一盘或 RS 内容。适配器递归发现的新引用继续进入同一图。
4. prepare 返回非空 output 和待提交 Write 列表。commit 在调用每个 write.commit 前就将它加入 attempted，使“写入一半才抛错”的当前项也进入回滚范围。
5. 写入完成后把真实 output 放进结果槽，再执行原版领取。以流体槽数量是否改变判断本次是否消耗；未消耗则回滚新库存并恢复原结果槽。

prepare 与 commit 没有重新校验整个外部源库存版本的通用机制；源库存一致性依赖同步调用和各适配接口。

## 失败时恢复什么

Prepared.rollback 按 attempted 的逆序调用所有 rollback，单项异常仍继续尝试其他项，最后汇总异常。回滚针对本次新身份：背包删除新库存，RS 删除新盘，统一盘删除新代理、Entry 和新 UUID 目录；不以清空源库存作为补救。

FluidCrafting 捕获 Exception。若已经进入领取阶段，逐个尝试恢复非结果槽、玩家背包，最后恢复结果槽和鼠标物品；单个槽位恢复失败会附加到原异常，继续恢复其他项。通知失败和广播失败也汇总到诊断。普通配方 action 的异常在该专用 try 之外，继续向外传递。

回滚处理本次登记的写入与菜单快照。外部接口已发生的副作用、恢复回调异常和 Error 继续由对应接口处理；各存档文件独立落盘。统一盘通过 UnifiedCopyCleanup 分别尝试删除新 RS 代理、管理器条目及新 UUID 目录；单步异常不阻断后续步骤，单个文件删除失败仍继续处理其他可访问文件。目录遍历不跟随符号链接。失败汇总包含新 UUID、目录及失败步骤，每个失败身份单独记录；不自动重试，不操作源盘。复制图仍继续其他 Write 的回滚。

## 定位问题

按 identification → snapshot → preparation → commit → collection 的阶段定位。能预览但领不到，先看 preparation 的外部内容与格式限制；出现残留新库存时再核对 commit/rollback 诊断和新 UUID，而不是修改原件身份。新菜单须将领取与材料消耗一并接入事务包装。
