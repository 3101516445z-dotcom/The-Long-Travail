# 喜欢的心情绑定与槲寄生生命周期

范围为喜欢的心情绑定/运行缓存/死亡清理与槲寄生施加/到期/奖励入口。第三方所有权、完整交易获取及特殊战利品实现需独立验证。

## 喜欢的心情：物品绑定与所有权

物品保存 BoundEntity、BoundOwner、BoundName；名称是绑定时字符串快照，不随目标改名自动更新。新绑定要求目标存活、非玩家、owner(target) 等于操作者 UUID，且实体 ID 不在黑名单。owner 最多沿 OwnableEntity 链追 16 步并防 UUID 循环；实体所有者不可解析时可返回其 owner UUID。

已有绑定时，对同一目标交互清除，对其他目标提示已绑定，不直接换绑。潜行使用直接清除三个键。bind 的已有绑定分支和潜行清除没有额外 ownerAllowed 校验；ownerAllowed 约束的是装备/有效查询，不应笼统描述为“所有操作都只有原主人可执行”。客户端交互反馈和服务端写入分开。

实际装备查询选首个非装饰、槽位在 AFFECTION_SLOTS 内且 ownerAllowed 的物品；没有 BoundOwner 的旧物品也允许通过该项检查。装备和卸下 false 分支重置玩家运行缓存，不删除绑定 NBT。

## 运行资格与效果消费

CHECKS 是玩家弱键，保存目标 UUID、实体对象、堆叠对象、检查时间和归属/黑名单结果；ACTIVE 将目标 UUID 映射到玩家 UUID。target 每次先对装备物品执行死亡账本 clean，并检查玩家存活/非旁观、绑定存在、目标能从玩家当前 ServerLevel 解析且存活。

实体或堆叠引用改变、目标 UUID 改变、或距上次检查至少 20 个 gameTime 时，重新检查归属与黑名单。范围每次查询检查，而非随缓存延迟；归属/黑名单结果则可能沿用这段缓存。目标必须在同世界已加载，代码不为绑定强制加载目标。

满足资格和 range 后设置 ACTIVE；超范围只撤销对应 ACTIVE 项。master 取得在线玩家后再次调用 target，并要求返回同一实体实例，不只信任反向表。

FloralCombat 使用对方损失生命比例 `clamp(1-health/max(0.001,maxHealth),0,1)` 计算双方输出加成和减伤；FloralEvents 将绑定目标损血比例用于玩家移速加成。实现是各自效果计算，没有将一方受到的伤害转移给另一方的调用。攻击责任解析 attacker 可沿 Projectile 或 OwnableEntity 链追到 ServerPlayer，同样有 16 步和循环限制；它与绑定 owner 解析不是同一个函数。

## 死亡确认与卸载区别

FloralEvents 在 LivingDeathEvent 暂存事件，服务器 END tick 再要求事件未取消且目标已死亡，才调用 AffectionDeaths.died。已观察目标会从 Watched 移入 Dead，并标脏保存；在线玩家背包、末影箱和 Curios 中对应绑定会清除。

未在这些容器扫描到的物品依靠后续装备查询 clean，或物品 inventoryTick 每 20 个实体 tick 清理。不是死亡瞬间全世界所有容器的同步扫描。watch 会加入 Watched 并移除同 UUID 的 Dead 标记；clean 删除物品绑定，但不从 Dead 中移除 UUID。

EntityLeaveLevel 只调用 forget 释放相关 CHECKS/ACTIVE；登出 reset，停服 resetAll。卸载、跨维度、离线、超范围不能等同死亡，也不能据此删除物品绑定。物品 NBT 与 SavedData 是持久化事实，CHECKS/ACTIVE 是运行缓存。

## 槲寄生：施加、叠加与同步

EntityInteract 将 PartEntity 解析为父实体。玩家目标明确 FAIL；死亡、旁观、盔甲架返回 PASS；客户端合格目标返回 SUCCESS，服务端实际处理。

有效等级取当前效果 amplifier+1 并限制到 MAX_LEVEL。每次施加等级加一至上限；即使满级仍追加 durationSeconds 对应时长。旧无限效果保留 -1，否则以 long 累加并封顶 Integer.MAX_VALUE。

先 addEffect；拒绝则提示 FAIL、不消耗物品。取得实际效果后强制写入新等级/时长、清 hiddenEffect，立即同步移速并发送原版效果更新包；非创造玩家最后消耗一个物品。addEffect 接受但查不到实际效果时也返回 FAIL，源码没有额外事务回滚。

攻击加成为等级×damageBonusPerLevel；减伤为 min(1,等级×damageReductionPerLevel)。移速用固定 UUID 的 MULTIPLY_TOTAL 临时属性，施加后和每个服务端 LivingTick 对账。公共 CombatContext 决定具体伤害路径是否消费这些值，不能从 Mistletoe.bonus/reduction 单独推导所有伤害都适用。

## 到期快照与结算

MobEffectEvent.Expired 仅为匹配效果、存活服务端实体建立 PENDING 弱键记录，putIfAbsent 保存首次到期的等级、最大生命、战利品表 ID 和位置。它不在效果列表遍历期间直接造成伤害。普通移除效果没有在此注册等价结算入口。

MistletoeExpiryMixin 包裹 tickEffects：原调用抛 RuntimeException 或 Error 时 abort 并原样抛出；正常返回才 afterEffects。afterEffects 先移除记录，目标仍活且在 ServerLevel 才继续；使用当前世界和快照位置、最大生命及等级。此方法没有再次检查是否已获得新的槲寄生效果。

伤害为快照最大生命×等级×expiryDamagePerLevel；奖励先按 min(1,等级×lootChancePerLevel) 抽取一次。伤害使用 magic，通过 SETTLING 作用域临时让该实体的槲寄生减伤返回 0，finally 恢复旧值。其他防御与事件仍走 hurt，不能把它写成无条件真伤。

奖励不要求到期伤害成功或杀死目标；只要抽中、表 ID 非空且 doMobLoot 开启，就收集奖励。若 hurt 自身抛异常，后续奖励不会执行。待结算记录已移除，不会自动重试。

## 奖励不是原版随机掉落

LootItemCollector 解析确切原版类型 LootItem、LootTableReference、AlternativesEntry、SequentialEntry、EntryGroup；忽略 AIR，按 Item 去重。它遍历结构而不执行原版条件、权重、数量/NBT 函数，也不调用第三方条目展开；未知类型记 skipped。

限制为 128 种物品、4096 节点、64 个表、深度 16。缓存按 LootDataManager 弱键、每个 Cache 最多 256 个根表，核对依赖 LootTable 对象身份；非冻结表不缓存。Mistletoe 消费 result.items，为每种物品生成一个默认堆叠，使用快照位置和默认拾取延迟；没有依据 limited/skipped 阻止部分结果。

addFreshEntity 的 false 返回未单独补偿；生成过程 RuntimeException 记录警告、不重试，先前已生成的物品不回滚。因此奖励不保证覆盖完整原版掉落表，也不具备失败原子性。获取交易迁移仍是独立入口，本章不以到期奖励核对替代交易验收。
