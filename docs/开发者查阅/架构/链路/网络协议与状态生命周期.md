# 网络协议与状态生命周期

说明 [TravailNetwork](../../../../src/main/java/com/thelongtravail/network/TravailNetwork.java) 的 21 个注册项、载荷、接收入口与状态生命周期。

## 注册、方向与线程

当前源码只有一个 SimpleChannel 注册入口：`the_long_travail:main`，协议字符串 `23`，两侧精确匹配。编号 0–20 各一个注册项，17 个 PLAY_TO_CLIENT（下文 S→C），4 个 PLAY_TO_SERVER（C→S）。消息以显式编号注册，下表按编号排列。

所有处理器均用 context.enqueueWork 执行状态更新/业务调用，并 setPacketHandled(true)。编解码在入队前完成；handled 标记消息处理状态，连接、实例和玩法资格由各处理器检查。多数公共包通过默认空 receiver 在客户端装配后接入表现层，Journey、TooltipConfig 和 Rain 状态有直接接收路径。

## 完整消息表

字段按写入顺序列出。V=VarInt，B=boolean，L=long，D=double，F=float，RL=ResourceLocation，U=UUID；列表包含长度前缀，枚举使用 FriendlyByteBuf 的枚举编解码。接收状态规则见下一节。

| 1 | TravailNetwork.JourneyPacket | S→C | count V、revealed V | JourneySync.accept |

## 客户端状态归属、身份与清理

| ID | 接收与清理规则 |
|---|---|
| 0 | [TooltipConfigCodec](../../../../src/main/java/com/thelongtravail/network/TooltipConfigCodec.java) 限制 512 数值、32 池、每池 2048 条、总计 8192 条及 1 MiB 载荷，拒绝重复键、非有限值和尾随字节。TooltipConfigSync 接收不可变副本，清显示名缓存并增加 revision；退出重置。包不含玩家/维度身份 |
| 1 | JourneySync 将 count 限制为非负、revealed 与 63 按位与；退出重置。包不含实体身份 |
| 2 | [EffectSounds](../../../../src/main/java/com/thelongtravail/compat/sounds/EffectSounds.java) 绑定当前 player/level，改变时清策略和计数；RESET 清策略，DIAGNOSE 开启临时诊断，其他通知交策略按 serial/batch 处理；退出清理。载荷无玩家身份，绑定的是执行时客户端对象 |
| 3 | [DiaryActionSounds](../../../../src/main/java/com/thelongtravail/client/DiaryActionSounds.java) 要求当前玩家/世界；延迟音效记录对象引用，切换对象丢弃，队列最多 16 项；退出清理 |
| 4 | [VisualDeprivationClient](../../../../src/main/java/com/thelongtravail/client/VisualDeprivationClient.java) 的 progress 要求现有 owner/level 相同且存活；完整 accept 绑定执行时对象，变化/死亡重置；退出重置。包不含连接或实体身份 |
| 5 | RainPacket 直接覆盖客户端状态及提示列表，接收时不核对 playerId 是否当前实体；RainClient 退出清空状态/提示。playerId 是载荷字段，不能等同完整身份校验 |
| 7 / 15 | RainClient / BoundlessClient 要求有玩家且相应消息配置启用，再显示提示；不建立持久化技能授权 |
| 8 | 接收时取当前玩家，remaining<=0 删除计时，否则使用客户端 tickCount 建立截止时间；退出置零。包不含原玩家身份 |
| 10 | BoundlessClient 设置 dreaming，cooldown 限制为非负，退出清状态和已消费按键；包不含实体/维度身份 |
| 11 | 解码限制场域和每场 allies 各 4096、中心有限、半径有限且 0<r<=128；接收先替换维度/快照，查询时再要求世界维度相符，退出清理。不是接收时拒绝所有异维度包 |
| 12 | [LanternLightingClient](../../../../src/main/java/com/thelongtravail/client/LanternLightingClient.java) 按 UUID 缓存维度及接收时间，active=false 按 UUID 移除；显示时过滤维度，非暂停状态超过 10 秒清过期状态，退出清缓存。不是按实体 ID 验证 |
| 13 | UnderworldClient 以 available 设置或清 Death UUID，有死亡界面时重建按钮，退出清空。客户端资格只是展示，真正请求由服务端复核 |
| 16 | 解码拒绝非有限坐标，TimeStopCue 要求当前维度匹配；提示粒子集合随 TimeStopClient.clear 清理 |
| 17 | 当前维度、实体 ID+UUID、非玩家 LivingEntity、租约共同约束；回执按世界保存、过期/卸载清理。完整边界见 [终结存储清理与实例保护](终结存储清理与实例保护.md) |
| 18 | [PrinceFlightClient](../../../../src/main/java/com/thelongtravail/client/PrinceFlightClient.java) 先核对当前连接就是原 source；PrinceFlightPermission 再核对存活、ID、UUID、维度，绑定对象变化时清授权，退出清理。同步的是飞行权限，不是客户端当前飞行状态 |
| 20 | handler 将 0–2 以外的类型归零，再交给客户端装配的 receiver；AbundanceUseClient 保存 selectedMode，退出归零。载荷没有玩家、维度或连接身份；登录、重生、跨维度和切换类型由服务端重新同步 |

公共退出入口在 [TravailClientEvents](../../../../src/main/java/com/thelongtravail/client/TravailClientEvents.java)，各主题还具有自己的退出订阅。各包的退出清理与连接身份检查分别列在表中。

## 客户端请求的服务端复核

| ID | 传输层到业务层 | 重复/旧请求边界 |
|---|---|---|
| 6 | 捕获原 sender 和 Connection；执行时检查连接有效、玩家未移除、listener/connection.player/在线列表仍指向该实例，再调用 [RainEvents.cast](../../../../src/main/java/com/thelongtravail/abyss/RainEvents.java) | 业务检查技能开关、存活、非旁观、菜单、装备、主世界、冷却与重复天气策略；同玩家同游戏 tick 有 castTick 去重。该业务入口没有额外的冻结校验 |
| 9 | 与 6 相同的原连接/玩家实例复核，再调用 [DreamState.cast](../../../../src/main/java/com/thelongtravail/boundless/DreamState.java) | 先检查时停；已有梦境进入 finish，否则检查存活、旁观、装备、菜单和冷却。不是与雨请求共用相同去重策略 |
| 14 | 入队后读取 ctx.getSender，非空则调用 [BookRevival.request](../../../../src/main/java/com/thelongtravail/underworld/BookRevival.java)；没有复制 6/9 的整套连接实例检查 | 要求玩家已死、存在 Ready 记录、Death UUID 相同、没有已有搜索、消耗资格允许且维度可用。搜索后复活仍复核当前记录和资格；旧 Death UUID 不因按钮仍存在而有效 |
| 19 | 入队后读取 context.getSender，非空则调用 LiquefiedAbundance.cancel | 移除该玩家当前会话；仅当正在使用的物品引用等于会话物品时停止使用。空会话无操作，包没有会话编号，也未执行 6/9 的原连接与实例复核 |

四种请求均从网络上下文取得发送者。取消包只触发会话取消；类型切换和药水抽取由服务端使用流程执行。

## 发送范围与维护

多数状态由 PLAYER 定向发送。Lantern 支持 TRACKING_ENTITY_AND_SELF 及指定 viewer；TimeStop 由 TimeStopSync 按玩家筛选并比较快照；TimeStopCue 发送给同世界距释放者 32 格内玩家；ExecutionTermination 遍历同 ServerLevel 玩家并检查远端通道存在。

修改字段/枚举顺序或编号要同时检查 encode/decode、注册方向、接收装配、发送方和版本匹配；新增状态还须明确退出、重生、换维度和旧连接处理。此表手工对照当前源码，索引指纹检查能提示 Java 变化，但不会自动证明协议表语义仍一致。

回归关注点：编解码往返、畸形载荷、重复请求、断线排队、重生换实例、跨维度乱序，以及旧取消请求与新会话相遇。执行结果见 [验证状态](../维护/当前状态与验收边界.md)。
