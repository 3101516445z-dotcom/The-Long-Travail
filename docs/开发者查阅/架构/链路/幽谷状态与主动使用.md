# 幽谷状态与主动使用

覆盖死告天使玩家触发状态、磷叶石属性/受击恢复、地下丝绒使用提交。终结底层继续复用已有章节，女仆完整链与第三方战利品需独立验证。

## 死告天使：触发机会不是持久化冷却

有效玩家状态要求存活、非旁观、实际日记与非装饰 head 槽死告天使。State 保存 witness 和 armed；见证值变化会 forget 旧状态及其请求，再建立新对象。未见证分支并未另外查询恶意标记。

[CombatConsequences](../../../../src/main/java/com/thelongtravail/helper/CombatConsequences.java) 的 received/confirmed 分别连接 received 和 damageDealt；公共伤害确认时序见 [伤害确认与重放](伤害确认与重放.md)。received 排除正在执行终结、没有来源实体和自伤，非见证状态置 armed=true；多次受击不会累积多个机会。

确认输出时排除正在终结、自伤、旁观受害者及不允许的玩家 PVP。恶意分支要求 armed，然后先置 false 再抽一次 MALICE 概率。见证分支用一个随机数在目标/自身/未触发三种结果中选择，分母为 max(1,TARGET+SELF)，概率和超过 1 时按总和归一化。

目标已因原攻击死亡也先消耗机会并抽取；结果非零才入 REQUESTS。请求保存玩家对象、目标 UUID、原 State 对象、自身反噬标志和维度。没有物品消耗、持久化 armed 或时间冷却字段，不能把一次性机会写成固定秒数冷却。

服务器 END tick 的 drain 以入口队列长度为本批次数，先进先出；复核服务器、断线、维度及 state(player) 是否仍为原对象。按 UUID 从当前世界重新找目标，或选择玩家自身；只有存活未移除实体才 execute。队列保存目标 UUID，不能声称持有目标旧实例保护；旧实例终结保护属于下游执行器。

forget 删除状态及该玩家排队请求；玩家 END tick 复核装备，登出/换维度/克隆旧玩家、旅程重置及日记依赖清理都有相关入口。停服清表和队列。请求取出后失效直接丢弃，不返还恶意机会；本层没有固定容量上限或跨 tick 的硬处理配额。

## 磷叶石：属性与受伤倍率分离

玩家 phase 要求存活、非旁观、非装饰 curio 槽物品，再查幽谷见证优先、恶意其次；非玩家委托 MaidAccessories。属性金额按阶段读取，phase=0 时为 0。

排除集为配置 EXCLUDED_ATTRIBUTES 与 [ArsNouveauAttributeRules](../../../../src/main/java/com/thelongtravail/compat/arsnouveau/ArsNouveauAttributeRules.java) 提供的固定属性排除项的并集，配置列表变化时重建不可变快照。APPLIED 是弱键，按阶段、金额和排除集的值比较；发生变化，或有效阶段每 20 个实体 tick，调用 AttributeModifierSet.reconcile。

该重载遍历注册属性，以来源 `the_long_travail:phosphophyllite` 添加 MULTIPLY_TOTAL 临时修饰符，跳过排除项和实体没有的属性。失效时对账撤销本来源；最大生命下降时公共基础限制当前生命到新上限。停服清缓存与重入集合，不逐实体遍历清理。PhosphophylliteItem.onUnequip 在服务端立即调用 tick，另有玩家 END tick 与依赖清理路径。

`damageBonus` 实际由 [CombatRules](../../../../src/main/java/com/thelongtravail/helper/CombatRules.java) 对 **受害者** 调用，表示承伤倍率部分，不应仅凭函数名写成攻击者输出加成。它还受 PHOSPHOPHYLLITE_DAMAGE 模式规则控制，与属性金额配置是独立支路。駅移速在 Player.getSpeed 另乘倍率，二者没有“属性互相转换”操作。

见证 received 以实体身份集合 HEALING 防重入，按 healChance 抽取后，以当前最大生命×healFraction 调用 OverflowHealing；finally 移除重入标志。公共 CombatContext 根据 ReceivedMalice 与受击触发模式决定是否调用，不是任意 hurt 调用都无条件抽一次。

[OverflowHealingMixin](../../../../src/main/java/com/thelongtravail/mixin/OverflowHealingMixin.java) 为指定目标领取一次治疗请求，在实际 heal 路径记录溢出；正常返回后仍存活且溢出>0 才加吸收，上限 Float.MAX_VALUE。治疗仍受原事件处理，不按请求金额直接无条件赠送吸收；异常时恢复作用域，不保证补发。

## 地下丝绒：先生成，再消耗与交付

物品 use 先检查物品冷却，服务端协调器再次检查冷却、旁观、时停；基础使用不要求日记。先按 oreChance 选择矿石或锭分支，TagItemSampler 合并 forge 标签与有效额外 ID，去重并去掉 AIR/null，均匀选一种，基础数量固定 8。所选池为空则失败，没有自动改抽另一池。

基础候选成功后获取 TravailStateApi.snapshot。恶意条件成立时，用单次抽取在废弃矿井、远古城市、无额外奖励之间选择，分母 max(1,mine+city)。构造 CHEST 上下文，原点为玩家位置、THIS_ENTITY 为玩家、luck=0；矿井请求 4 次、古城 2 次，每次最终数量固定 1，排除地下丝绒自身。

WeightedLootSampler 处理候选权重、条件和函数，与槲寄生使用的静态 LootItemCollector 不同。每次抽取最多 32 次候选尝试；某轮不能产生合格单堆叠时返回 complete=false。协调器对 skipped 警告但允许 complete=true 的结果，complete=false 或采样 RuntimeException 则整次使用失败；不把部分生成列表交付。

| 顺序 | 当前行为与边界 |
|---|---|
| 生成阶段失败 | 提示失败；尚未 shrink 或设置冷却，已消耗随机数不恢复 |
| 生成阶段完成 | 非创造玩家 shrink(1)；设置向上取整的 cooldownTicks |
| 发放 | 逐堆叠 ItemDelivery.give，按最大堆叠拆分、插主背包、余量 player.drop |
| 见证奖励 | 发放循环后，快照 hasWitness 成立则增加 15 个经验等级 |

恶意与见证分别调用快照查询，不应在文档中自行把两个 if 改成统一 else。发放在消耗之后：ItemDelivery 没有持久化返还队列，不验证 player.drop 成功结果，也没有跨多件奖励的回滚。故“生成失败不消耗”不能扩大为“任何发放失败都不消耗”；发放异常还可能阻止后续经验奖励。
