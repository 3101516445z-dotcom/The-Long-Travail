# 日记主题与阶段交叉复核

A07-17 静态核对日期：2026-10-24。范围为六主题日记效果、阶段变更后的运行维护，以及无穷花阶段与伤害重放。运行验收 NOT_RUN；空间到访、旅程生成和第三方兼容仍分别引用已有专项。

## 基础状态与玩法条件

[旅程与主题状态](../模块/旅程与主题状态.md) 定义见证读取、身份与写入基础；[TravailEvents](../../../../src/main/java/com/thelongtravail/event/TravailEvents.java) 负责事件协调，[TravailEffectActions](../../../../src/main/java/com/thelongtravail/event/TravailEffectActions.java) 执行药效、受击和攻击效果，[TravailPlayerMaintenance](../../../../src/main/java/com/thelongtravail/event/TravailPlayerMaintenance.java) 负责经验、额外槽位及旧飞行速度记录迁移。它们属于协调层，不是脱离 Minecraft 的通用算法。

无日记时 TravailStateApi 返回 INACTIVE；有日记但没有该主题有效见证时按 MALICE 读取。见证包含自然完成、来源授予与调试覆盖，不应只检查剩余探索列表。具体物品还需自己的装备、环境或冷却条件，不能把 hasWitness 当作“该主题所有效果当前都在生效”。

[ModeEffectRules](../../../../src/main/java/com/thelongtravail/config/ModeEffectRules.java) 的 DIARY 规则控制日记恶意是否作用于创造/旁观者，默认 false；它不是所有物品和所有见证效果的总开关。磷叶石承伤、终结、星之声冻结、花朵负面效果等有独立规则。

## 六主题日记规则对照

| 主题 | 未见证的日记效果 | 见证后的日记效果 | 关键入口与边界 |
|---|---|---|---|
| 繁茂 | 治疗量乘减益系数；生命严格高于配置最大生命比例时增加承伤 | 按玩家累计发现群系数计算治疗加成并封顶 | onHeal、CombatRules.internalAmount；群系历史属于 PlayerJourneyData，不是无穷花物品 |
| 归墟 | 挖掘减速、接触流体的周期伤害、四类环境伤害倍率 | 四类环境伤害免疫及流体环境概率保护 | 四类为 in_wall/cramming/drown/freeze；CombatContext 先考虑駅免疫及回退配置，见 [归墟战斗与药效](归墟战斗与药效.md) |
| 穷遐 | 受击时概率清全部增益，否则清一个；成功攻击另按概率/冷却清一个 | 周期净化，剩余操作额度抽取增益；新加入有益效果提高等级 | EffectActions、CleanseRotation、IncomingEffectLevels；黑名单与等级上限依赖 RuntimePools |
| 幽谷 | 受击概率视野剥夺；成功攻击概率僵直 | 成功攻击冷却内发放速度和随机增益；拒绝/清除黑暗与失明 | 视野剥夺/僵直有独立状态，不等于原版黑暗/失明；攻击附加效果受自动药效预算 |
| 冥府 | 输出伤害减益、经验等级上限 | 钓鱼概率生成实体或额外物品奖励 | CombatRules、Maintenance、TravailRewards；书的苏生及见证授予另见复活专项 |
| 无垠 | 高度阈值以上速度惩罚；飞行攻击输出限制 | 额外 Curios 槽位；周期尝试击杀附近幻翼并发奖励 | AltitudePenalty、CombatContext、Maintenance、TravailRewards；不是小王子、伊卡洛斯或星之声的替代实现 |

[CombatRules](../../../../src/main/java/com/thelongtravail/helper/CombatRules.java) 的繁茂/归墟承伤与冥府输出检查 DIARY 适用条件，玫瑰伤害有独立旁路。无垠飞行攻击对弹射物读取创建时写入的 LongTravailFlyingProjectile，对其他来源读取当前 abilities.flying 或 isFallFlying；不能用命中时是否落地统一判断。

[IncomingEffectLevels](../../../../src/main/java/com/thelongtravail/data/IncomingEffectLevels.java) 对服务端有益效果检查穷遐见证和等级黑名单，与午夜拉菲贡献合并，再按配置上限处理；结果不降低原等级，槲寄生效果直接排除。完整药效合并仍应沿已有药效专项和 Mixin 检查。

冥府经验维护在等级达到上限时将等级钳制、进度归零并重算 totalExperience；正经验/等级事件在已达上限时置零，tick 再处理越界。无垠当前速度惩罚由 AltitudePenalty 读取时计算；Maintenance.updateAltitudePenalty 的实际工作是迁移可确认来源的旧能力速度记录，不是每 tick 重写飞行速度。

## 触发时序、预算与奖励

[CombatContext](../../../../src/main/java/com/thelongtravail/helper/CombatContext.java) 对成功攻击以有限生命或吸收值下降确认，同一上下文只确认一次。finish 的日记成功攻击要求 damageConfirmed、非玫瑰、玩家攻击者且非自身；处决、重放、堂吉诃德次生攻击、见切反伤和洛伦兹次生路径提前分流。不能在普通事件中再调用一遍日记成功攻击。

受击恶意通过 [ReceivedMalice](../../../../src/main/java/com/thelongtravail/helper/ReceivedMalice.java) 与 [ReceivedHitGate](../../../../src/main/java/com/thelongtravail/common/ReceivedHitGate.java) 控制排除伤害类型和按实体冷却。配置 ATTACK_ATTEMPT 在攻击尝试阶段触发；HEALTH_LOSS 在 finish 读取 committed，仅损失吸收值不等于生命损失。免疫与 skipReceivedPenalty 影响是否进入，详见 [伤害确认与重放](伤害确认与重放.md)。这与星之声 received 是不同的调用与间隔机制。

穷遐攻击净化只有随机命中后才写 AttackCleanseCooldown，并用线程内 UUID 集合阻止重入；幽谷见证先写 ValleyWitnessCooldown，再尝试发放速度和随机增益，预算不足不会回退这次冷却。这两个截止时间在日记 LongTravail 标签中，不是玩家星之声的倒计时键。

[AutomaticEffectBudget](../../../../src/main/java/com/thelongtravail/data/AutomaticEffectBudget.java) 为穷遐/幽谷自动操作共用预算，拒绝或取消的尝试也可能消耗额度，超额跳过而不排队。不要将配置的操作数描述为每轮必定成功取得的效果数。EffectActions.secondsToTicks 使用四舍五入并至少 1 tick；它与星之声配置向上取整、允许零的换算不同。

[TravailRewards](../../../../src/main/java/com/thelongtravail/event/TravailRewards.java) 的冥府钓鱼在实体和物品概率总和大于 1 时归一化，以一次随机数择一分支；这是日记见证奖励，与 [获取表](获取配方与展示一致性.md) 中的共享战利品和完美流体注入分开。物品走 RewardDelivery 预留，实体分支独立创建入世，不保证生成成功。幻翼按范围、存活、尝试数和队列预留限制执行，造成 Float.MAX_VALUE 玩家来源伤害后确认死亡才提交奖励；不是绕过所有模组的无条件删除。

## 阶段切换与生命周期

| 入口 | 核对到的维护行为 |
|---|---|
| 正常 LivingTick | 先更新视野剥夺/僵直；每 20 tick 更新旅程查询；有日记时初始化并校正维护项 |
| 无日记 | EffectChanges.unequipped、清高度缓存、迁移旧飞速；每 20 tick 移除额外槽位，随后返回 |
| onJourneyChanged | 按查询策略失效查询/路引；幽谷切换或重置清 AzraelState；穷遐清 CleanseRotation；无垠清高度缓存并重算槽位/速度维护 |
| onDiaryReset | 清运行缓存、视野剥夺/僵直，更新槽位和高度维护并同步旅程 |
| 死亡、重生、换维度 | 按入口 resetRuntime；死亡监听没有在这里确认最终死亡是否被其他监听器取消，不能与书的 accepted 死亡提交等同 |
| 登出 | 清连接相关运行缓存、暂停路引返还；不按“登出清理”直接删除持久化诅咒截止时间 |
| 登录、Clone | 登录重发状态/旅程和配置，维护槽位；Clone 复制玩家旅程数据，日记与其他专项的 Clone 另有入口 |

onJourneyChanged 不等于 onDiaryReset，也不是清除全模组所有冷却。星之声整数、书身份、无穷花队列等均须查各自生命周期；不要为了统一清理而增加原实现没有的重置。

## 无穷花的阶段矩阵

[EverlastingFlower](../../../../src/main/java/com/thelongtravail/flourishing/EverlastingFlower.java) 的 equipped 要求存活且非旁观者；玩家取非装饰 Curios 物品，女仆走适配。phase 对服务端玩家要求日记：无装备/无日记为 0，未见证为 1，繁茂见证为 2。

| 能力 | 当前条件 | 是否额外检查 flower_biomes |
|---|---|---|
| 移速加成 | phase=1，update 对固定 UUID 属性对账 | 是 |
| 减伤 | phase=1，公共承伤管线调用 reduction | 是；公共管线另有伤害旁路 |
| 输出增伤 | phase=2，公共输出汇总调用 bonus | 是 |
| 成功攻击概率抗性 | phase=1，非重放；现有效果不存在或等级不高于配置等级才写入 | 否 |
| 追加伤害首轮入队 | phase=2，有限正数伤害、概率命中；公共调用排除玫瑰与 THORNS | 否 |
| 追加链继续 | 执行时策略仍 phase=2，成功确认后再次抽取 | 否 |
| 催生提交 | 有效装备、全局 GROWTH 与物品 growthEnabled | update 本身不检查 phase 或群系；实际任务仍受 GrowthScheduler 约束 |

催生开关、范围、预算与卸下处理见 [花朵组合与成长调度](花朵组合与成长调度.md)。不能将“取得见证”直接写成开启催生的必要条件，也不能将催生开关视作战斗加成开关。

[DamageReplay](../../../../src/main/java/com/thelongtravail/combat/DamageReplay.java) 保留每服务器 END tick 只取队首一项、FIFO、最多 4096 待执行任务；满队列记录丢弃，不追赶或批量爆发。任务保存伤害数值、来源与实体弱引用，至少下一 tick 才可执行；即使队首已失效，本 tick 也不继续抽取下一项。

执行时复核存活、原世界、UUID 对应实例、策略阶段和玩家目标伤害许可。临时清受伤无敌时间，finally 恢复状态；只有未取消、确认造成伤害、目标仍存活且策略允许时才按概率续链，续链沿用原任务 amount。重放上下文只记录自己的 confirmed，提前退出普通后果，避免重新触发日记攻击效果和无穷花首轮入队。unequipped 调用 cancel 删除该来源旧任务并禁止当前帧续链，已发生伤害不回滚；阶段失效也会在策略复核时阻止执行。跨维度、换实例或死亡不能继续旧实例任务。

## 维护与验收边界

新增主题效果先决定状态所有者（日记、玩家持久数据、运行缓存或调度任务），再明确阶段、ModeEffectRules、装备与环境条件。成功攻击效果接公共确认；受击效果明确 ATTACK_ATTEMPT/HEALTH_LOSS；阶段改变只失效有关缓存，避免以整本重置替代主题切换。

本轮未重做空间搜索、所有第三方药效合并、全部玩法兼容和真实飞行/客户端表现。待运行用例 NOT_RUN：六主题无日记/恶意/见证/强制覆盖；创造与旁观者开关；吸收伤害和免疫后的受击；自动预算耗尽；经验越级；弹射物起飞/落地；无穷花移出群系、卸下、阶段切换、重放队满/失效队首及跨维度；死亡被取消后的状态与重新登录。
