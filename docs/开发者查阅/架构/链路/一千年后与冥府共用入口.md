# 一千年后与冥府共用入口

范围为一千年后的玩家装备、凋零加成、攻击类型替换，以及与死者之书共享的资格和账本入口。复活事务、墓碑扫描沿用已有专项，女仆生命周期见 [兼容边界](../维护/兼容边界与A07收尾.md)。

## 基础、协调与扩展

| 层次 | 源码与职责 | 维护边界 |
|---|---|---|
| 装备基础 | [AccessoryEquipRules](../../../../src/main/java/com/thelongtravail/helper/AccessoryEquipRules.java)、[TravailCurios](../../../../src/main/java/com/thelongtravail/helper/TravailCurios.java) | 装备准入通过 hasDiary 检查 travel_diary 功能槽，含恢复作用域；运行查询用 TravailCurios.stack，后者自身是 findFirstCurio |
| 冥府共享查询 | [UnderworldItems](../../../../src/main/java/com/thelongtravail/underworld/UnderworldItems.java) | equipped、consumed、seesUndead、attackType、bonus；查询入口不负责攻击提交或复活执行 |
| 物品入口 | [UnderworldAccessoryItem](../../../../src/main/java/com/thelongtravail/item/UnderworldAccessoryItem.java)、[ModRegistry](../../../../src/main/java/com/thelongtravail/registry/ModRegistry.java) | true 注册 a_thousand_years_later，false 注册 book_of_the_dead；共用单件堆叠和稀有度；戒指允许佩戴，书仅携带生效 |
| 战斗协调 | [CombatContext](../../../../src/main/java/com/thelongtravail/helper/CombatContext.java) | 建立本次伤害的 witherBonus 快照，纳入公共结算；普通加成、次生伤害和重放不可混写 |
| 复活与持久化 | [BookRevival](../../../../src/main/java/com/thelongtravail/underworld/BookRevival.java)、[UnderworldLedger](../../../../src/main/java/com/thelongtravail/underworld/UnderworldLedger.java) | 死亡资格、书身份、极限模式消耗、旅程见证；不是戒指的次数或冷却表 |

## 装备与消费交叉表

| 项目 | 一千年后 | 死者之书 |
|---|---|---|
| 构造参数 / 查询参数 | ring=true | ring=false |
| 生效位置 | ring 功能槽 | CarryingApi 允许的内置携带位置 |
| canEquip | 玩家、非装饰槽、日记、同物品唯一、未被账本判消耗 | 不允许装备 |
| equipped | 日记查询非空后，按精确物品、槽标识、非装饰、未消耗取首件 | 日记查询非空后，通过 CarryingApi.findStack 取首件未消耗的真实书本栈 |
| 主要调用方 | bonus / seesUndead | BookRevival.beginDeath |
| 消耗写入 | 本链无按次扣除、无专属冷却，也不主动创建书身份 | 合格死亡捕获书身份；极限模式苏生在 respawn 返回后 consume(Book UUID) |

戒指的 canEquipFromUse 返回 true，书返回 false；共用的 canRightClickEquip 返回 true，不绕过 canEquip 的最终资格判断。equipped 本身不检查玩家存活、旁观者或阶段，各调用方按自己的需要补充条件。

consumed 要同时满足堆栈含 TravailBookId UUID、玩家是 ServerPlayer、账本 spent 命中。客户端不持有这个权威判断，因此客户端返回 false 不代表服务端已认可资格。该方法没有额外物品类型检查：如果非正常数据把已消费书 UUID 写到戒指上，共用入口也会拒绝它。

账本 reconcile(ItemStack) 会将已消费身份堆栈置零；嵌套 NBT 的 reconcileNode 对书 Count 的处理则明确匹配 book_of_the_dead ID。加载钩子 [UnderworldStackMixin](../../../../src/main/java/com/thelongtravail/mixin/UnderworldStackMixin.java) 仅在当前服务器主线程且主世界存在时进行校正。扫描、墓碑和损坏账本策略见 [墓碑校正与账本生命周期](墓碑校正与账本生命周期.md)。

## 未见证时的凋零加成

玩家路径 bonus(target, source) 要求 source.getEntity() 是 ServerPlayer、有效装备一千年后、日记没有冥府见证；这里没有再显式要求 hasMalice。目标身上没有 WITHER 就返回 0，否则返回 `(amplifier + 1) * WITHER_BONUS`。读取的是目标的效果，不是攻击者的效果；该函数不施加凋零，也不消费效果。

[UnderworldItemsConfig](../../../../src/main/java/com/thelongtravail/config/UnderworldItemsConfig.java) 的 items.thousandYears.witherBonusPerLevel 默认 0.15。因此默认凋零 I 给出 0.15，凋零 II 给出 0.30；这是与其他同类输出比例相加的贡献，不是每个贡献独立相乘。没有仅限近战的条件，伤害归属是否为 ServerPlayer 才是本函数的入口条件。

CombatContext 构造时读取玩家和女仆贡献，处决路径置零。普通 outgoingBonus 纳入 witherBonus；堂吉诃德次生伤害、见切反伤、洛伦兹幻想直击伤害的 outgoingBonus 返回 0，重放按既有重放路径结算；玫瑰伤害保留单独使用 witherBonus 的分支。outputApplied 等标记由公共层控制，物品事件沿用公共结算结果。具体时序见 [战斗结算](../模块/战斗结算.md)、[伤害确认与重放](伤害确认与重放.md)。

## 见证时的亡灵判定范围

seesUndead 对玩家要求有效戒指及冥府见证；attackType 只在攻击者与目标不是同一实例时返回 UNDEAD，否则保留 target.getMobType()。这是一次调用中的类型视角，既不写实体类型，也不改变模型、阵营、AI、治疗规则或所有第三方查询。

| 使用处 | 实际替换点 | 边界 |
|---|---|---|
| [UnderworldAttackMixin](../../../../src/main/java/com/thelongtravail/mixin/UnderworldAttackMixin.java) | Player.attack 内 LivingEntity.getMobType | 影响这条玩家攻击路径中的类型读取；未满足条件调用原操作 |
| [UnderworldEnchantmentMixin](../../../../src/main/java/com/thelongtravail/mixin/UnderworldEnchantmentMixin.java) | DamageEnchantment.doPostAttack 内 getMobType | 仅作用于该调用点，并排除攻击自己 |
| [UnderworldMaidAttackMixin](../../../../src/main/java/com/thelongtravail/compat/mixin/maid/UnderworldMaidAttackMixin.java) | Mob.doHurtTarget 内 getMobType | 仅女仆兼容入口确认 seesUndead 时替换；不是所有 Mob 都获得效果 |
| [SwordLanternState](../../../../src/main/java/com/thelongtravail/valley/SwordLanternState.java) | 当前 pending 目标使用 attackType | 其他候选仍读真实 getMobType；详见 [剑与灯](剑与灯战斗及光源管理.md) |
| [MaidLanternCombat](../../../../src/main/java/com/thelongtravail/compat/maid/MaidLanternCombat.java) | 女仆剑与灯当前目标的 attackType | 通过女仆资格与战斗计算入口查询 |

[MaidAccessories](../../../../src/main/java/com/thelongtravail/compat/maid/MaidAccessories.java) 通过 loaded 门控转入 [MaidAccessoryRules](../../../../src/main/java/com/thelongtravail/compat/maid/MaidAccessoryRules.java) 的资格查询与 [MaidCombatCalculations](../../../../src/main/java/com/thelongtravail/compat/maid/MaidCombatCalculations.java) 的伤害计算。女仆亡灵视角要求 Phase.WITNESS，凋零贡献要求 Phase.MALICE；玩家 bonus 使用的是“没有见证”。主人阶段、饰品同步和第三方女仆攻击见 [兼容边界](../维护/兼容边界与A07收尾.md)。

## 死者之书复活入口与失效

BookRevival.beginDeath 通过 equipped(p, false) 取书，排除旁观者、世界最低建造高度以下、终结来源，以及达到阈值或异常负值/NaN 的 generic_kill 原始输入。阈值默认 10000000；若没有匹配 Hit，则该入口传入 0 供排除判断。复活资格本身不要求四种药效或已取得冥府见证。

见证获取另有条件：匹配本次 Hit、凋零/中毒/虚弱/缓慢同时存在、记录的最终伤害严格大于最大生命、此前没有见证。合格死亡才调用 identity(book)，已存在的 UUID 保留，不存在才生成。死亡确认、Ready、请求 UUID、落点复查与重生顺序见 [死亡确认复活与终结](死亡确认复活与终结.md)。

极限模式苏生在新玩家生成后标记书身份消耗并调用存储校正；普通模式不走此 consume 分支。账本 canRevive 对极限模式要求消耗记录可靠且 UUID 未使用，普通模式不受这两个条件限制。此流程没有完整回滚事务，异常后的处理应按已有复活章定位阶段，不能直接重复消费或强制恢复 Ready。

一千年后没有独立 tick 状态、登出缓存或冷却需要清理；卸下/日记变化通过下次查询生效，已建立的单次伤害上下文保留当时的加成快照。书的持久化记录、待搜索状态和跨重启维护属于 BookRevival/账本职责，不属于 UnderworldAccessoryItem。

## 修改入口

- 修改佩戴资格：同时检查 canEquip 与 equipped；准入、恢复作用域和运行查询不能只改一个入口。
- 修改凋零加成：修改配置/bonus 后核对 CombatContext 的快照、加法汇总和特殊伤害路径，避免重复放大。
- 扩展亡灵视角：为实际攻击调用定位读取点，明确是否排除自身；不要用全局 getMobType 替换扩大作用域。
- 修改书消耗：沿 identity → Death.Book → canRevive → consume → reconcile 核对，复用既有账本和墓碑专项。

回归用例：无日记/装饰槽/重复装备；未见证与见证切换；凋零 I/II/无效果与弹射物归属；攻击自身及剑与灯非当前候选；附魔/第三方攻击；普通和极限模式死亡、重复请求、同身份书副本、损坏 Spent、重启与墓碑恢复。获取配方见 [获取、配方与展示一致性](获取配方与展示一致性.md)，女仆链路见 [兼容边界](../维护/兼容边界与A07收尾.md)。
