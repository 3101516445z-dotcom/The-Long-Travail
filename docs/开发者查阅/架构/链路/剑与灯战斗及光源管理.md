# 剑与灯战斗及光源管理

范围为玩家战斗状态、照明开关、状态同步、客户端动态光源与旧灯光方块清理。

## 装备、照明与免疫分开

SwordLanternState.equipped 检查存活、非旁观玩家功能 belt 槽，不检查日记或主题阶段。物品 canEquip 要求非装饰 belt 槽和唯一装备，也没有日记前置。

潜行使用在服务端切换堆叠 `LanternLightDisabled`；启用时移除键，禁用时写 true。LanternSources 的 equipped/held/dropped 才读取开关，战斗 equipped 不读取。因此关闭灯光不会关闭战斗加成或免疫；仅手持或掉落发光也不代表获得 belt 装备的战斗能力。

SwordLanternEvents 在 Applicable LOWEST 拒绝玩家失明、黑暗、反胃；服务器 END tick 对已装备玩家通过 EffectChanges.remove 清除这三类已有效果。没有专属主动攻击技能或秒数冷却字段；这里的时间参数是敌人记忆、脱战和久战阈值。

## 战斗状态与候选

STATES 以玩家 UUID 为键，保存敌人 UUID→最后记录时间、附近实体列表、扫描时间、战斗开始和最后交互时间。update 到达 TIMEOUT 即清 start/last；敌人记忆达到 MEMORY 或不再 eligible 时移除。附近列表每 10 gameTime 刷新；判定半径来自 detectionRadius（默认 64 格，范围 8～64），同时用于包围盒、距离过滤和敌人记录。半径变化时立即刷新缓存，玩家与女仆使用相同配置。

bonus 合并缓存附近列表、当前世界玩家、敌人记忆重新解析实体及本次 pending 目标，按 UUID 去重。即使缓存存在，每次仍检查存活、未移除、非旁观、同世界和距离；它不是每次调用都全量空间搜索。

eligible 还要求可攻击、非友方；玩家敌人排除创造并检查服务器 PVP 与 canHarmPlayer。友方包含双方盟友关系、原版/FTB 队友、自己的所有权实体以及在线队友的所有权实体。敌人除 eligible 外，还须是本次 pending、当前攻击玩家的 Mob 或记忆对象。

| 加成 | 实际条件 |
|---|---|
| 群敌 | 敌人数达到 crowdMinimumEnemies（默认 11，范围 2～64） |
| 亡灵 | 至少一名敌人是亡灵；pending 用 UnderworldItems.attackType，其余用实际 MobType |
| 独行 | 没有范围内的非敌对玩家，也没有自己拥有的非玩家实体；不能等同“没有友军”泛化判断 |
| 久战 | start 有效且 elapsed 严格大于 DURATION |
| 低血 | 当前生命严格低于最大生命×HEALTH，不计吸收 |

五项通过 damageBonus 相加，再由 CombatContext 汇入输出加成。confirmed 的主动伤害与 received 的受击分别 record；record 排除友方、不同世界、范围外、旁观及不合格玩家，但没有与 eligible 完全相同的目标存活/可攻击检查。首次记录设置 start，每次刷新 last 和敌人时间；之后 update 再清失效目标。

卸下后的 tick/bonus 会 forget；死亡事件、登出、换维度 reset，同时清同步状态并发送 inactive。停服清表。状态不持久化；不能将同 UUID map 理解成跨重启战斗记录。

## 玩家装备状态同步

服务器 END tick 对每个玩家执行 State.tick、LanternSync.tick，再处理免疫；同步判定为 LanternSources.equipped。首次、状态变化以及 active 时每 20 个服务器 tick 发送。StartTracking 单独给观察者发送目标当前状态。

LanternPacket 携带维度、玩家 UUID 和 active，不发送位置。客户端位置来自已跟踪玩家实体；held 与掉落光源也不靠这张装备状态表逐帧发送。协议接收装配及连接边界沿用 [网络协议与状态生命周期](网络协议与状态生命周期.md)。

## 客户端光源与清理

ACTIVE 保存玩家状态及 System.nanoTime 接收时间，非暂停时超过 10 秒移除；暂停时刷新时间以免超时。玩家必须存活、非旁观，并满足匹配当前维度的 active 或当前手持启用物品。位置按渲染插值，玩家/女仆高度取实体高度的 0.55，掉落物取 0.5。

实体加入/离开事件维护掉落物和女仆索引；客户端 END tick 筛选掉落灯光，每帧还核对世界及有效性。切换世界时清快照/重建器并从渲染实体重建索引；LoggingOut 清 ACTIVE、实体索引和快照。空世界帧清显示侧缓存，但 ACTIVE 的完整清理由登出路径负责，不能概括成每次换世界都清 ACTIVE。

LanternRebuildScheduler 两次发布至少隔 33,000,000 纳秒；成员集合变化或相对上次发布坐标任一轴移动超过 0.08 才触发更新。触发后按精确 Source 值比较，将变更光源旧/新覆盖分区都标脏。变更数量较少时增量更新快照，否则重建；这是发布节流，不是每帧立即重建世界网格的保证。

[LanternLighting](../../../../src/main/java/com/thelongtravail/client/LanternLighting.java) 取最近光源：3 格内亮度 15，至 12 格线性衰减到 0。merge 只提高 packed light 的方块光低字节，不降低原光照，也不改其余位。多灯不会简单相加变亮；函数没有遮挡射线查询。快照索引和渲染消费入口见 [界面会话与渲染生命周期](界面会话与渲染生命周期.md)。

## 服务端旧灯光方块

LanternLight 注册 invisible、无碰撞、光等级 15 的 lantern_light 方块及 Data。Data 的 Expires 仍读写 NBT，但当前 tick 没有按 expires 延续光源，而是遍历 LOADED 尝试删除已加载的旧方块。

删除先核区块已加载、当前位置 BlockEntity 仍为同一 Data 实例；change 只允许本方块变空气，并用 ThreadLocal Change 精确记录世界、位置、前后 BlockState，finally 恢复嵌套作用域。permitted 提供受控更改判定，不能当成对任意方块的通行许可。

Data.onLoad 加入集合，移除/区块卸载退出；ServerStopping 尝试清理后清集合。未加载区块不会为此强制加载，删除失败也不能宣称所有旧方块必已清空。当前代码没有根据玩家位置持续放置新灯光方块，动态显示来自客户端链路。
