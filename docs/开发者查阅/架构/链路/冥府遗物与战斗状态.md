# 冥府遗物与战斗状态

范围为第六天魔王与万魂幡的装备依赖、属性对账、战斗计算、死亡收魂与终结衔接。一千年后、死者之书和女仆完整生命周期需独立验证。

## 装备资格与依赖失效

Item.canEquip 要求玩家、非装饰槽、实际日记和唯一物品；第六天魔王使用 bracelet，万魂幡使用 charm。UnderworldRelics.phase 对死亡、移除、旁观实体返回 0；玩家查询冥府主题状态，其他实体委托 MaidAccessories。equipped 在 phase=0 时先返回空，因此“拥有物品”不等于遗物当前生效。

玩家查询只取对应槽位的首件非装饰物品；女仆走 relicStack 独立入口。装备/卸下回调和服务端 LivingTick 都调用 refresh，覆盖装备及阶段变化。

DependentAccessories 为两件物品登记日记依赖，依赖失效清理回调同为 refresh。移出与返还的公共三态边界沿用 [装备恢复与依赖返还](装备恢复与依赖返还.md)，本章不另造遗物专属返还队列。

## 属性对账与魂数持久化

魂数存于物品 `the_long_travail:soul_banner` 子标签的 `Souls`。souls 只接受万魂幡物品，将读取值限制到 `[0, capacity]`；读取不写回，因此调低容量不会直接截断存量。addSoul 以有效魂数判断是否满额，满额返回 false，否则写有效值+1。

| 条件 | 本来源提供的 ADDITION 加值 |
|---|---|
| 见证且装备第六天魔王 | OVERLORD = king.overlord |
| 恶意且魂数 n>0 | CRITICAL_CHANCE = n × banner.maliceCriticalPerSoul |
| 见证且魂数 n>0 | CRITICAL_CHANCE = n × banner.witnessCriticalPerSoul |
| 见证且魂数 n>0 | INSIGHT = min(banner.insightCap, n × banner.insightPerSoul) |

只放入正值；未满足条件时期望表为空。来源 ID 为 `the_long_travail:underworld_relics`。APPLIED 是实体弱键到期望属性表的缓存，不是魂数存储。Modifier 是值对象，以值相等比较避免每刻重复重建；期望值变化时对账，非空期望值还每 20 个实体 tick 再核一次。

AttributeModifierSet 按来源生成稳定 UUID，只处理该来源的修饰符，匹配则保留，不匹配则删除/添加 transient modifier。wanted 为空且 APPLIED 无记录时，refresh 提前返回，并非每次都全表清理。死亡事件在存在 APPLIED 记录时主动 clear 并移除缓存；停服这里只清 APPLIED，不遍历实体逐一撤销修饰符。

## 第六天魔王：快照与实际结算

bonus 要求伤害源 getEntity 为有效装备的 LivingEntity 且不是目标：恶意对燃烧目标加 burningBonus；见证在攻击者所在群系带 IS_NETHER 标签，或 IcarusEnvironment.openSky 为 false 时加 environmentBonus。判定是群系标签/露天，不是简单维度名称，也没有继承恶意燃烧加成。

CombatContext 将 relicBonus 与其他输出加成相加；终结、重放、堂吉诃德追加、见切反击、玫瑰伤害路径不采样该加成与吸血堆叠。洛伦兹幻想直击路径另有输出/finish 控制，不能只看 DemonKingCombat 单个函数推导它的最终行为。

恶意减伤要求伤害不带 BYPASSES_INVULNERABILITY、受害者有效装备第六天魔王、来源为另一个 LivingEntity 且 MobType.UNDEAD，乘 `(1 - king.undeadReduction)`。公共 beforeAbsorption 还限制为非终结、非玫瑰、非重放、非穿透、非堂吉诃德追加的相应分支；它不是全部亡灵伤害的全局免疫。

吸血分两步：

1. healingStack 在伤害上下文建立时捕获恶意攻击者当前第六天魔王堆叠，排除自伤与见切反击。
2. recordHealthLoss 对有限生命变化累计 `max(0, max(0,before)-max(0,after))`，排除负血溢出；吸收值损失没有计入 relicHealthLoss。finish 调用 heal 时再次检查攻击者存活、仍为恶意、有效装备堆叠与原对象 **引用相同**，再按 loss × lifesteal 治疗并封顶 Float.MAX_VALUE。

因此同 ID 或相同 NBT 的替换堆叠不自动承接该次吸血；治疗仍经过实体 heal 路径。第三方直接写入生命值的路径需单独核对。

## 万魂幡：捕获、确认、去重

capture 排除玩家、盔甲架、客户端和实体类型命名空间为 dummmmmmy 的目标。它沿 Projectile.getOwner 解析来源，用对象身份集合防循环；最终责任实体必须为非自杀的玩家或女仆，并有有效万魂幡。Claim 保存击杀者实体和当时的万魂幡堆叠对象。

普通 LivingDeathEvent 以受害者对象身份存入 PENDING。已有有效普通记录不随重复事件任意覆盖；旧普通事件已取消时才允许替换。服务器 END tick 先复制并清空待处理表，再执行：

| 步骤 | 边界 |
|---|---|
| 普通死亡确认 | 事件取消或目标仍活着则跳过 |
| COUNTED 去重 | 按实体对象身份记录，不按 UUID 建永久账本 |
| 装备复核 | 当前有效万魂幡必须与 Claim.banner 引用相同；失去阶段或换幡则不收取 |
| 加魂 | 未满容量才写 +1，成功后立即 refresh 属性 |

COUNTED 在装备复核与容量判断之前写入。因此换幡或满额导致未增加，也不会保留这条待处理记录等待重试。活实体的服务端 LivingTick 会移除其 COUNTED 记录，允许同一实例复活后的后续死亡重新计数；停服清 PENDING 和 COUNTED。两张表不持久化，不能当作跨重启恰好一次账本。

## 终结衔接与维护边界

[AzraelExecution](../../../../src/main/java/com/thelongtravail/valley/AzraelExecution.java) 在执行前捕获 soulClaim；无限伤害、generic kill 或直接死亡尝试返回 DEAD 时调用 executed。executed 用 forced 记录替换待处理项，刻末跳过普通死亡事件取消/存活复核，仍经过实例去重、同堆叠与容量检查。不能把“进入终结流程”写成“必定收魂”，更不能把普通移除等同于 DEAD。

完整终结/存储流程继续查 [死亡确认复活与终结](死亡确认复活与终结.md) 和 [终结存储清理与实例保护](终结存储清理与实例保护.md)。

物品名称、魂数展示与说明维护入口见 [语言源说明](../../../../src/main/lang/README.md)；配置位于冥府主题文件。配置或容量变化后的效果由 refresh 重算，不需要修改保存格式来更新属性。
