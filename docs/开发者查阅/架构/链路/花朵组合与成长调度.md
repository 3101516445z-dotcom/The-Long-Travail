# 花朵组合与成长调度

范围为春日一隅花朵组合、玩家花卉效果入口与清理、无穷花催生来源及公共成长调度。喜欢的心情绑定、槲寄生和女仆完整效果链保留独立范围。

## 两条链路与职责

| 层次 | 源码 | 职责 |
|---|---|---|
| 组合数据 | [Flower](../../../../src/main/java/com/thelongtravail/flourishing/Flower.java)、[FlowerData](../../../../src/main/java/com/thelongtravail/flourishing/FlowerData.java) | 有限花卉枚举、ID、标签资格、最多三种组合与效果开关 |
| 配方入口 | [SpringRecipes](../../../../src/main/java/com/thelongtravail/flourishing/SpringRecipes.java) | 单花春日一隅合成、加花、水洗及容器余料 |
| 效果协调 | [FloralEvents](../../../../src/main/java/com/thelongtravail/flourishing/FloralEvents.java) | 玩家周期属性、治疗、效果施加、反击、死亡确认、进食 |
| 战斗与被动计算 | [FloralCombat](../../../../src/main/java/com/thelongtravail/flourishing/FloralCombat.java)、[FloralPassives](../../../../src/main/java/com/thelongtravail/flourishing/FloralPassives.java) | 输出/减伤、固定 UUID 属性、有害效果时长 |
| 催生玩法来源 | [EverlastingFlower](../../../../src/main/java/com/thelongtravail/flourishing/EverlastingFlower.java) | 有效装备及开关复核，提交或移除催生来源 |
| 公共调度基础 | [GrowthScheduler](../../../../src/main/java/com/thelongtravail/growth/GrowthScheduler.java)、[GrowthAdapter](../../../../src/main/java/com/thelongtravail/growth/GrowthAdapter.java) | 扫描、轮转、位置间隔、预算与适配器异常隔离 |

春日一隅不是成长任务的提交者。GrowthScheduler 接受 kind、实体和 Policy，不直接读取春日一隅或主题状态。当前主源码中查到的 submit 调用来自 EverlastingFlower；register 是扩展入口，未查到生产源码中的额外注册调用。

## 春日一隅组合与配方契约

`TravailFlowers` 是堆叠 NBT 字符串列表。read 按保存次序读取、忽略未知 ID 和重复项，最多保留三种；write 去重并截断到三种。parse 接受枚举短 ID 和对应 minecraft:ID，不支持仅靠标签增加任意新花种。

active 额外检查该花的配置 enabled，但前三种位置由有效、不重复的花占用；配置禁用某花不会让第四种花自动递补。Flower.craftable 还要求对应物品属于 spring_flowers 标签，因此合成资格和已有组合是否生效是两层条件。

| 配方路径 | 契约 |
|---|---|
| Crown | 花种可合成且启用后沿用有序配方匹配，输出单花春日一隅 |
| Change 加花 | 恰好一件春日一隅和一种其他输入；花种可合成、启用、未重复且原组合不足三种 |
| Change 水洗 | 春日一隅与水桶，原组合多于一种；只保留第一种，返回空桶 |

assemble 复制春日一隅、数量设为 1，再更新花列表，因此保留其他 NBT。它复核输入结构、数量及重复，但不再次检查 enabled/tag；正常流程依赖 matches。客户端 matches 使用同步展示配置，服务端读取实际配置。新增花种需同时维护枚举、标签/配方、配置和效果消费者，不能只追加标签。

## 装备入口、效果查阅与退出

[FlourishingAccessoryItem](../../../../src/main/java/com/thelongtravail/item/FlourishingAccessoryItem.java) 的 true 分支对应春日一隅。实际查询经 [Affection.equipped](../../../../src/main/java/com/thelongtravail/flourishing/Affection.java) 选择首个非装饰且槽位在 SPRING_SLOTS 内的堆叠；false 分支才处理喜欢的心情的所有者与装备重置。

| 维护目标 | 花种与消费者 |
|---|---|
| 输出加成 | 虞美人、低血红色郁金香、弹射矢车菊、日照向日葵 → FloralCombat.bonus |
| 减伤 | 绒球葱的毒伤识别、蓝花美耳草的摔落、火把花的火焰、低血白色郁金香 → FloralCombat.reduce |
| 周期属性 | 牡丹最大生命、橙色郁金香攻速、兰花游泳、粉红色花簇/向日葵移速 → FloralEvents.tick |
| 其他属性 | 樱花树叶重力、盛开的杜鹃抗击退、盛开的杜鹃树叶韧性、紫颂花触及 → FloralPassives.tick |
| 治疗与进食 | 滨菊周期治疗、粉红色郁金香治疗倍率、瓶子草击杀治疗、蒲公英饥饿/饱和增益 → FloralEvents |
| 施加与时长 | 铃兰中毒、凋零玫瑰凋零、丁香延长指定负面效果、孢子花缩短收到的有害效果 |
| 反击 | 玫瑰丛 → received/roseHit，自定义玫瑰伤害避免常规反复触发 |

此表是代码定位，不替代逐项数值配置。[FlourishingItemsConfig](../../../../src/main/java/com/thelongtravail/config/FlourishingItemsConfig.java) 为效果数值入口。FloralCombat.sunny 当前只检查 isDay 和玩家方块位置 canSeeSky，没有独立的无雨/无雷条件，不能照搬伊卡洛斯的晴天定义。

玩家 END tick 将死亡/旁观玩家的春日一隅视为空，按固定 UUID 对账临时属性；卸下后由后续 tick 删除对应增益。春日一隅没有 onUnequip 立即清空所有 FloralEvents 状态的路径。最大生命增益撤去时，若当前生命超新上限则截至上限。滨菊计数在花种不生效时归零；玫瑰与击杀冷却留在玩家 State，不因重新装备自动重置。

TARGET_COOLDOWNS 以受害实体为弱键，内部按攻击者 UUID+花种区分，清除已到期项后最多 256 项；先记录冷却再调用 addEffect，不因效果未成功施加自动返还冷却。登出删除玩家 State 并重置 Affection；停服清 State、目标冷却、待确认死亡和 Affection 状态。

瓶子草在 LivingDeathEvent 暂存击杀者、治疗比例与事件，到服务器 END tick 再确认事件未取消且目标已死亡；这是延迟确认，不是收到死亡事件就立即治疗。该阶段不重新读取春日一隅治疗比例。

[FloralFoodMixin](../../../../src/main/java/com/thelongtravail/mixin/FloralFoodMixin.java) 接管对应进食路径，蒲公英的小数营养余量保存在玩家 `TravailFoodFraction`，不是春日一隅 NBT；无有效花种/食物属性时回原调用。

[FloralPoisonMixin](../../../../src/main/java/com/thelongtravail/mixin/FloralPoisonMixin.java) 用 ThreadLocal 作用域识别中毒 tick 的 MAGIC 伤害，finally 恢复嵌套状态；绒球葱免疫限定在该中毒作用域。[LivingCombatMixin](../../../../src/main/java/com/thelongtravail/mixin/LivingCombatMixin.java) 的 addEffect 包裹依次衔接玩家延长、女仆延长、午夜拉菲时长和孢子花缩短。孢子花对非瞬时有害效果复制并递归处理隐藏效果链，有限正时长向上取整，无限时长不缩短。

## 无穷花如何提交催生

[EverlastingFlowerItem](../../../../src/main/java/com/thelongtravail/item/EverlastingFlowerItem.java) 潜行使用在服务端写 `TravailGrowth` 开关；未保存开关时由 growthEnabled 读取默认配置/同步值。update 仅在服务端执行：有效装备非空、全局 GROWTH 允许且堆叠开关启用，才 submit；否则 remove。

提交催生不要求繁茂阶段或花卉群系。花卉群系与阶段另用于速度/战斗效果，不应误加到催生条件。LivingTick 对服务端玩家和女仆调用 update；装备回调也更新状态。

unequipped 直接取消的是 DamageReplay 追加链，不直接调用 GrowthScheduler.remove；成长来源由 update 的当前装备检查移除，或心跳过期淘汰。[CurioFlowerRemovalMixin](../../../../src/main/java/com/thelongtravail/mixin/CurioFlowerRemovalMixin.java) 在真实槽位移除/提取后取消旧追加链，覆盖同刻卸下重戴。它不是植物任务回滚器。战斗追加队列仍见 [伤害确认与重放](伤害确认与重放.md)。

## 调度与额度

State 按 MinecraftServer 存储，来源键是 kind+所有者 UUID，持有实体弱引用、Policy、心跳和游标。每次 submit 刷新策略与服务器 tick 心跳；容量已满时拒绝新增，替换不同实例的同键来源也经过容量检查。Policy 验证水平半径 1–32、竖直半径 0–16、间隔 1–1200000。

| 每服务器预算/容量 | 当前值 |
|---|---:|
| 每 END tick 扫描候选坐标 | 2048 |
| 每 END tick attempt 调用 | 128 |
| 每 END tick heavy 调用 | 1 |
| 来源上限 | 1024 |
| recent 位置上限 | 65536 |
| 每 tick recent 清理检查 | 256 |

END tick 删除弱引用失效或心跳差大于 1 的来源，每刻轮换起始来源。每来源扫描额度为 `min(剩余扫描数, max(1, ceil(包围盒格数/interval)))`。游标遍历包围盒坐标，再裁成水平圆形；中心取所有者当前方块位置，移动不会保留旧中心任务。

死亡、移除、冻结或非服务端世界的所有者跳过。坐标扫描先消耗扫描额度，再检查圆形、区块已加载、位置未冻结、随机刻资格和 EXCLUDE。因此额度是工作上界，不是成功催生次数，也不是保证每个位置按 interval 准时执行。

外部适配器按注册顺序选择第一个 supports=true 的实例；无匹配才使用内置适配。内置覆盖作物、树苗、茎、疣、可可、浆果、甘蔗、仙人掌、竹子、海带和两类藤蔓等及 INCLUDE 标签，且仍受随机刻资格与 EXCLUDE 限制。内置树苗标为 heavy，要求周围 16 格区域已加载，其他内置对象要求 1 格；attempt 调用一次 state.randomTick，不保证生长成功，也不强制加载区块。

recent 以世界实例+方块位置为键，多个来源共享同一位置间隔；先执行者的 interval 决定该次截止时间。容量满且位置为新键时跳过。清理每次检查最多 256 项，未到期项移到尾部；没有来源时清空 recent，停服移除整个服务器 State。ADAPTERS 注册表不随该停服事件清除。

## 异常和扩展约束

调用 attempt 前先写 recent 截止时间并扣调用/heavy 额度。RuntimeException 后不回滚这些记录，也不当场重放；同一适配器实例在本 tick 剩余处理中跳过，按实例最多每 60 秒警告一次，下一 tick 可再次参与。

supports 抛异常时跳过当前位置，不立即回退内置适配器；heavy/ready/attempt 异常都进入同一失效处理，但只有已走到 attempt 前的记录步骤才占用调用预算与间隔。异常隔离不是任意 Throwable 捕获。

GrowthAdapter 默认 ready=true，扩展自身负责额外区域加载条件；接口约定一次 attempt 只推进一次生长机会，不得内部无界循环。全局调用数上限不能保证第三方单次回调耗时，也不是整合包 TPS 验收。预算不足降低频率，不补发历史随机刻。

## 回归关注点

回归用例：组合水洗/禁用、属性撤销、死亡取消、嵌套药效、多来源重叠、公平轮转、移动/冻结/卸载、适配器异常与饱和容量均需对应环境验证。
