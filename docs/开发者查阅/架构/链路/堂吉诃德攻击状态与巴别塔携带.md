## 堂吉诃德：快照、确认与追加攻击

玩家有效装备要求存活、非旁观、非装饰 body 槽。LivingEntity 重载将非玩家分派至 MaidAccessories，阶段也是分开查询。

snapshot 排除无攻击者、自伤、未装备、堂吉诃德追加伤害、荆棘和玫瑰伤害。CombatContext 还在终结、重放、洛伦兹幻想虚空及见切反击等路径跳过该快照。

体积默认取目标宽度平方乘高度；sizeOverrides 按实体 ID 使用首个匹配项，仅改计算指标，不改碰撞箱。有效正有限体积的增伤为：

`min(maxBonus, max(0, cbrt(volume / 0.648) - 1) × sizeFactor)`

快照同时记录目标有效最大生命、见证状态，以及恶意阶段下“目标当前生命 >= 攻击者当前生命 × healthRatio”的资格。攻击者生命须正有限，两者当前生命均须有限。体型增伤本身不要求阶段，进入公共 outgoingBonus 合计。

CombatContext 记录生命与吸收值的实际下降，确认后在 finish 调用 DonQuixoteCombat.finish。这里的 recordedDamage 包含吸收损失，不应简化为“只看生命条损失”；训练假人还有独立确认入口。

| 完成分支 | 条件与动作 |
|---|---|
| 共通 | 快照存在、最大生命有效、已记录伤害 > 0、攻击者仍能解析且有效装备 |
| 见证 | 伤害严格大于快照最大生命 × witnessThreshold，调用 State.trigger；trigger 再核当前见证与冷却 |
| 恶意 | 快照 strike 为 true，目标仍存活、未移除、与攻击者同世界，追加快照最大生命 × trueFraction |

恶意追加不在 finish 重新计算生命比或阶段。攻击玩家目标前检查 PVP/女仆伤害许可。追加使用 `don_quixote_strike` 伤害类型，数值须正有限且封顶 Float.MAX_VALUE；finally 恢复原 invulnerableTime 与 lastHurt。

追加类型有绕过护甲、冷却、效果、附魔、抗性和盾牌的 [数据标签](../../../../src/main/resources/data/minecraft/tags/damage_type)。公共战斗桥接为追加类型保留吸收量、抑制重复输出加成、再次快照及常规 confirmed 副作用。它仍调用 target.hurt，不是直接写生命，也不据此保证绕过所有第三方取消。完整公共时序见 [伤害确认与重放](伤害确认与重放.md)。

## 见证防护生命周期

GUARDS 是按 LivingEntity 对象存储的 WeakHashMap，每个实体只有一个 Guard：触发目标 UUID、截至 gameTime、当前维度键、女仆所有者。trigger 在见证且冷却 <= 0 时同时写入防护和冷却；冷却从触发开始，不等防护结束。

reduce 先复核装备、见证、有效期、维度和所有者；失效则删除记录。仅当伤害源 getEntity 的 UUID 等于记录目标，才乘 `(1 - reduction)`，不是全来源减伤。CombatContext 只在非终结、非玫瑰、非重放、非穿透、非堂吉诃德追加的相应分支调用它。

玩家冷却存在 persistentData 的 `TravailDonQuixoteCooldown`，服务端 PlayerTick END 减一，未要求仍装备才减。Guard 不持久化。Clone 复制冷却并移除旧玩家 Guard；登出移除 Guard 并调用 BabelCarrying.forget；换维度移除 Guard。tick 清除装备/阶段/所有者失效的 Guard，时间到期在 reduce 时检查；不能描述为到期 tick 必定立即删表。

非玩家冷却委托 MaidAccessories，forget 只删除 Guard；本章不声称已验证女仆保存或重载。

## 巴别塔携带的三态含义

BabelCarrying 使用 `query(...) != ABSENT`，所以 PRESENT 和 UNKNOWN 都进入携带分支。它不同于 CarryingApi.isCarrying 仅接受 PRESENT 的布尔接口；提供方异常但未找到确定存在时，保护和交易资格仍采用这一保守结果。

内置 inventory/offhand/armor/enderChest/curios 查询受公共区域开关和巴别塔区域开关约束。位置缓存每次验证；有效外部信号保留到当前 tick 与报告 tick 差不超过 2，时间回退或超过窗口时移除。BabelItem.inventoryTick 只有负槽位且 externalInventoryTick 允许时才报告兼容信号，普通背包由直接扫描确认。

提供方抛 RuntimeException 会记录失败、限频警告，继续查其他提供方；若后续确认存在则 PRESENT，否则 UNKNOWN。查询要求服务端游戏线程，死亡或旁观返回 ABSENT。forget 删除玩家信号和位置缓存，不删除物品或执行返还。协议细节继续维护在 [携带 API](../../carrying-api.md)。

## 基础保护、挑衅和 AI 桥接

保护对象必须为 Mob。babel_exclude 优先否决，babel_include 随后允许；否则排除猪灵蛮兵和疣猪兽，接受 NeutralMob、猪灵，或非 Enemy 的动物、村民、傀儡、水生与环境生物。

protects 要求服务端玩家目标、合格生物、该生物未记录玩家挑衅且玩家携带巴别塔，不要求主题阶段。`TravailBabelProvoked` 在生物 persistentData 中记录玩家 UUID；伤害源实体、直接实体依次经 Affection.attacker 解析责任玩家。记录不要求攻击当时携带巴别塔，也没有本类提供的到期清除。

CombatContext 在有限生命/吸收损失记录处登记挑衅，每上下文一次；假人确认入口没有同样调用。损坏的 UUID 数组会被忽略并限频警告，不能把它理解成整份记录被自动修复。

| 桥接 | 作用 |
|---|---|
| [BabelMobMixin](../../../../src/main/java/com/thelongtravail/mixin/BabelMobMixin.java) | setTarget 包裹及字段提交拦截，serverAiStep 清除受保护目标、导航、伤害对象、怒气与 Brain 记忆 |
| [BabelLivingMixin](../../../../src/main/java/com/thelongtravail/mixin/BabelLivingMixin.java) | canAttack、最近伤害对象拦截；构造、读取及 getBrain 绑定所有者 |
| [BabelBrainMixin](../../../../src/main/java/com/thelongtravail/mixin/BabelBrainMixin.java) | 弱引用所有者，拦截记忆写入并在 tick 清理 ATTACK_TARGET/ANGRY_AT/HURT_BY_ENTITY/HURT_BY |
| [BabelTargetingMixin](../../../../src/main/java/com/thelongtravail/mixin/BabelTargetingMixin.java) | 仅战斗目标条件拒绝受保护玩家 |
| [BabelEndermanMixin](../../../../src/main/java/com/thelongtravail/mixin/BabelEndermanMixin.java)、[BabelPiglinMixin](../../../../src/main/java/com/thelongtravail/mixin/BabelPiglinMixin.java) | 末影人注视/目标、猪灵受击/怒气专门桥接 |

这些修改目标与记忆，不等于全局伤害免疫，也不能覆盖未经核对的第三方私有 AI。

## 交易资格、价格恢复与补货

恶意交易要求：服务端玩家、恶意成立、见证不成立、携带、未挑衅该村民。**见证不继承恶意折扣和加速补货**，保留基础保护。

refresh 先移除本模块上次记录的 specialPriceDiff 增量，再根据当前资格计算第一项材料价格：当前价格 × priceFactor，向上取整且至少 1。增量按 MerchantOffer 对象身份保存，第二项材料不在此折扣计算中。巴别塔、槲寄生、考古固定交易跳过；不将刷新写成反复叠乘。

[BabelVillagerMixin](../../../../src/main/java/com/thelongtravail/mixin/BabelVillagerMixin.java) 在原特价更新前移除增量、之后刷新；原重置后忘记增量。保存前移除，finally 在仍交易时重新应用，避免临时折扣直接写入保存。村民 AI 和 [菜单点击](../../../../src/main/java/com/thelongtravail/mixin/BabelMerchantMenuMixin.java) 都复核；sync 更新交易结果槽、容器和报价消息。

补货资格检查同世界范围内任意符合恶意资格的玩家。restock 尾部记录实际世界日、次数与 gameTime，普通补货也计数。shouldRestock 使用原次数与实际次数的较大值、原时间与实际时间的较大值，检查次数、间隔和存在缺货报价。当天曾启用增强后，即使携带者离开，仍走记录分支但回到普通上限 2 和间隔 2400 刻；这避免简单移除物品后重置次数。它只改变 shouldRestock 判定，没有直接调度 restock 或替代完整工作行为。

BabelTrades 还注册大师皮匠交易：鞍 + 山羊角换巴别塔。ensure 对大师皮匠保留首个产出巴别塔的报价、移除后续重复项，没有时补加；不是只删除价格完全相同的报价。[BabelOfferMixin](../../../../src/main/java/com/thelongtravail/mixin/BabelOfferMixin.java) 对符合固定配方的报价直接返回第一项基础成本。
