# 星之声触发与状态

覆盖玩家星之声的触发、间隔、组冷却、克隆和登录衔接。时停执行器复用既有专项，女仆生命周期见 [兼容边界](../维护/兼容边界与A07收尾.md)。

## 基础与扩展分工

| 层次 | 源码 | 职责 |
|---|---|---|
| 装备与阶段 | [BoundlessAccessoryItem](../../../../src/main/java/com/thelongtravail/item/BoundlessAccessoryItem.java)、[BoundlessEquipment](../../../../src/main/java/com/thelongtravail/boundless/BoundlessEquipment.java)、[TravailStateApi](../../../../src/main/java/com/thelongtravail/api/TravailStateApi.java) | 星之声使用 dream=false；准入要求玩家、功能 necklace 槽、日记和同物品唯一；运行查询要求日记非空及精确物品的非装饰 necklace 槽 |
| 战斗协调 | [CombatContext](../../../../src/main/java/com/thelongtravail/helper/CombatContext.java)、[CombatConsequences](../../../../src/main/java/com/thelongtravail/helper/CombatConsequences.java) | 区分受击尝试和确认伤害，避免单次上下文重复分发 |
| 玩法扩展 | [StarVoiceState](../../../../src/main/java/com/thelongtravail/boundless/StarVoiceState.java) | 来源过滤、阶段选择、间隔检查、随机抽取、请求建立时停 |
| 时停公共执行 | [TimeStopManager](../../../../src/main/java/com/thelongtravail/boundless/TimeStopManager.java) | 验证区域参数、容量、组锁，建立场与合并组，结束后交付冷却 |
| 生命周期协调 | [BoundlessEvents](../../../../src/main/java/com/thelongtravail/boundless/BoundlessEvents.java) | 服务端 tick、克隆复制、登录冷却接收、停服清理 |

星之声没有命中次数或保底累积；名称中的 State 在这里主要对应三个玩家 persistentData 倒计时。右键入口允许装备，没有专属主动施放方法。日记准入与运行查询细节沿用 [装备与携带](../模块/装备与携带.md)。

## 两条触发入口

未见证路径：CombatContext.prepareAttack 在正数且有限的受击输入、目标存活且非旁观者时，每个上下文最多调用一次 received；排除重放、处决、玫瑰伤害、见切反伤、洛伦兹次生伤害及正在执行的终结。分发发生在后续内部免疫判断之前，因此它不是“确认损失生命后”触发。最终被免疫或取消的攻击是否到达此入口，应沿实际伤害管线判断。

StarVoiceState.received 只处理 ServerPlayer 受害者。优先取 source.getEntity，否则取 directEntity；来源为空不抽取，来源是本人不抽取。在 getEntity 为空时，还用 TimeStopExemptions.owner 检查直接实体是否归本人。不要把这里概括为枚举所有来源的完整所有权过滤。

见证路径：CombatContext 对有限的生命或吸收值下降确认伤害，兼容的 recordDummyDamage 也可提供正数确认。damageConfirmed 保证同一上下文的生命与吸收变化只分发一次；处决、重放、堂吉诃德次生伤害、见切反伤及洛伦兹虚空分支不会进入这次 confirmed 分发。StarVoiceState.confirmed 进一步要求伤害归属是 ServerPlayer、攻击者不是目标、目标非旁观者；不要求目标在此刻仍存活，所以致死伤害可以进入抽取。

详细确认时序见 [伤害确认与重放](伤害确认与重放.md)。新增攻击路径若绕过公共确认，不能仅凭调用 hurt 或播放命中动画就宣称星之声已覆盖。

## 抽取顺序与失败代价

roll 按顺序执行：

1. 拒绝死亡、旁观者、被冻结、未有效装备或 UUID 已被任意时停组锁定的玩家。
2. 读取无垠见证。attacking 必须与 witness 相等：未见证仅受击，见证仅造成伤害。
3. 见证检查 COOLDOWN 与 INTERVAL；未见证只检查 RECEIVED_INTERVAL。组锁是两者共同条件。
4. 先写入对应判定间隔，再随机比较概率，命中后调用 TimeStopManager.start。

随机未命中不会退还间隔。start 返回 false 也没有间隔回滚或重试：非法参数、盟友快照不可用、组锁、区块容量等可能阻止建场。未通过前三步则不写新间隔。概率为零仍会在合格尝试时写间隔；间隔为零不绕过其他资格和组锁。

## 三个倒计时及配置

[BoundlessItemsConfig](../../../../src/main/java/com/thelongtravail/config/BoundlessItemsConfig.java) 的配置路径为 items.boundless.star.*；时间通过公共 TickDurations.ceilNonNegative 向上取整为 `ceil(seconds * 20)` 并限制至少零。

| persistentData 键 | 赋值来源 | 递减与默认值 |
|---|---|---|
| LongTravailStarReceivedInterval | 未见证的合格抽取前 | maliceInterval 默认 0.2 秒，即 4 tick |
| LongTravailStarInterval | 见证的合格抽取前 | witnessInterval 默认 1 秒，即 20 tick |
| LongTravailStarCooldown | 成功建立见证场、时停组结束、登录接收离线冷却 | witnessCooldown 默认 5 秒，即 100 tick；赋值取新旧最大值，仅未被组锁时递减 |

默认未见证概率 10%、时停 2 秒；见证概率 5%、时停 5 秒；半径 32 方块，组期限 15 秒，每区块覆盖场数量上限 2。这些是源码默认值，不代表用户当前配置文件值。

BoundlessEvents 先让各世界 manager 处理到期，再在服务端 START 阶段对未被冻结的在线玩家调用 StarVoiceState.tick。两个判定间隔每次减 1，COOLDOWN 还要求未被组锁。被冻结时三个值均不在这里递减；卸下饰品没有阻止 tick，所以在线且未冻结时仍计时。零值保留，不主动删键；这套计时不是墙上时钟，离线不补扣。

## 时停组结束与冷却交接

成功 startCaster 先验证实体所在世界、中心/半径/时长/盟友参数，处理到期，再检查跨世界 UUID 组锁及覆盖区块容量。重叠场合并为组，期限取新旧 deadline 的最小值；新场固定在触发坐标，不随玩家移动。见证施法者记入组成员及配置冷却，未见证成员冷却为零。组成员不是所有豁免盟友。

成功建场时已把见证 COOLDOWN 写入玩家，但组锁期间暂停递减。个人场先结束而组内其他场仍存在时，仍然保持锁定；整个组没有存活场后，expire 才按成员交付冷却并移除组。在线玩家写入最大值，离线玩家进入 OFFLINE_COOLDOWNS；女仆先走专用 completeCooldown 适配。

因此修改持续时间、组期限或冷却时，需要区分“个人场结束”和“组结束”。完整冻结、恢复及协议见 [时停与恢复](../模块/时停与恢复.md)、[冻结与恢复](冻结与恢复.md)、[时停逐入口边界](时停逐入口边界.md)、[网络协议与状态生命周期](网络协议与状态生命周期.md)。

## 持久化、克隆与清理

| 事件 | 当前源码行为 |
|---|---|
| 卸下星之声、卸下日记、切换阶段 | 后续 roll 重新查资格；没有清空三个键，也没有按此事件撤销已有时停场 |
| 玩家 Clone | 无论 Clone 是否由死亡产生，复制三个整数到新实体；不把死亡当作冷却重置 |
| 登录 | TimeStopManager.login 取出当前进程离线冷却，和玩家已有 COOLDOWN 取最大值；同步时停状态 |
| 登出 | BoundlessEvents 清同步缓存及梦境任务；没有删除星之声计时或主动删除施法场 |
| 换维度 | 清同步缓存、结束梦境并同步新维度时停；星之声键不在此重置，locked 会扫描所有世界组 |
| 服务器停止中 | manager 清场、处理组结束和冷却、推进冻结任务恢复 |
| 服务器已停止 | clear 清 WORLDS 与 OFFLINE_COOLDOWNS；临时场与组不是 SavedData |

三个整数存在玩家 persistentData，Clone 显式转移；正常存档/重连应按玩家数据链核验。OFFLINE_COOLDOWNS 是进程内 Map，不能把它称作跨重启持久账本；离线玩家停服时的冷却交接仍需验证。成功建场时预先写入的 COOLDOWN 与临时离线队列也不是同一种存储。

当前没有专用的“重置星之声”写入或删除入口；通用外部 NBT 编辑不在此结论范围。运行恢复不能靠假定重登、死亡或重新佩戴会清零。

## 扩展路径与待验收

新增触发类型先决定是攻击尝试还是确认伤害，再接入公共分发；修改概率/间隔应保留“先写间隔、再随机、失败不回滚”的既有契约；修改冷却必须同步检查玩家持久键、组成员冷却和离线交接。女仆由 MaidCombatFeedback 触发、MaidPeriodicEffects 逐 tick 递减、MaidRuntimeState 提供状态访问，并使用 MaidAccessoryLedger 的独立 StarCooldown/StarInterval/StarReceivedInterval，不应改为复用主人的玩家键；其完整阶段和生命周期由 A07-18 核对。

待回归用例：无装备/装饰槽、阶段切换；环境无来源和自有弹射物；受击后免疫；吸收与生命同时下降只抽一次、致死命中及假人；概率失败和建场容量失败保留间隔；个人场结束但组仍存活；冻结暂停、卸下继续计时；死亡 Clone、换维度、离线组结束、停服重启及女仆冷却独立性。
