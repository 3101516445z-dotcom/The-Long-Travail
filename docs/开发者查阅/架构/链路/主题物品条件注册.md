# 主题物品条件注册

## 启动和生命周期

[ItemRegistrationConfig](../../../../src/main/java/com/thelongtravail/config/ItemRegistrationConfig.java) 从独立的 `item-registration.toml` 读取并冻结关闭集合。GROUPS 按六主题维护 30 个 ID。Startup 延迟持有者在首次注册判定时只初始化一次，不进入 ManagedConfig 的监听和重载流程。

读取复用 ConfigFileIO 的 UTF-8 TOML 和原子写入。缺项补 true；非法配置失败停止启动，原文件保留；未知键保留并告警。这与普通玩法配置的恢复策略不同。

[ModRegistry](../../../../src/main/java/com/thelongtravail/registry/ModRegistry.java) 的 themeItem 仅为启用项调用 DeferredRegister.register；关闭项保留相同类型的未解析 RegistryObject。原字段名与 ID 不变，辅助序列化器及效果仍注册。

## 查询、获取和展示

[RegisteredItems](../../../../src/main/java/com/thelongtravail/registry/RegisteredItems.java) 在 ItemStack/Item 身份判断前检查引用是否存在。装备、携带与女仆查询新增 RegistryObject 重载，不把关闭物品替换为空气。直接构造物品、Curios 查询及交易入口另有前置检查。

DependentAccessories 在规则建立时固定 enabled 值；关闭规则保留原来的前置条件和 cleanup 时机，仅跳过缺失物品的读取；属性与待执行状态仍由既有生命周期入口清理。女仆全量 equipmentChanged 直接执行原有撤销动作，不构造用于触发撤销的虚拟物品栈。

CatalogEntries 只加入启动时启用的主题条目。拾遗使用原布局和搜索逻辑；详情直达关闭条目时回到列表。创造栏及 JEI 只登记可用物品；内置配方使用 Forge item_exists 条件，标签中的可关闭引用设为 optional。

交易同时检查成本及产物，新村民注册和旧村民 ensure 均受保护。已有 MistletoeTradeMixin 在旧交易 NBT 反序列化前过滤 buy/buyB/sell 中明确关闭的 ID，防止缺失原料变成空栈；全开时直接跳过，关闭时仅在确有受影响交易时复制并替换 Offers。UnifiedLoot 区分明确关闭的内置 ID 与错误 ID：关闭项使用显式空权重项，保留总权重；错误 ID 仍报错。MaterialLoot 在特殊单轮表重建前移除关闭项，保留其他奖励的绝对概率。

## 联机与性能边界

TravailNetwork 的协议标识为 `24-items-<关闭集合位掩码的十六进制>`，沿用现有通道双向版本匹配，不新增消息或运行期同步。GROUPS 的顺序参与位掩码编码，改变顺序必须重新考虑协议兼容。进入另一种注册配置的服务器需重启客户端。

开关不产生新线程、文件监听、逐 tick 扫描或逐玩家缓存；热路径仅增加存在性判断。注册集合不随数据重载变化。性能采样只位于测试夹具，不进入正式包。

旧存档缺失映射按平台实际行为处理；本功能不实现占位物品、恢复系统或外部数据包重写。
