# 性能改进与伤害规则说明

本轮只修改性能相关路径和配置说明。LivingAttackEvent、LivingHurtEvent、LivingDamageEvent 三个处理器与备份逐段比较一致；流体穿透 Mixin 未变更。

## 已实施

| 项目 | 修改 | 保留的行为 |
| --- | --- | --- |
| 流体侵蚀、远方见证的周期任务 | 世界时间加入玩家 UUID 与任务类型的稳定相位 | 每个完整周期执行次数、每轮动作数、概率不变；不消耗随机数生成相位 |
| 高空减速缓存 | Player Mixin 实例字段保存当前 tick、世界、配置版本与倍率 | 同 tick 复用；新 tick、换世界、配置更新、装备回调与显式重置时失效 |
| 名称文字 | 每次绘制预处理一次去标记字形，供 16 个光晕与主体复用 | 字符顺序、索引、字体样式与全部光晕参数不变 |
| 材质探测 | 已去标记文本直接跳过重复探测；名称不再扫描散文扫光宽度 | 未标记外部文本仍正常交给原字体渲染 |
| 缓冲包装 | 常见单材质路径不用映射表；出现其他材质才创建映射 | 每段文字的坐标参数独立，支持混合字体图集，不使用捕获坐标的全局缓存 |
| 日志 | 视觉剥夺逐次开始、清除改为 DEBUG | 状态、发包、判定、刷新全部保留；已有显式诊断日志保留 |
| 配置说明 | 增加高频效果、短周期、大范围实体查询、大量掉落的中英文警告 | 全部数值默认值、上下界、奖励限制与工作量规则不变 |

周期错峰改变相位，因此首次触发时间及与其他事件的相对顺序可能变化。周期为一 tick 时保持每 tick 执行，不能通过错峰减少总工作量。

高空配置读取同时明确区分逻辑端：服务端使用自己的配置，客户端使用同步的配置；不让单人进程共享的客户端展示缓存反过来支配服务端计算。

文字预处理仅在本次绘制期间保留，没有跨帧缓存可变文本。16 个矩阵仍各自独立，以免字体替换模组延迟消费矩阵时串用数据。着色器和光晕位置、透明度没有修改，也没有新增画质降档。

## 验证

- 编译、独立测试服务器回归。
- 100 玩家交错读取缓存，覆盖 64 项旧容量边界；验证下一 tick、手动失效、同 tick 配置更新、卸装备。
- 周期测试验证次数与间隔、负哈希、大时间值及每 tick 配置。固定 100 玩家、100 tick 周期模拟中峰值为 4 次，而原算法在边界 tick 为 100 次。这是操作次数模拟，不是实际 TPS/耗时测试。
- 文字回归验证 17 次重用只遍历源文本一次，保留索引、Unicode 码点、顺序、颜色、粗斜体与自定义字体，并保留 sink 提前终止语义；混合材质与不同文字坐标保持隔离。
- 原有 OpenGL 着色器测试通过，覆盖金色周期、扫光、bitmap/intensity/SDF 图集。
- 对比备份确认数值配置默认值与上下界一致、着色器文件一致、三个伤害处理器一致。

没有进行整合包完整客户端画面对比或真实多人压力测试，不将上述次数优化换算成 FPS/TPS 提升百分比。

## 第 2 项的功能分配

苦旅实际包含四类不同规则：

1. 受击诅咒：远方恶意清正面效果，幽谷恶意触发视觉剥夺，在 LivingAttackEvent 前置执行。
2. 自身免伤：归墟见证在 LivingAttackEvent 取消窒息/挤压；在 LivingHurtEvent 中，对处于流体中的玩家按概率取消伤害（排除 GENERIC_KILL）。
3. 攻击限制：无垠恶意在 LivingAttackEvent 取消飞行攻击者的攻击，不属于受害者的免伤奖励。
4. 环境侵蚀穿透：仅在来源为 fluid_erosion 时，穿透攻击事件的取消，属于侵蚀伤害本身的规则。

以下战斗说明保留当时讨论背景，已由用户后续确认的 [当前战斗实现](combat-rules.md) 替代。当前实现中，自身见证免伤成功会跳过受击反馈，外部取消则不会自动免除反馈。

当时建议的拆分只针对第 1 类的事件接收方式，不删除、移动或降低第 2 类，也不把普通攻击重新放行。

例如玩家拥有归墟见证、仍有幽谷恶意：窒息攻击可以先触发黑屏，再由归墟见证免除窒息扣血。当前代码就是这种分配。免伤保护生命，恶意影响视觉，两者并存。

receiveCanceled=true 的含义是“仍观察已经取消的攻击事件”，不是“取消免伤”，也不是 event.setCanceled(false)。它也不能保证药水移除一定成功或观察到根本未发布的事件。

## 第 4 项扩大穿透的后果

扩大到 Hurt 与 Damage 后，限定 fluid_erosion 的实现可以令这类伤害不再被上述两个阶段的取消、归零或减伤抵消；普通攻击不会因此穿透归墟见证。正常侵蚀仅在归墟恶意时生成，与归墟见证互斥；不能说扩展就会普遍废除自身见证免伤。如果外部系统直接对有见证玩家施加同一伤害类型，则必须明确谁优先。

但“强制穿透”必须规定恢复什么数值：默认侵蚀配置为 1，若繁茂恶意把它乘为 2，再把 Hurt 的返回值强制写回初始 1，就连苦旅自己的增伤也消掉了。强制固定数值与只拒绝防御性减免是不同规则。

更合适的候选是为自身侵蚀维护伤害下限，明确该下限是否包含苦旅自己的增伤，且避免在两个阶段重复乘算。仍需注意：已经取消的事件会跳过普通监听器；恢复返回结果不会补执行这些监听器，也不会撤销已消耗的饰品充能、耐久或反击副作用。

即使两个阶段都恢复正伤害，也不等于保证死亡：更早的 hurt 注入、原版无敌、图腾、死亡事件取消、自定义生命系统与事后回填仍在其他层面。此次不修改这些机制。
