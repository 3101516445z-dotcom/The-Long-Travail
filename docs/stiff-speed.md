# 僵硬速度修正

僵硬原先通过 `MOVEMENT_SPEED` 的 `MULTIPLY_TOTAL = -1` 修饰将速度归零。现在移除该属性修饰，改为在 `Player.getSpeed` 和 `LivingEntity.getSpeed` 返回处检查僵硬效果；效果存在则返回零。玩家覆盖了父类方法，所以两处均需处理。

这与无垠恶意在速度读取结果上施加修正的方式一致。清除负面速度属性修饰、甚至清空全部速度修饰，都不会单独解除僵硬。原来的完全减速强度、持续时间、触发概率及禁跳逻辑保留；效果等级提高也仍是完全减速。

两侧均直接读取当前药水效果，不另建逐刻缓存。僵硬移除后，下一次速度读取立即恢复正常计算，包括仍然有效的无垠恶意和其他速度加成。效果本身仍可正常驱散或到期，此次没有加入药水不可移除规则。

玩家侧在既有 `AltitudeSpeedMixin` 中统一处理：先检查僵硬，存在则归零，否则应用无垠倍率。不能用两个各自可提前返回的 RETURN 注入依赖执行顺序叠加，否则无垠先返回时可能跳过僵硬。非玩家由 `StiffSpeedMixin` 处理父类速度读取。

旧存档可能保存旧版僵硬的属性修饰。移除效果时额外清理原 UUID `d2b21a50-a731-4f15-91ea-5cfcb76e818f`，避免旧修饰在效果结束后残留；不清理其他来源的速度修饰。

修改作用于正常的移动速度读取，不强行清零实体速度向量，不额外取消击退、传送或外部自定义位移。它也不保证覆盖其他模组在更后面直接重写移动速度的注入。

回归入口：`tools/smoke/AltitudeCacheSmoke.java`。覆盖清除速度修饰、无垠叠加、正面速度加成、同刻驱散恢复、旧修饰清理、非玩家及高等级僵硬。运行命令：`./gradlew.bat --offline -I tools/review.init.gradle runServer build jarJar`；检查 `TRAVAIL_STIFF_PASS`、`TRAVAIL_COMBAT_PASS` 和 `TRAVAIL_SMOKE_PASS`。
