# 第一轮代码改进

范围：落实视觉剥夺生命周期、旅程任务池校验；保留受击前置惩罚与流体伤害穿透规则。

## 视觉状态

- 旧实现把缓存释放与诅咒结束混在一起。在线重置可能只删服务端标签，客户端继续显示黑屏。
- 新实现的 `resetRuntime` 显式调用 `VisualDeprivation.clear`，同时清时间戳、尝试移除展示效果、发送结束包。
- 显式清除即使没有时间戳也发送结束包，因此重复喝奶、调试清除可修复客户端残留。
- 退出仅清运行缓存，保留时间戳；重登继续使用 `resend`。服务器运行时离线期间继续计时，服务器停止时游戏时间不前进。
- 自然到期也同步结束，并尝试清理展示图标。
- 客户端时间线在收包时绑定玩家对象，避免“恢复包先到、下一 tick 才发现换人”而丢弃新状态。刷新不重播渐入。
- 死亡、重生、换维度与日记重置继续沿用原先结束状态的规则，改为明确同步结束。

独立时间线只管客户端表现，不将药水效果重新当成诅咒真值。

## 任务池与存档

- 新的 `RequirementPools` 在服务端按注册表与配置生命周期缓存校验结果；配置重载、服务器停止会失效缓存。无效池不会每 tick 重新解析、刷日志。
- 数量为零或显式空列表视为 `DISABLED`；非空池全部目标无效视为 `INVALID`；其余为 `READY`。
- 相同资源 ID 只保留第一条的显示名称与权重，输出重复诊断；有效目标不足时抽取全部有效目标并诊断。
- 任意必需类别无效时阻止本次新旅程生成。先在独立 NBT 副本中完整生成，再设置 `Initialized` 并提交。
- `tryInitialize` 返回成功与否；原有 `initialize` 的 void 签名保留。`refreshedCopy` 失败返回空物品，调用者在消费道具、替换装备和添加冷却之前退出。
- 新日记使用 Version 2，每个方面保存 `BiomesStatus`、`StructuresStatus`。完成判断要求状态有效且两个任务列表存在并为空。
- Version 1 已初始化日记不重抽、不撤销见证、不改写数据；继续支持原有完成逻辑。旧格式不能可靠追溯空任务的起因，因此不做猜测式修复。
- 配置修正、热重载后，未初始化日记会在后续 tick 自动重试；旧的已初始化旅程不随配置变化被重写。

仅验证注册表存在性，不声称目标一定会在自定义世界生成，也不通过大范围世界搜索校验配置。

## 保留的玩法与讨论结论

受击惩罚旨在作用于攻击尝试，即使其他模组免伤或取消伤害也应压制。此次没有后移事件、增加冷却、过滤零伤害或改变触发概率。

检查当前安装的 `dream_relics-1.0.3-forge+mc1.20.1.jar` 字节码可见，虚空项链在 `LivingAttackEvent` 处理器中检查装备与伤害来源实体为空，然后取消事件。现有 `ForgeHooks.onPlayerAttack` 返回钩子能对自己的流体伤害恢复该阶段结果，针对这种取消方式有明确依据。它不等于绕过后续每一种免伤/死亡取消；此次没有修改它，也没有伪造攻击实体或改成直接扣生命。

## 验证

独立测试服务器位于 `build/review-server`，生产模组与玩家世界没有被替换。

```powershell
./gradlew.bat --offline -I tools/review.init.gradle reviewTimeline runServer
./gradlew.bat --offline build
```

`review-server` 首次使用需要准备该测试实例的 EULA 与本地服务器配置。本次沿用已有测试实例的 EULA 接受记录，绑定 127.0.0.1，随机端口，使用独立超平坦世界。

检查输出必须包含 `TRAVAIL_REVIEW_PASS` 与 `TRAVAIL_SMOKE_PASS`，且不含 `TRAVAIL_SMOKE_FAIL`；仅看 Gradle 的退出状态不足以判断旧 smoke 入口中的断言。

新增验证包括客户端收包/首次 tick 顺序、玩家替换、刷新渐入、重复清除、自然到期、服务端清除包、退出/重登、错误池缓存、生成失败 NBT 与道具保护、旧格式保留、恢复生成、Version 2 完成与无效状态拒绝、主动零任务完成。原有 smoke 覆盖效果合并、权重抽取、净化预算、查询缓存、饰品返还、吸收生命、图腾与幻翼范围。

没有进行客户端实际画面验收或整个整合包联机压力测试。
