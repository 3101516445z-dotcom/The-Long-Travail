# 战斗规则拆分与真伤穿透

本文件对应 2026-09-27 用户确认后的实现，替代早期设计文档中的候选方案。

## 规则与旧方案对比

| 情况 | 旧方案 | 当前实现 |
|---|---|---|
| 归墟见证免除窒息／挤压／溺水／冻结 | 先触发受害者反馈，再取消 | 先确认自身免伤，跳过受害者反馈 |
| 恶意倍率与见证免疫的伤害集合 | 各自硬编码，容易走偏 | 共用 `abyssEnvironmentDamage` 判定，两侧恒等 |
| 归墟见证流体概率免伤 | Hurt 阶段抽签，反馈已经触发 | Attack 事件派发前抽签一次，成功则跳过反馈 |
| 无垠恶意禁止攻击者飞行输出 | 与受害者处理写在同一个监听器 | 独立输出限制；仍执行受害者反馈，但不扣血 |
| 外部模组取消普通伤害 | 受击反馈可能受监听器顺序影响 | 在事件派发前执行反馈；外部取消仍然有效 |
| 外部取消流体真伤 | 只恢复玩家 Attack 返回值 | 在 Attack、Hurt、Damage 的返回边界保护 |
| 苦旅自身倍率 | Hurt 的 LOWEST 监听器 | 普通伤害在 Hurt 返回后计算；受保护真伤在 Hurt 派发前计算一次 |
| 成功攻击反馈 | 在 Damage 事件中执行，仍可能被其他监听器取消 | 观察 actuallyHurt 的实际扣血，hurt 正常返回后执行一次 |

免伤概率前移意味着：外部已经打算取消的攻击，现在也可能先抽中苦旅免伤，因而没有受击反馈。这是“自身免伤优先”的明确规则变化。已经被更早的实体检查拦住、根本没有进入攻击钩子的伤害不额外制造反馈。

## 一次伤害的处理

1. `Player.hurt` 或非玩家的 `LivingEntity.hurt` 建立 `CombatContext`。玩家进入父类 `hurt` 时复用该上下文；递归调用玩家 `hurt` 则建立独立上下文。
2. 进入 Forge 的攻击钩子后，分别判断受害者自身免伤、攻击者输出限制。自身免伤成功则跳过反馈；否则执行远方／幽谷受击反馈，包括攻击者被禁攻的情况。
3. 任一内部阻断成立，返回拒绝伤害；不再派发这一攻击的外部事件。内部结果不由真伤穿透恢复。
4. 放行后派发原本的 Forge 事件。普通伤害尊重取消，指定真伤可恢复攻击钩子的许可返回值。
5. 进入 Hurt：普通伤害在外部事件返回后应用自身倍率，取消得到的零不会被放大成正数。受保护真伤先应用自身倍率，再让外部处理这个数值，并保护它作为后续下限。
6. 进入 Damage：受保护真伤取外部有效结果与保护下限的较大值，不再重复计算倍率。苦旅自身计算为零时保持零。
7. 仅在 `actuallyHurt` 中原本的 `setHealth` 调用确实降低生命时记录成功。退出此次 `hurt`、释放上下文后再执行成功攻击反馈；完全吸收或取消不算成功。生命下降后图腾救活仍属于成功造成伤害。

例如 Hurt 阶段输入为 2，繁茂恶意乘 2，攻击者冥府恶意削减 50%，则保护值为 `2 × 2 × 0.5 = 2`。外部返回 0，最终恢复到 2；外部返回 5，保留 5，不再乘一次苦旅倍率。保护值取 Hurt 入口输入，而非强行恢复到调用 `hurt` 前的原始数值，保留到达此阶段前的正常处理。

## 生命周期与边界

`CombatContext` 使用 ThreadLocal 链式栈与 try-with-resources。每次调用有自己的内部裁定、保护值和扣血标记，嵌套同一目标、同一 DamageSource 也不会共用标记；异常时仍恢复父上下文，最外层退出移除 ThreadLocal。没有向实体 NBT 写入临时状态。

方法包装使用 [MixinExtras WrapMethod](https://github.com/LlamaLad7/MixinExtras/wiki/WrapMethod)，以保证方法提前返回或抛异常时都清理上下文。MixinExtras 0.4.1 通过 Forge Jar-in-Jar 内嵌；普通使用者无需单独安装。实际扣血观察使用 WrapOperation，调用原方法，不代替原版扣血。

当前强穿透仅针对 `the_long_travail:fluid_erosion`，受 `fluidErosionUnavoidable` 控制。关闭时三个事件阶段都尊重外部取消，原有伤害类型标签和玩家吸收绕过机制仍保留。

穿透边界是 Forge 事件派发方法的返回处，不是任意模组代码之上的绝对优先级。更早返回的 hurt 注入、实体无敌、PVP 限制、后置自定义锁血／回血、图腾和死亡事件不在此次扩大范围内。绕开标准 hurt 链、直接调用 ForgeHooks 的第三方代码没有完整上下文，沿用其原始事件返回值。现有吸收绕过针对玩家，未把它扩展为全部生物的吸收穿透。

恢复返回值不会撤销外部事件已消耗的充能、耐久或已经执行的反击，也不会补执行因取消而跳过的监听器。不二次调用 hurt，不重发事件，不用额外 setHealth 强行补扣。

## 验证与交付

独立测试服使用 `tools/smoke/CombatRulesSmoke.java`，通过真实 Forge 事件和实际应用的 Mixin 验证：自身窒息／流体免伤、免伤只抽一次、五种外部取消／归零、普通伤害与真伤区别、繁茂和冥府倍率、外部增伤、配置关闭、双玩家飞行禁攻、实际扣血才有成功反馈、吸收、同目标同来源的嵌套伤害、异常清理、对非玩家造成伤害。原有套件另覆盖图腾、流体吸收、生命周期及性能回归。

命令：`./gradlew.bat --offline -I tools/review.init.gradle reviewTimeline reviewPerformance runServer build jarJar`。日志中的 `TRAVAIL_COMBAT_PASS` 和 `TRAVAIL_SMOKE_PASS` 均需出现；不能仅凭 Gradle 成功判断游戏内断言通过。异常清理测试会故意让一个事件监听器抛异常，Forge 的对应异常日志是预期测试输出。

可安装成品：`build/libs/the_long_travail-0.1.0.jar`，包含内嵌依赖。`-slim.jar` 是不含依赖的构建中间产物。测试源码不打入正式成品。测试运行于 `build/review-server`，不替换整合包 mods 目录，不修改用户存档。

这些验证不等于完成整个整合包的联合兼容测试，尤其不对直接注入生命处理的外部模组作无限穿透保证。
