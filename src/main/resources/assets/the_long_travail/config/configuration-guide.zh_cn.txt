[C01] 文件分组
------------------------------------------------
general.toml：跨主题公共规则、探索抽取数量、统一战利品及 carrying 携带位置开关。
全局与物品独立携带开关的关系见 [C03]。
utility_items.toml：路引等通用功能物品。
client.toml：仅影响本客户端的显示偏好。
aspects/：六个主题及其关联物品。各主题保留独立的探索条件池。
修改一般配置后会自动重新加载；统一战利品还需执行 /reload 或重启。
探索池和抽取数量的修改只影响新生成的旅程，不改写已有苦旅。

阅读顺序
general.toml：初始物品、探索规则、恶意、携带检测与限制、兼容、战利品、内部升级记录。
主题文件：群系池、结构池、恶意、见证、其他主题规则、关联物品，最后为按类型分组的联动预设处理记录。
upgrades 由模组维护，请勿手动修改；联动预设的初始化标记可按下文说明重置。

[C04] 基础写法与单位
------------------------------------------------
修改等号右侧的值，保留配置键。使用 UTF-8、英文双引号和英文逗号；# 开头的文字是注释。

开关、数字和文字
- 开关：enabled = true 或 enabled = false，不加引号；true/false 的具体效果看该项说明，不能一概理解成启用/禁用。
- 数字：chance = 0.07，表示 7% 的前提是该项定义为概率。直接填写数字，不把数字放入引号。
- 属性加值和倍率不同：加值 0.1 表示加 0.1；倍率或比例按该项说明换算。
- 科学计数法：2.0E-5 等于 0.00002；若用于概率，相当于 0.002%。
- 文字与枚举：rewardOverflowPolicy = "DEFER"。枚举只填写 Allowed Values 列出的选项，保持大小写。
- Range 是允许范围；不要据此猜测单位。游戏刻按每秒 20 刻换算；现实时间与游戏时间须按字段说明区分。

列表
items = [
    "minecraft:apple|6|1|5",
    "minecraft:emerald|6|1|5"
]
每个字符串用英文双引号包围，条目之间加英文逗号；不能缺少末尾的 ]。保留字段原有类型，不把所有列表都写成这种物品格式。
[] 表示空列表；0 和空列表的效果依字段而定，不一定禁用功能。联动记录仍为 false 时，空池也可能在满足条件后补入预设，见 [P01]。
同一表内不要重复定义同名键。表名中的完整资源 ID 含冒号，应按 [C06] 的示例用引号包围。

[C02] 配置键的读法
------------------------------------------------
例如在 [travail.witness.compatInitialization] 下，goety.positiveEffectsAdded = false 的完整路径为 travail.witness.compatInitialization.goety.positiveEffectsAdded。
点号只是把原来的嵌套表写成一行，配置含义不变；按类型集中排版不会合并各模组或各池的记录。

[C05] 列表格式速查
------------------------------------------------
按配置池选择格式；竖线 | 分隔字段，不填写尖括号占位符。

群系／结构：ID|显示名称|正整数权重；例 minecraft:plains|@biome.minecraft.plains|3。见 [E01]、[E02]。
物品奖励／共享战利品：物品ID|权重|最小数量|最大数量；例 minecraft:apple|6|1|5。见 [C06]、[P04]。
钓出生物：实体ID|权重；例 minecraft:pig|100。见 [P05]。
增益效果：效果ID|最高等级|权重；例 minecraft:jump_boost|5|5。见 [P06]。
物品／附魔黑名单：每项只填完整 ID，例如 "enigmaticlegacy:astral_fruit"；不加权重。见 [P07]、[P08]。

各字段仍受自己的范围和合法性校验限制。以上示例是写法示意，不要求加入你的配置。
ID、翻译键与自定义名称用途不同：只有探索池的名称字段使用 @ 翻译键。其他列表不可直接照搬这个名称字段。

[E01] 探索条件池
------------------------------------------------
群系格式：群系ID|显示名称|权重
结构格式：结构ID|显示名称|权重
权重必须为正整数。权重越大，抽中概率越高。
每个条目单独占一行，放在方括号内，并用英文双引号包围。
条目之间用英文逗号分隔，例如：
biomes = [
    "minecraft:plains|高峰出云|3",
    "minecraft:forest|林间漫步|1"
]
显示名称可以填写自定义文字或谜语，不会改变实际目标。
上例中的“高峰出云”仍然要求探索平原，只改变苦旅页面上的名称。
群系和结构的 ID 必须在当前整合包中实际存在。
结构示例：example:stronghold|末路之门|3
example:stronghold 仅为格式示例，使用时须替换成实际结构 ID。

[E02] 多语言名称
------------------------------------------------
显示名称以 @ 开头时，后面填写翻译键。例如：
minecraft:plains|@biome.minecraft.plains|3
example:stronghold|@structure.example.stronghold|3
翻译键须在模组或资源包的语言文件中提供对应译文。
找不到译文时显示目标 ID。普通文字不会随游戏语言切换。

[E03] 抽取与无效条目
------------------------------------------------
抽取数量位于 general.toml 的 requirements 分组。
空列表或抽取数量为 0 时，禁用对应类别。
相同目标 ID 只保留第一个有效条目，不通过重复填写增加权重。
有效目标不足时抽取全部有效目标；无效或未注册条目会被跳过并记录日志。
非空池中没有有效目标时，会阻止新旅程生成，须先修正该池。

[C06] 共享战利品写法与概率
------------------------------------------------
位置：general.toml / loot。loot.enabled 是总开关；保存后执行 /reload 或重启。

完整示例（只演示写法，不代表默认概率）
[loot.tables."minecraft:chests/ancient_city"]
chance = 0.2
items = [
    "minecraft:apple|1|1|2",
    "minecraft:emerald|3|1|1"
]

先按 chance 判定本表是否触发，再按权重选择一个条目，最后在该条目的数量范围内取数量。
上例有 20% 概率触发；触发后苹果占 1/4，绿宝石占 3/4，因此每次执行本表时两者的最终概率分别为 5% 和 15%。
添加候选会改变相对权重，不会自动增大 chance。chance = 0 或 items = [] 停止本表的苦旅奖励；chance = 1 表示必定触发。
物品 ID 必须存在，权重须为正整数，数量范围为 1～2304，最小值不能大于最大值。父表和子表独立抽取；不会额外附加抢夺、时运、精准采集或玩家击杀条件。
错误配置与保留原件的处理见 [T01]。

钓鱼宝藏单件概率（独立字段）
loot.fishing_treasure.itemChance
駅、东海道五十三次、完美流体在钓鱼宝藏子表内各自的概率，默认 0.1，即各 10%。归墟精粹保留 20%，原版物品合计占 50%。范围 0~0.2；0 禁用这三件奖励，同时受 loot.enabled 控制。保存后执行 /reload 生效。

[P00] 预设是什么
------------------------------------------------
预设是苦旅事先整理好的一组配置条目。检测到对应联动内容、且允许处理时，模组会把其中缺少的条目补进相应配置池，省去玩家逐个查找、填写 ID 的过程。

例如安装 Terralith 后，符合条件的主题会补入预先选定的群系；玩家已配置同 ID 群系时，保留玩家的名称和权重。补入后仍可以自行修改或删除。

需要区分的三个概念
- 配置池：游戏实际使用的候选列表，例如 biomes 或 positiveEffects。
- 预设：用于补充这个列表的内置条目，无需玩家另外填写一份“预设文件”。
- 处理记录：compatInitialization 下的布尔值，控制是否还等待一次自动补入，具体操作见 [P01]。

原版默认配置池另行维护：默认值用于新建或缺失的配置项；联动预设补充可选模组的内容。重置联动记录不会把已有完整配置池恢复成默认值。

预设只包含事先选定且当前可用的候选，安装模组不会把该模组的全部内容都加入。群系和结构预设使用权重 1 与 @ 名称；其他类型有各自的权重、数量或等级上限，见 [P02] 至 [P08]。
归家与飨宴使用不同命名空间，生物与效果预设按完整 ID 分别处理，初始化标记独立；不互相替换或迁移已有配置。

[P01] 联动预设记录与操作
------------------------------------------------
检测到对应来源并满足处理条件后，模组只补入缺少的预设条目，保留已有同 ID 条目的设置和顺序。

记录值
true：停止自动补入。完成一次处理后自动设为 true，即使没有新增条目；也可手动设为 true，提前跳过补入。
false：等待一次处理机会，不表示联动被禁用。来源缺席或不满足该预设的处理条件时，保留 false。
这些值不是模组安装状态，也不表示当前池中包含全部预设条目。删除条目、清空池、更换存档或更新预设均不会重置 true。
记录保存在配置文件中，使用同一份配置的存档共用；不同主题、模组和配置池分别记录。

操作步骤
重新补入：退出世界；专用服务器先停服。将对应记录设为 false 或删除该键，保存后重新打开世界或启动服务器。
完美流体需要完整重启游戏或服务器，仅重新打开世界不足以触发。重新处理仍然只补缺少的条目，不恢复整池默认值。
阻止首次补入：在加载世界前将对应记录设为 true 并保存；完美流体须在启动游戏或服务器前设置。
停止某个池的实际效果需要修改对应功能或池设置；只改变预设记录不会移除已经加入的条目。

[P02] 联动群系预设
------------------------------------------------
通用记录规则与重试步骤见 [P01]。

检测与条目格式
世界加载时按实际注册的群系识别联动，未检测到时不记录初始化。Terralith 与 Incendium 也支持数据包版。
仅补入预设中已注册且本池尚未配置的群系，使用 @翻译键，权重为 1；已有同 ID 条目的名称、权重和顺序保留。

来源与数量
Terralith：繁茂 16、归墟 10、穷遐 19、幽谷 9、冥府 4、无垠 7；Incendium：冥府 8；Alex 的洞穴：幽谷 2。

记录与生效范围
对应主题的 travail.requirements.compatInitialization 下，分别用 terralithBiomesAdded、incendiumBiomesAdded、alexsCavesBiomesAdded 记录处理状态。
无对应预设的主题不生成该联动标记。
译名由模组或资源包提供，见 [E02]。结构池与抽取数量不变，已有旅程不重新抽取。

[P03] 联动结构预设
------------------------------------------------
通用记录规则与重试步骤见 [P01]。

检测与条目格式
世界加载时按实际注册的结构识别来源；只补入已注册且对应池中没有的预设 ID，使用 @structure.<命名空间>.<路径>，权重为 1。

来源与数量
已接入 Terralith 18、诡厄巫法：觉醒 9、Towns and Towers 8、诡厄巫法 8、Incendium 6、Iron 的法术与魔法书 4、万法皆通 4、新生魔艺 3、海灵物语 2、Alex 的洞穴 1、Mowzie 的生物 1、T.O Magic 'n Extras 1，共 65 个结构。

记录与生效范围
各主题的 travail.requirements.compatInitialization 下以 *StructuresAdded 独立记录，不受群系的 *BiomesAdded 标记影响。无对应预设的主题不生成该标记。
已有名称、权重和顺序保留；译文由模组或资源包提供，缺译显示 ID。未接入的模组及原版结构不自动补入，已有手动条目保留。
不改变结构抽取数量和已有旅程；general.toml 的 requirements.structureDrawCount 默认仍为 0，需要结构目标时自行设置数量。

[P04] 见证奖励池与联动预设
------------------------------------------------
通用记录规则与重试步骤见 [P01]。

配置位置与格式
冥府 fishingSpecialItems 与无垠 phantomDrops 的格式为 物品ID|权重|最小数量|最大数量，没有独立名称字段。
两池的原版默认值和联动预设分别维护，目前内容相同，可分别调整物品、权重与数量。

原版默认值
当前原版默认值：苹果、绿宝石各权重 6、数量 1～5；铁锭、金锭、钻石、鹦鹉螺壳各权重 6、数量 1～3。
附魔金苹果权重 3、下界合金锭权重 2、下界之星与龙蛋各权重 1，均为 1 件；下界合金碎片与回响碎片各权重 3、数量 1～3，共 12 项。
新默认值用于新建或缺失的配置项，已有完整列表不会自动替换。

联动候选
世界启动时，按物品注册表补入 8 个模组的 49 项候选：l2complements 17、curseofpandora 16、celestial_core 8、irons_spellbooks 3、apprenticecodex 2、enigmaticlegacy 1、enigmaticaddons 1、enigmaticdelicacy 1。
莱特兰、潘多拉与学徒法典奖励权重为 2，其他为 3，Iron 的传说墨水为 2；数量均为 1～3。全部存在时，新配置每池共 61 项。
仅补入已注册且本池没有的 ID；已有同 ID 权重、数量和顺序优先。ROR 不加入预设，手动配置保留。

记录与生效范围
对应主题的 travail.witness.compatInitialization.<命名空间> 下，分别以 fishingItemsAdded、phantomDropsAdded 记录初始化，与群系、结构标记独立。
联动不改变钓鱼触发概率、幻翼检测与击杀规则、发奖限制和钓出生物池；新增候选只改变物品池内的占比。

[P05] 钓出生物默认配置池与联动预设

配置位置与格式

原版默认值

联动候选

共 5 个来源、15 项候选；其他来源齐全、归家与飨宴只安装其一时，新配置共 19 项，两个命名空间候选全部存在时共 24 项。仅补入实体注册表中存在且池内缺少的 ID，保留已有权重与顺序；亚小妹 starfantasy_goety:apollyon 不自动加入，已有手动条目保留。

记录与生效范围
travail.witness.compatInitialization.<命名空间>.fishingEntitiesAdded 独立记录处理状态，与物品奖励及探索池分开。
联动不改变钓鱼触发概率、实际实体生成方式或物品奖励池。

[P06] 增益效果联动预设
------------------------------------------------
通用记录规则与重试步骤见 [P01]。

配置位置与格式
穷遐与幽谷各自的 travail.witness.positiveEffects 使用 效果ID|最高等级|权重；两池的默认值、预设与初始化记录分别维护。

原版默认值
原版默认值保留：跳跃提升 5|5、生命恢复 5|3、抗性提升 4|2、急迫 3|2、力量 3|2；后两列为最高等级和权重。已有合法配置不覆盖。

联动候选
每池提供 12 个来源的 36 项联动候选，权重均为 1，最高等级按各效果预设；其他来源齐全、归家与飨宴只安装其一时，新配置每池共 36 项，两个命名空间候选全部可用时共 41 项。
来源：goety（9）、more_potion_effects（5）、youkaisfeasts（5）、youkaishomecoming（5）、irons_spells_delight（3）、goetyawaken（2）、cataclysm（2），以及 enigmaticaddons、irons_spellbooks、alexsmobs、attributeslib、ars_nouveau 各 1 项。
AD（astral_dimension）、esoteric_spell、projectile_damage、gtbcs_geomancy_plus 不自动加入；已有手动条目保留。

检测与处理规则
加载世界时按效果注册表命名空间检测来源，只补入已注册、属于增益类型且本池缺少的 ID；已有最高等级、权重与顺序优先。
各主题文件的 travail.witness.compatInitialization.<命名空间>.positiveEffectsAdded 独立记录处理状态。
效果触发、持续时间与等级处理沿用原规则；穷遐等级加成上限仍取两池同 ID 的较高上限。

[P07] 黄金时代联动黑名单
------------------------------------------------
通用记录规则与重试步骤见 [P01]。

配置位置
aspects/far_reach.toml 的 items.golden_age.foodBlacklist 与 enchantmentBlacklist 基础默认值为空，分别排除黄金时代的食物和附魔候选。

联动候选
食物：Enigmatic Legacy 的天体果实 enigmaticlegacy:astral_fruit；Enigmatic Delicacy 的深渊乱炖 enigmaticdelicacy:abyssal_stew。
附魔：L2 Complements 的 projectile_reject、fire_reject、environment_reject、explosion_reject、magic_reject、invincible，均使用 l2complements: 前缀；Celestial Enchantments 的 celestial_enchantments:death_blade、celestial_enchantments:celestial_shelter。

检测与处理规则
加载世界时检查模组安装状态，只补入对应注册表中存在且列表内缺少的 ID，保留手动条目与顺序。
items.golden_age.compatInitialization.<模组ID> 下的 foodBlacklistAdded、enchantmentBlacklistAdded 分别记录处理，与见证奖励和效果池独立。
只影响黄金时代的产出候选，其他获取途径不受影响；原有食物筛选和附魔等级规则保留。

[P08] 完美流体联动黑名单
------------------------------------------------
通用记录规则与重试步骤见 [P01]。

配置位置
aspects/abyss.toml 的 items.perfect_fluid.itemBlacklist 保存禁止复制的物品 ID，处理记录位于 items.perfect_fluid.compatInitialization。

模组与对应物品
车万女仆（Touhou Little Maid，touhou_little_maid）：maidSoulAdded 对应初始魂符和已收纳女仆的魂符，不包含空魂符。
车万女仆性格模组（Touhou Little Maid Personality，touhou_little_maid_personality）：monsterBattleDeviceAdded 对应怪兽战斗仪。

启动时的特殊规则
两项记录独立。启动游戏或服务器时，只有对应模组已安装、且该组所有预设物品均已注册，才补入列表中缺少的 ID 并设为 true。
该组物品已全部在黑名单中时仍设为 true；模组缺席或该组任一物品未注册时保持待处理，不部分填入该组。
之后可自行增删黑名单。要重新补入，关闭游戏或服务器后将对应标记设为 false，保存并重新启动。
实际复制限制始终以黑名单内容为准，标记仅控制是否自动补入。

[C03] 携带位置开关
------------------------------------------------
配置位置与作用范围
- general.toml / carrying：駅、巴别塔与小王子共用的位置开关。
- aspects/abyss.toml / items.eki.carrying：駅的独立位置开关。
- aspects/far_reach.toml / items.babel.carrying：巴别塔的独立位置开关。

駅与巴别塔在某个位置生效，需要全局开关和该物品的独立开关同时为 true。这些是当前有效的物品独立设置，新建配置也会生成。
例如 carrying.inventory = true 允许全局检查背包，但 items.babel.carrying.inventory = false 仍会排除背包中的巴别塔，不会因此关闭其他物品的背包检测。

各位置的特殊规则
- inventory：主背包与快捷栏；offhand：副手；armor：四个原版盔甲槽；enderChest：末影箱。
- curios：已装备的 Curios 槽位，不含外观槽。启用检测不会赋予物品装备到某个槽位的能力。
- externalInventoryTick：外部容器须支持并启用模拟物品栏更新；普通嵌套容器不会被递归搜索。
- 駅的位置开关只适用于玩家。女仆使用原生饰品栏，见 [M01]；玩家在多个位置携带駅也不叠加效果。

[M02] 自动效果与奖励发放限制
------------------------------------------------
配置文件：general.toml

自动效果次数限制
~~~~~~~~~~~~~~~~~~~~~~~~
effectLimits.maxAutomaticEffectActionsPerPlayerPerSecond
每名玩家任意连续20游戏刻内，穷遐之见证与幽谷之见证共用的自动效果尝试次数上限。
包括穷遐的净化和增益，以及幽谷攻击触发的增益；失败或被取消的尝试也计数。
超出上限的尝试直接跳过，不补发。0表示不限次数。
不影响受击恶意、视觉剥夺，以及幽谷的黑暗和失明免疫。

奖励队列与发放策略
~~~~~~~~~~~~~~~~~~~~~~~~
rewardDelivery.rewardMaxItemEntitiesPerTick
全服每游戏刻最多生成的额外奖励物品实体数；不限制原版掉落。

rewardDelivery.rewardQueueCapacity
待发奖励的记录数量上限。达到上限时，暂停自动击杀幻翼，并跳过钓鱼的额外物品奖励。调低上限不会删除已有记录。

rewardDelivery.rewardOverflowPolicy
DEFER：分批发放全部奖励。
LIMIT：每次最多发放 rewardMaxEntitiesPerReward 堆物品，超出部分不发放。
两种方式均受全服每游戏刻发放上限限制。

rewardDelivery.rewardMaxEntitiesPerReward
LIMIT模式下，每次奖励最多发放的物品堆数。

[M03] 死告天使的处决与防护
------------------------------------------------
配置文件：aspects/deep_valley.toml

时限与处决概率
~~~~~~~~~~~~~~~~~~~~~~~~
items.azrael.executionWatchSeconds
强制处决后主动防护的最长持续时间，单位：秒，每秒按 20 游戏刻计算。默认 300 秒；未被重新插入世界的目标只观察 10 秒。目标被重新插入或清理失败均不会重置此时限。到期后停止主动清理，但仍保留对旧实体实例的被动拦截。修改仅影响之后发生的处决。

items.azrael.maliceChance
幽谷之恶意生效时，受击可获得一次处决判定机会，自身造成的攻击除外。
此值为接下来首次实际造成伤害时，处决目标的概率。
处决判定次数和处决概率均不可累计；
0.025表示2.5%。

items.azrael.targetChance
幽谷之见证生效时，每次判定中处决目标的概率。
处决目标与处决佩戴者不会在同一次判定中同时发生；
两项概率之和超过1时，按原比例缩放至合计1。

items.azrael.selfChance
幽谷之见证生效时，每次判定中处决佩戴者的概率；默认值0.005表示0.5%。

处决步骤与后备处理
~~~~~~~~~~~~~~~~~~~~~~~~
items.azrael.damageAttempts
处决第一阶段使用无限大真实伤害的最大尝试次数。每次尝试前重置原版无敌帧，处决成功后停止尝试。

items.azrael.genericKillFallback
第一阶段失败后，尝试一次保留玩家来源的generic_kill伤害。

items.azrael.directDeathFallback
前两个阶段均失败后，跳过可取消死亡检查并锁定旧实体生命值；玩家保留重生流程，非玩家调用原版死亡方法后强制终结，可能绕过自定义掉落或Boss清理。

创造与旁观者模式
~~~~~~~~~~~~~~~~~~~~~~~~
items.azrael.selfExecutionAffectsCreativeAndSpectator
死告天使对佩戴者自身的处决是否对创造模式或旁观者模式的玩家生效。

items.azrael.targetExecutionAffectsCreativeAndSpectator
死告天使对其他玩家的处决是否对创造模式或旁观者模式的玩家生效。

[M04] 路引搜索与缓存
------------------------------------------------
配置文件：utility_items.toml

引导时间与搜索范围
~~~~~~~~~~~~~~~~~~~~~~~~
items.wayguide.guideDurationSeconds
路引找到目标后的引导时长，单位：秒。
从开始飞出到变成掉落物为止，包含飞行和悬停，不包含搜索等待。
修改后也会影响正在指路的路引。

items.wayguide.search.searchRadius
路引的最大水平搜索半径，单位：方块，可配置范围16至30000000。未找到目标不代表整个维度都没有目标。

items.wayguide.search.searchTimeoutSeconds
单次搜索的最长等待时间，按现实时间计秒。
从请求被接受时开始计时，包含准备和排队。检测到超时后停止搜索并返还路引。

采样精度
~~~~~~~~~~~~~~~~~~~~~~~~
items.wayguide.sampling.biomeSampleSpacing
群系的水平采样间距，单位：方块；数值越小，搜索越精细，但耗时也越长。

items.wayguide.sampling.heightSampleSpacing
群系采样的垂直间距，单位：方块；无论间距如何，都会额外检查玩家所在高度。

搜索预算
~~~~~~~~~~~~~~~~~~~~~~~~
items.wayguide.budget.samplesPerTick
全服每游戏刻最多进行的路引搜索采样次数，由所有玩家共用。

items.wayguide.budget.searchMillisPerTick
每游戏刻的搜索时间预算，单位：毫秒。
包含准备、检查、采样和收尾。单次操作及必要清理可能使实际耗时超过预算。

items.wayguide.budget.maxSamplesPerSearch
单次路引搜索的采样次数上限；达到上限后停止搜索并返还路引。

缓存与失效条件
~~~~~~~~~~~~~~~~~~~~~~~~
items.wayguide.cache.cacheTicks
搜索结果的缓存时间，单位：游戏刻；0表示不缓存。移动超过128格、切换维度或苦旅进度变化后，缓存失效。

[M05] 客户端显示偏好
------------------------------------------------
client.toml 仅影响当前客户端。名称光晕、视觉剥夺动态变化、技能台词和时停边界显示均不改变服务端规则。两个名称光晕设置独立；保存后自动重新加载，重启客户端可确保生效。

光晕档位：HIGH 高、MEDIUM 中、LOW 低、OFF 关闭。降低档位可减少绘制开销；OFF 仍保留名称内部动态效果。

nameEffects.nameHaloQuality
苦旅名称的光晕质量。

nameEffects.aspectNameHaloQuality
六类主题名称的光晕质量。

visualDeprivation.reduceVisualMotion
是否在本客户端关闭视觉剥夺的周期性强弱变化。

messages.rainSkillMessages
显示东海道技能台词。

messages.dreamSkillMessages
显示入梦技能台词。

timeStop.boundaryLevel
时停边界显示档位，仅影响本客户端：1=完整半透明玻璃球面，2=线状球面。
默认1；改用2可减少绘制开销。两种显示方式均使用亮青绿色表示豁免边界，橙红色表示危险边界。

[T01] 配置写错时如何处理
------------------------------------------------
使用 UTF-8 编码，可保留文件开头的 UTF-8 BOM。数值推荐直接填写，如 chance = 0.07；合法的数字字符串也会自动转换。

启动时：缺值、括号或引号未闭合、重复键、编码损坏等导致文件无法解析时，先保存原件，再恢复该文件的默认设置，其他配置文件不变。
普通配置项类型错误或超出范围时，只将该项改回默认值；正常补充缺失项不产生错误备份。

运行时：无法解析的文件保留原处，继续使用已加载的配置，等待修正后保存。
普通配置项的非法值沿用本次运行的有效值，其他合法修改继续生效。

战利品：按整张表校验。某表的概率、物品 ID、权重或数量有误时，沿用该表本次运行的有效规则；没有旧规则则暂停该表的苦旅奖励。
其他有效表和钓鱼宝藏单件概率独立处理。合法删除、概率为 0 或物品列表为空会停止对应奖励。

原件与修复：恢复损坏文件或自动纠正已有值前，原始内容会保存到 invalid/<时间与唯一编号>/，保留主题子目录，并附 errors.txt 说明原因。
原件保存失败时不覆盖配置。备份不自动删除，也不会在重启后自动恢复；需要旧设置时，从原件中取回并修正后填入当前 TOML 文件。

日志与提醒：单人玩家或服务器管理员会收到一次汇总提醒。重复警告会被抑制，每 60 秒最多输出 20 条详细警告，其余约每分钟汇总数量和涉及文件，停服时补齐剩余汇总。
按日志或 errors.txt 定位问题，修正当前配置并保存；共享战利品还需执行 /reload 或重启。

[M01] 女仆兼容
------------------------------------------------
仅已接入的饰品支持女仆，且只能放入女仆原生饰品栏。
女仆普通背包、主副手和 Curios 槽位均不作为生效位置。
需要苦旅状态的效果读取在线主人所佩戴的苦旅，不消耗见证成果。
主人未在线或未佩戴苦旅时，需要苦旅状态的效果不生效。
一位主人的苦旅可以支持多名女仆；每名女仆仍须装备对应饰品。
駅的 carrying 开关与饰品的 Curios 槽位设置仅适用于玩家。

[M06] 主题物品的适用范围与判定条件

永生芽：aspects/flourishing.toml → items.immortal_bud
- 赋予标记时固定修满目标耐久；不再提供修复开关。
- itemBlacklist 默认为 []，按完整物品 ID 排除新的赋予；已有标记及其保护不受影响。

剑与灯：aspects/deep_valley.toml → items.swordAndLantern
- detectionRadius 默认 64 格，可设为 8～64 格；玩家与女仆的敌人、亡灵和独行判定共用此半径。
- crowdMinimumEnemies 默认 11，可设为 2～64；敌人数达到此值时应用 crowdBonus。

液化丰饶：aspects/abyss.toml → items.liquefied_abundance
- 注意：effectWhitelist 只要不是空列表，就只会生成名单内的药水效果，所有名单外的效果都不会再出现。此列表用于限制效果，不是追加效果。
- 例如，只填写 ["minecraft:speed"] 时，只会生成速度效果的药水。默认 [] 表示不启用白名单限制；清空列表可恢复，但仍受 effectBlacklist 限制。
- effectBlacklist 始终优先。例如白名单为 ["minecraft:speed", "minecraft:poison"]、黑名单为 ["minecraft:poison"] 时，只能抽到速度。
- 使用完整状态效果 ID。白名单中的未知或格式错误 ID 会被忽略并记录警告；重复项不增加权重。非空白名单全部无效时不会退回全部效果。
- 两张名单只筛选效果种类；保留效果仍按“效果 → 等级 → 时长”逐层等概率抽取。缩小效果池会提高剩余效果各自的抽取概率，不会改变它们已有的等级、时长及回退规则。
- 筛选后没有可用效果时，取消转换并提示，不消耗液化丰饶；已有药水不变。配置重载会取消正在进行的转换，之后使用新的效果池。

高频战栗：aspects/deep_valley.toml → items.high_frequency_tremor
- witnessBreakBlacklist 默认 ["minecraft:barrier"]，按完整方块 ID 限制见证状态的潜行右键破坏；同样作用于 FTB 连锁。
- 清空名单允许破坏基岩，但按正常战利品规则不会生成基岩物品；领地保护与取消破坏事件仍然有效。

伊卡洛斯与午夜拉菲：aspects/far_reach.toml、aspects/abyss.toml
- 伊卡洛斯 sunnyExtraPeak 与午夜拉菲 shelteredNonClearExtraPeak 为普通 malicePeak 之上的额外增量，默认0.25。malicePeak 默认0.5，witnessBonus 默认0.2；三项下限均为0.01。旧环境总峰值迁移为 max(0.01, 旧峰值 - 普通峰值)，迁移前配置按现有恢复流程归档。
